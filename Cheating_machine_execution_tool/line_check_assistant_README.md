# openWRT老化测试环境搭建助手

## AI 诊断助手（源码版新增，待现场复验）

### 对话排障（2026-11-11）

重启源码程序后打开常用工具“AI诊断”，默认进入“对话排障”。先在“模型接入”保存厂商、地址、模型与密钥，再选择目标、新建会话，描述故障。支持连续追问、纠正判断及补充现场现象，Ctrl+Enter发送；不会每轮强制生成六段报告。“诊断与监控”、原报告和“已确认案例”入口保留。

- 会话固定关联批次、通道、目标及模型配置。切换目标或模型配置后发送会新建会话；历史记录保留。新批次后旧会话只能分析留存材料，需要查询新现场时请新建会话。
- “授权本次会话”会列明目标、接收方及范围，一次允许连续登录查询、限定出口Ping、抓包、日志跟踪及受控临时Debug。模型必须先通过“测试连接与工具能力”。授权仅限当前进程和批次，不随程序重启恢复；“结束授权”取消新增采集并等待清理，后续可继续分析材料。“停止本轮排查”只停止当前轮次，不结束本次授权，也不停止原挂测。
- AI需要你核对指示灯、接线或实际业务时，会说明原因和具体检查方法，显示“等待你回复”。输入答案后沿用当前对话和证据继续；未回复不视为同意，不推测结果。仅问答模型仍可用文字追问，但结构化等待及自动工具依赖已验证的工具能力。
- 本次程序从挂测开始旁路缓存每通道最多2MiB/2000条事件，AI窗口晚打开仍能读取缓存和已登记的准确结果/WiFi日志；不扫描旧文件冒充当前记录。文件最多自动读取64KiB尾部，较早未载入部分可由你导入相关片段；无法还原此前未采集的串口输出或数据包。证据标明来源、批次、时间，日志读取时间与行内故障时间分别说明，当前查询正常不能反推故障时正常。
- “导入文本日志”支持txt/log/csv/json/md，单文件最多2MiB，也可直接粘贴材料（每条消息最多32768字符）。“查看证据”查看留存原文；导入内容作为不可信证据，其中的指令不会直接执行。材料沿用下方真实信息发送规则。
- 新工具可检索会话证据和历史消息，读取路由/地址/ARP/无线状态，按本次出口发送固定4包、每包2秒的Ping。有线限定通道源IP及接口到DUT管理地址；无线只使用本次测试明确指定的网卡及无线Ping目标，身份不明或没有有效IPv4则跳过，不选其它网卡。全局网络快照需按目标接口核对，不能直接当作DUT可达证据。
- 设备或共享无线网卡被挂测占用时跳过冲突采集，保留已获得的证据并说明原因；不抢占连接、不重连WiFi、不修改网络。每条用户消息最多5轮模型交互、10次工具调用；上限后可继续发送消息。AI不会重启、上下电、升级、恢复出厂、执行任意Shell或自动修复配置。
- 对话与证据保存在本机AI数据库，关闭窗口后可重新打开查看；关闭AI窗口仅隐藏，当前排查可继续。程序退出会停止新增任务并等待必要清理。每次请求最多续接最近8轮、合计48000字符的完整协议组，较早原文保留并可按关键词检索；界面提示裁剪，不把缺失上下文当作已知。
- 原挂测、失败判据、重试及续跑规则保持，由操作员决定何时停测。自动监控仍默认关闭，继续使用原有触发阈值；其成功/恢复事件不取消手动对话。真实厂商API、完整Windows操作及真实DUT仍待负责人复验，本次仅源码功能与离线验证，不属于EXE交付。

在主界面常用工具中点击“AI诊断”。AI窗口与写样机参数、串口日志、DUT配置、检查更新统一使用测试项配置的浅蓝灰背景；输入区、日志区和状态色保留原用途。正在运行的旧源码进程需重启后加载本轮修改。

AI诊断使用真实信息（2026-11-11）：手动提问、自动监控、PC快照、串口输出、工具结果、模型回复、本地报告及确认案例中的IP、子网掩码、网关、DNS、MAC、SSID、设备账号、密码及材料中的令牌均原样保留和发送，不再替换为`<IP_n>`等占位符。AI登录日志显示实际下发的设备用户名、密码。模型服务API密钥仍以DPAPI加密保存，仅用于请求认证；已登记的模型密钥会从诊断正文、报告和日志中过滤。现有监控确认框显示真实信息发送范围及接收厂商/地址，主执行日志同步记录。旧报告中的占位符无法自动还原，需要重启源码程序后重新采集。同子网、默认路由不等于DUT已可达，未做Ping或其它连通性验证时不能认定线路正常。

### 配置厂商与模型

1. 在“模型接入”页选择 DeepSeek、MiniMax、OpenAI 或自定义，分别填写API地址、协议和模型ID。DeepSeek/MiniMax默认兼容Chat Completions，OpenAI默认Responses；MiniMax不同区域的地址需按对应账号文档填写。
2. “新增配置”可为同一厂商保存多个账号或区域；“复制配置”不复制密钥。选择已保存厂商或配置时恢复其模型及设置，密钥不回显。切换对下一次诊断生效，不自动跨厂商重试。
3. 填写API密钥后“保存并选择”。密钥以Windows当前用户DPAPI加密保存，并绑定该配置和地址；换地址需重新填写密钥。数据位于`%LOCALAPPDATA%\LineCheckAssistant\ai`，不随便携包交付；跨Windows用户/电脑需重新配置密钥。
4. “刷新模型”失败时可手填模型ID。“测试连接与工具能力”使用不含项目资料的样例；只有“可自动诊断”且配置未变时允许模型请求主动采集，“可问答”仍可分析已有证据。厂商API调用按所选服务实际计费。

### 选择性触发与采集

- 自动监控每次启动默认关闭。选择目标、功能和规则后勾选“启用本次自动监控”，确认本次设备查询及真实诊断信息（含材料中的账号、密码）的发送范围；新批次需重新启用。
- 默认业务最终失败立即触发，或同一通道、同一阶段连续三次实际尝试异常触发；频段隔离，成功清零，同次尝试的重复消息不重复计数。停止、取消、正常等待和正常跳过不触发。
- 默认第三次轻量采集，第四次或最终失败允许深入采集；可关闭深入采集。连续阈值、60秒默认冷却、监控通道、功能、自定义字面关键词和错误码可在窗口调整。关键词只参与可信业务异常，不扫描凭据正文。
- 每通道保留最近120秒、最多2MiB上下文。每次诊断最多5轮模型交互、10次采集，普通查询超时20秒。资源占用时跳过主动操作，不改变原测试结果、重试或运行时序。
- “仅问答/分析已有材料”不开放DUT命令工具；“诊断并按需采集”允许受控登录查询。停止AI采集不停止原测试；程序退出会等待必要恢复和已发网络请求结束。
- AI主动命令优先使用锁源Telnet，不自动启用Telnet或修改PC网络；连接不可用时回退目标串口。只有本次通道/VLAN/COM映射明确才可自动打开该目标串口，不打开全部或程控电源端口。
- 串口打印可随时被动读取，即使Telnet可用、未触发Debug或升级持有发送锁；串口未打开时被动读取不会自动打开端口。主动Debug复用原窗口和连接，收发继续记录；AI持有控制权期间锁定该端口手动发送，关闭窗口/标签会取消并等待清理。Boot或身份不明提示符不发送唤醒键。
- 深入采集只使用DUT已有工具：最长30秒日志跟踪、256包/96字节截断且不超过10MiB的抓包，以及可确认旧值的OpenWrt内核console日志级别临时调整。原始抓包保存本机，只向模型发送保留真实值的摘要；报错后抓包不代表报错前的数据包。
- 临时状态恢复失败会记录“恢复待完成”，再次连接核查。AI禁止直接或间接重启、上下电、升级、恢复出厂；配置修复只给建议。操作员启动新设备任务时，已有AI临时操作须先清理，不会强制抢占。

### 报告与学习

“诊断与监控”可查看本地报告，区分事实、证据、原因假设、建议、缺失信息及恢复状态。报告保留使用的厂商、模型、批次和通道。API不可用时仍保留本地触发快照。

本地证据按采集工具和PC命令分段显示，保留实际换行、采集失败原因及串口现场日志。PC命令输出兼容UTF-8与Windows本地编码，主执行日志记录实际命令、解码编码和返回码，无法解码时明确提示。修正仅影响新采集内容及报告显示；旧报告中已经损坏的中文不会自动恢复，需要重新发起分析采集。重启源码程序后生效。

在“已确认案例”填写实际原因、处理方法、复测结果和适用范围，人工确认后才参与检索。支持修订、停用和删除；AI猜测或自行恢复不自动成为根因。案例在本机供不同模型复用，只发送本次所需且保留真实值的摘要，不转发上一厂商的完整对话，也不进行模型微调。

## 当前实现

这是用于配置测试通道、自动上/下电、检查线路和升级样机的桌面工具。

本文后续出现的 `config/...` 均指 `Auto_power_on_off_tool/config/...`；主程序不再使用 `Cheating_machine_execution_tool/config`。

- **工具栏项目名称**：显示“项目信息”中已保存的项目名称，不添加“当前项目：”前缀；浅蓝底、深蓝加粗，超长名称显示省略号，鼠标悬停可查看完整值。启动、打开“测试项配置”、重新加载和保存后刷新，未保存的编辑不影响显示。项目名为空或配置文件不存在时显示“未设置”，读取异常显示“读取失败”并记录执行日志；保存部分失败时回读实际磁盘值。150%字体缩放下若将窗口缩至1040像素宽，原有工具按钮可能受挤压，请将窗口扩至1200像素或最大化。
- 读取和实时维护 `Auto_power_on_off_tool/config/network_card_ip.ini` 的通道配置。
- **显示所有网卡和串口**：主界面“2 配置测试参数”的样机管理IP输入框右侧提供同名勾选框，每次启动默认不勾选。勾选后，“通道对应 VLAN”展示全部已识别网卡（包括以太网、Wi-Fi、虚拟及禁用网卡）；“程控电源串口”和“通道对应 COM口”均展示本机实际识别的全部串口，不限编号或品牌，按编号排序去重，电源仍可留空。下方的原有分组规则适用于未勾选时。取消勾选只恢复候选规则，不清空当前选择；开关本身不写配置，实际选择仍实时保存，有效的已保存电源COM编号在重启后继续保留。点击“刷新串口”同步两处COM候选，点击“刷新网卡”更新网卡候选；串口枚举失败保留上次成功清单，未识别到串口或设备断开时保留当前选择。自动上/下电的串口选择弹窗遵循相同模式并保留当前串口。切换显示模式只更新列表，不打开串口或下发命令。
- 在“通道对应 VLAN”选择非数字结尾的网卡时，软件先恢复原选择，再询问是否修改网卡名称。选择“否”或取消输入保留原配置；选择“是”后可输入新名称并点击“确认修改”，由软件执行 Windows 网卡重命名。新名称须以 **2–254** 的数字结尾（**非网关地址**），例如 `VLAN101`、`以太网101`，且不能与其它网卡重名；“非网关地址”为操作员选址提示，软件不自动查询或修改系统网关。修改需要管理员权限，测试、升级、写参、网络查询或全流程运行期间禁止修改。后台执行期间请等待身份回读完成；超时先核实实际结果，不重复下发。
- 网卡改名成功后自动刷新候选，当前通道选中新名称，并同步引用旧名称的其它通道和相关目标预览、派生 PC 静态 IP。通道勾选和其它配置保持，显式 COM 不变；历史无显式 COM但原 VLAN 有有效映射时，会将原映射保存为显式 COM以保持原串口。配置仍按原规则只保存启用通道。系统修改失败保留原配置；提示“网卡已重命名，但配置保存失败”时，系统名称和内存已经更新，请核对后重新保存。若无法确认结果，请先在 Windows 网络连接中核实名称，再点击“刷新网卡”重新选择。
- 主界面内容区不重复显示应用名称和功能说明，只在 Windows 标题栏显示“openWRT老化测试环境搭建助手”及当前发布版本；版本号从发布包的 `VERSION_INFO.txt` 读取，后续发布更新该文件后标题会自动同步。“执行日志”标题下不再显示“运行步骤、检查结果和异常信息”提示行，日志框与“清空日志”按钮保持不变；管理员权限状态显示在“常用工具”栏右侧、“刷新串口”左边，权限就绪为绿色，缺少权限为红色警示。刷新串口、刷新网卡按钮顺序保持不变；其右侧新增“检查更新”。窗口较窄时，管理员状态、刷新和更新控件整体换到工具栏下一行靠右显示。
- 主界面左侧“选择测试通道”列表加宽显示，已启用通道的 VLAN 与 COM 信息不会被截断；通道表提供“通道对应 VLAN”和“通道对应 COM口”两个只读下拉列，选择后实时保存到`network_card_ip.ini`。程控电源串口首项为空值：未选择时，VLAN列展示PC中所有已识别网卡，COM口列展示`COM1`–`COM48`；选择程控电源后，两列都按每组8个范围筛选，例如`COM101`对应`VLAN101`–`VLAN108`和`COM1`–`COM8`，`COM102`对应`VLAN109`–`VLAN116`和`COM9`–`COM16`，后续分组顺延。切换程控电源不会自动清空或改写已保存的通道VLAN/COM配置。自动上/下电、全包升级和全流程执行在未选择程控电源时仍要求操作员确认已手动重启样机，且不会向任何程控电源COM口下发指令。
- 在左侧“选择测试通道”列表中右键任一通道，可选择“打开本次开关机运行日志”或紧接其后的“打开本次WiFi连接日志”。程序先将该行设为当前通道。开关机运行日志仍在`Auto_power_on_off_tool/test_results/device_N/`中匹配`device_N_command_results_*.log`，按文件名时间戳打开最新一份。WiFi入口只打开当前测试批次、当前执行或续跑尝试已成功刷新过的准确文件，可查看正在写入的内容；完成或停止后仍可打开该文件。新测试或续跑尚未生成文件时明确提示，不回退打开历史文件；未参与当前批次的通道、没有当前批次（包括重启程序后）、文件被删除或移动时分别提示。两类入口互不混选，只交给Windows关联程序打开，不改写、改名、清理文件或执行电源/设备命令。未选有效通道、无文件及打开失败时提示并写主日志；本次尚未生成WiFi文件时显示预期结果目录。
- 左侧通道列表中，单击或双击通道行以外的空白处不会选择通道或切换启用状态。
- 执行全流程子任务7“开关机测试”时，左侧已选通道继续只用于配置、勾选和右键打开结果日志，不显示运行态。主界面“环境检查与开关机测试”卡片会展开“通道概览”：每张小卡显示通道号、独立完成轮次和等待/运行/重试/失败/已完成状态；卡片可收起，点击任一小卡会在下方显示该通道的当前阶段或失败详情。概览上方只显示落后、重试或失败通道的“关注”行，避免正常通道淹没异常信息。某条测试指令进入下一次验证前，该通道小卡显示“重试”，主执行日志仍以黄色显示“通道 N 执行指令：…，在第X次时出现错误；准备第Y/Z次验证”；重试用尽时，小卡显示“失败”，主执行日志以红色显示完整指令与验证次数。全部通道结束后，结束提示逐行列出每台的最终结论，而不只显示失败通道编号；其余通道仍按原策略继续完成。
- **通道正常颜色恢复**：收到“通道N下挂的设备在第X次测试时正常”的明确轮次结果后，该通道小卡立即恢复绿色“正常”（例如 `3/5 正常`），全部轮次完成仍显示绿色“已完成”。明确开始下一轮或续跑时切回运行状态；后续重试、失败继续显示黄色、红色。重复或旧轮次正常日志不会覆盖新的异常，当前状态恢复不清除此前的重试/失败历史，最终结论仍以实际业务结果为准。
- 通道概览中的小卡点击后，主界面只保留当前轮次/状态的一行摘要；该通道**本次开关机测试**独立保存的“重试/失败历史”会在非模态、可滚动的独立窗口中显示。历史按发生顺序列出所属轮次、重试、重试后成功和最终失败信息；也收录旧工具的“第 N 次连接telnet 失败，等待10s再连接一次”、带通道号的“执行错误时发生异常”（保留完整指令和异常原因，如 WinError 10054）以及“发送 ping error 信号”原文。Telnet 等待重连标为“重试”，命令异常与 Ping error 标为“失败”事件，事件本身不改变测试的最终结果判定。窗口打开期间会随新事件刷新。每次重新启动开关机测试时，仅清空本次所选通道的旧历史，不写入配置或改动旧工具结果日志。

- C600必须保留一条网络侧VLAN600业务。例如 `5,112,335`、`6,113,600`、`7,114,50` 分别表示ONU侧112/113/114进入网络侧语音335/IPTV600/TR06950。`6,113,600` 会将ONU侧 `service` 和 `mvlan` 配为113，OLT侧仍为 `igmp mvlan 600` / VPort3 receive-port，并仅在该ONU的IPTV VPort增加 `mvlan-translate 600 to 113`；不修改全局组播转换表。旧600→600不新增转换命令。该新增组播命令的现场版本兼容性、WAN DHCP、双向业务与IPTV持续播放/切台尚待负责人复验；出现CLI错误会按原规则停止，配置回读成功不等于节目验收通过。

- 全包升级中的 `Tftp指令` / `Tftp Put` 与主界面的“样机管理 IP”和通道已保存的 PC 静态 IP 隔离：无论两者填写何值，均将当前 VLAN 网卡准备为固定 `192.168.1.<VLAN尾号>`，样机固定使用 `192.168.1.1`；运行时切网不改写 `network_card_ip.ini`。`web打开网关` 则使用主界面填写的样机管理 IP 和对应通道 PC 静态 IP/掩码，详见下文；页面升级、写参和线路 Ping 保持各自原有地址配置。
- 选择“全包升级 + Tftp指令”后，只显示可调的并行数 Spinbox（1–8）；程序始终按该并行数完成即补位，单台失败不会停止其它样机。程控电源 COM 帧仍按通道串行发送，后续 Boot、TFTP、重启等待和最终登录可并行。每台 TFTPy Server 及其后续数据传输 socket 都严格绑定当前 VLAN 的 PC IP；设置网卡 IP 后会最多等待 15 秒，直到 Windows 确认该 IP 可绑定，仍不可绑定才报网卡/重复 IP/驱动错误，不回退到 `0.0.0.0`。所选固件映射为设备固定请求名 `tclinux_allinone`，设备仍执行 `tftp <通道IP>:tclinux_allinone`。
- 选择“全包升级 + Tftp Put”后，程序先对当前通道下电再上电；上电帧下发后等待 1 秒稳定，随即循环发送回车，检测到 `UserName:` 后按 boot 账号 `telecomadmin / nE7jA%5m` 登录。随后仍由 TFTPy Client 从当前通道 IP 上传到固定设备 `192.168.1.1:69`，并绑定该源 IP，避免多张 `.1` 网卡造成错误选路或启动变慢；远端文件名使用所选固件 basename。上传后同样观察 90 秒 Boot/Bood 标记：检测到则发送 `reset`，未检测到则对当前通道执行后备下电再上电；后备上下电沿用普通电源默认时序，不使用首轮进入 boot 的 1 秒/1 秒专用时序。未勾选恢复出厂时，完成 reset 或后备上电后仅等待 3 秒即结束当前通道，不登录最终系统；勾选恢复出厂时才保留 120 秒等待、最终系统登录及恢复出厂。该流程同样始终按 Spinbox 的并行数运行，单台失败不会停止其它样机，共享程控电源 COM 由 coordinator 复用同一长连接。
- `Tftp指令` 和 `Tftp Put` 均可在执行窗口的 Spinbox 调整并行数 1–8 台（默认 2，存于 `sample_upgrade_settings.ini` 的 `parallel_count`）；全包升级全程不临时改写 `Auto_power_on_off_tool/config/network_card_ip.ini`；所有串口和 TFTPy Client/Server 都由本程序在 `finally` 中关闭，不查找或关闭外部 CRT/Tftpd 进程。一次并行批次内共享的程控电源 COM 由 `UpgradePowerCycleCoordinator` 持有长连接 `ProgrammablePowerSupply`，仅在首台样机上下电前打开一次，最后一台完成后由 `coordinator.close()` 关闭，避免逐台反复 open/close。
- 全包升级进入 boot 前，`Tftp指令` 与 `Tftp Put` 的程控电源时序统一为“关闭当前通道 → 等待 1 秒 → 开启当前通道 → 等待 1 秒 → 立即放行串口循环回车”；不会再补足 10 秒启动等待或叠加第二个 1 秒等待。主执行日志会输出上电稳定完成及开始进入 boot。该调整只用于样机全包升级，普通自动上/下电等其他电源流程保持原有默认时序。
- `Tftp指令` 仍以串口的 `done` 与 `write` 同时出现作为设备处理完成判据；`Tftp Put` 则以 TFTPy 上传成功作为传输完成判据。两条路径传输后均观察 90 秒 boot 标记：`Boot/Bood` 后延迟 1 秒发送一次 `reset`，未检测到时已配置程控电源则对当前通道执行一次后备下电再上电；后备上下电保持普通默认时序。**未勾选恢复出厂**时，完成 reset 或后备动作后只等待 3 秒，记录当前通道升级完成并跳过最终系统登录。**勾选恢复出厂**时，才等待 120 秒、执行最终系统五次登录重试，再按“命令→1 秒→回车→8 秒”执行恢复出厂；最终登录只能由独立的 shell 提示符行判定成功，密码回显中的 `#` 或 `>` 不会触发恢复出厂。仅当实际发送恢复出厂命令后，主程序执行日志才显示 `TX firstboot -y;reboot`。未配置程控电源时会记录跳过后备上电；未勾选恢复出厂仍等待 3 秒后结束当前通道。
- `Tftp指令` 在样机串口同时出现 `ARP Retry count exceeded` 与 `U-Boot>` 提示符时会自动重发同一 `tftp` 命令，最多 3 次、每次间隔 1 秒；单次等待窗口 5 分钟，由按秒轮询替代阻塞 `wait_for_all`，避免已知快速失败场景消耗完整超时。每次重试和最终成功/失败都会写入主程序执行日志，例如“检测到 ARP Retry count exceeded...，剩余 2 次自动重试”、“自动重试 TFTP 命令：第 2/3 次发送...”、“TFTP 命令在第 2 次尝试时检测到完成标记”或“TFTP 命令已重试 3 次仍未成功...”。仅 `ARP Retry count exceeded` 但未回到 `U-Boot>`（样机仍卡在 Loading）时按普通超时处理，不重试。
- Boot 登录在上电帧后的 1 秒稳定窗口结束后立即发送首个回车；仅当完整 `UserName:` / `User Name:` 在 1 秒稳定窗口内未夹带旧 `Password:` / `Passvord:` 时才提交用户名。用户名回车后重新从串口新数据中等待完整密码提示符，避免首轮上电过渡日志或旧缓存导致账号、密码错位。`Tftp Put` 的 UserName 后直连 boot 登录会在写用户名前记录密码游标、在写密码前记录 shell 游标，确保同批回显里的 `Password:` 或 `ECNT>` 不会漏检。
- 主界面“串口日志记录”已改为内置多通道终端：按 VLAN/COM 分页实时显示、开始/停止、清屏、手动命令发送和日志保存。每个Tab优先打开该通道“通道对应 COM口”的实际选择；历史配置没有`serial_port`时才按`vlan{N} → COM{N-100}`兼容推导。手动打开、“打开全部”、全流程预启动以及自动升级附加日志使用同一映射。“打开全部”会依次启用窗口当前全部 VLAN/COM Tab。每个 Tab 的命令输入框按下 `Enter` 即等价于点击「发送」按钮（输入框非空则发送文本并清空，等价「发送」；输入框为空时发送纯回车，等价「回车」）；自动升级占用某通道时仍显示输出，但手动发送（含按 Enter）被锁定；高频串口输出以最多约每 33ms 一轮的节奏渲染，只有当前 Tab 实时重绘，其他 Tab 切换后显示最新缓冲；每个 Tab 的屏幕只保留最近 5000 行，避免长时间高频输出导致 Tk 无响应。屏幕缓冲超过 64KiB 时会提示已合并字符，但原始日志始终完整写入磁盘；日志文件名按打开监控当日保存为 `vlan名_COM口_YYYYMMDD.log`，例如 `vlan112_COM12_20260808.log`，手动打开、“打开全部”和全流程预启动必须记录实际选择的COM；文件内每个落盘行都以 `YYYY-MM-DD_HH:MM:SS` 开头并保留 RX/TX/STATE/ERROR 方向，例如 `2026-08-08_19:12:10 RX 打印内容`，半行分包会先拼接，不会重复添加时间戳；全包升级自动打开的终端会在本批串口释放并写入关闭状态后自动关闭，手动打开的终端不会被自动关闭；`reboot`、`reset`、`firstboot`、`tftp`、`upgrade` 类手动命令需要二次确认；默认日志目录或本机终端状态文件不可写时会弹出明确错误提示。
- 凡主程序需要准备 VLAN 网卡的流程，都会先查询目标网卡的启用状态和现有 IPv4/前缀：已经启用且地址完全匹配时直接复用，不再重复启用或设置静态 IP；仅有一项不满足时只修复该项，无法读取状态时按原流程完整准备。该规则覆盖线路 Ping、页面升级、全包升级 TFTP 网卡、写参用户/工厂模式切网、测试项执行、DUT 配置和“查询现有 WAN”；原来具有源 IP 可绑定确认的流程仍会继续确认，后续 Ping、UBUS/Telnet 登录或 TFTP 成功判据不变。
- **单独关闭串口**：每个串口标签右侧均有“×”，点击后直接停止该标签监控并移除标签，已保存日志保留，其他串口继续记录。未打开或已停止的标签也可移除；自动升级占用时会提示“当前串口正在自动升级，升级结束后可关闭”，保留连接和标签。点击标签正文只切换页面；在“×”上按下后拖离再松开不会关闭。关闭最后一个标签后窗口仍保留；再次点击主界面“串口日志”入口可按当前勾选通道恢复标签，再点击“打开全部”启用。关闭不修改主界面通道配置；成功、占用跳过和失败会记录在主执行日志中。多个标签使用同一COM时仅移除本标签监控，其余持有者继续使用连接。

- 主界面“串口日志”右侧提供“DUT配置”入口。窗口包含“Telnet配置”“WAN配置”“2.4G WiFi配置”“5G WiFi配置”“语音配置”“TR069配置”六个 Tab。主界面已勾选通道只作为候选范围；六页目标表共享独立“选择”列和“全选/清除”按钮，首次加载默认选中全部候选，在任一页勾选或取消都会同步到其它页，所有配置和只读查询只处理DUT窗口内当前选中的目标。因此主界面可同时保持vlan112、vlan113启用，再在DUT窗口取消vlan113，仅操作vlan112。刷新相同候选范围会保留手动取消状态，主界面新增候选默认选中、移除候选自动删除；选择变化后旧查询状态和WAN下拉失效，未选择目标时禁止启动。UBUS 账号、密码和并行数与 Telnet 页共享，账号密码与“写样机参数”的首次登录凭据一致并明文显示。每台完成上述按需网络准备后仍等待源 IP 可绑定，再从该源 IP 登录样机 UBUS；支持 1–8 台并行（默认1）、单台失败隔离和停止后不再启动后续 DUT，同一时间只运行一个 DUT 配置批次，批次运行期间不能修改目标选择。
- “Telnet配置”点击“开启 Telnet”并确认后，通过 UBUS 开启 `Device.Firewall.<X_SDMC_>Security.AccessCtrl` 下的 LAN-telnet 规则，再从对应 VLAN 源 IP 验证 TCP 23 端口；只有 UBUS 和端口验证均成功才判定成功。点击“查询当前Telnet”只读取AccessCtrl总开关和LAN Telnet规则，并锁源探测TCP 23，不执行set/add；“当前状态”区域逐台显示总开关、规则、SourceInterface和端口可连接状态。
- “WAN配置”支持新增、修改和删除指定 WAN，并按当前选择实时只展示有效字段：新增隐藏现有连接索引，修改显示索引和配置项，删除只保留现有连接选择。修改/删除时，“现有连接名/索引”是只读下拉框；点击旁边“查询现有 WAN”后，程序会对DUT窗口当前已选中的每台目标执行网络准备和锁源 UBUS 登录，通过只读 `bbfdm.get Device.IP.Interface.` 获取现有连接。单台时显示该 DUT 的连接；多台批量时只显示所有目标名称完全一致的共同 WAN，不按相同数字索引合并不同业务；任一目标查询失败或停止都不会生成下拉列表。目标 DUT 或DUT窗口选择变化、执行过 WAN 配置后会清空旧列表并要求重新查询。桥接仅展示业务类型、业务 VLAN、优先级和端口绑定，业务类型限定为IPTV/INTERNET/OTHER；路由才展示接入方式、协议、MTU、NAT和地址参数。端口绑定使用LAN1–LAN8原生多选框，分别对应位掩码1、2、4、8、16、32、64、128，多选自动按位合并；新建桥接且未选择端口时默认勾选LAN1，查询现有WAN时会把例如 `PortBind=8` 反向显示为LAN4。修改现有WAN时会保留设备返回的WiFi等非LAN绑定，切回新增时不继承这些不可见旧位。当业务类型为IPTV时，路由和桥接都会额外显示可选“组播 VLAN ID”；留空表示不单独配置，填写时必须在1–4094范围内并以 `MulticastVLANID` 下发，切换到非IPTV后该字段隐藏且旧值不会误下发。IPoE隐藏PPPoE账号密码、切换时自动回填默认MTU 1500；PPPoE显示账号密码、自动回填默认MTU 1492，并只允许动态地址。IPv4只显示IPv4地址方式，IPv6只显示IPv6地址方式，IPv4+IPv6双栈同时显示两者；DHCP/SLAAC/DHCPv6隐藏对应静态地址项，选择静态才显示地址、网关、DNS和掩码/前缀。IPoE双栈仅允许DHCP+SLAAC、DHCP+DHCPv6、静态IPv4+静态IPv6；PPPoE双栈仅允许动态IPv4+SLAAC或动态IPv4+DHCPv6。界面下方会显示当前组合说明，业务预检也会再次拒绝非法组合；MTU自动值仍可按设备需要在576–2000范围内调整。程序不提供删除全部 WAN，删除前会再次提示不可自动恢复。
- “查询现有 WAN”现会一次只读获取 IP Interface、Ethernet/VLAN、PPP、Bridge、DHCP、DNS 和 NAT 关联信息，并把同一批结果逐台显示在WAN页“当前状态”区域，不会为状态展示重复查询设备。查询成功后默认选中第一条，切换下拉项会把当前连接的业务类型、业务 VLAN、组播 VLAN、优先级、模式、端口绑定、接入方式、IP协议、地址方式、MTU、NAT，以及设备可返回的静态地址/DNS/PPPoE凭据同步到表单；例如 `3_INTERNET_R_VID_172` 会显示 `INTERNET` 和 VLAN `172`，不会沿用新增页原来的 TR069/VLAN默认值。多台批量时，只有同名 WAN 的完整参数在所有目标上也一致才自动回填；参数不一致仍保留共同名称供删除选择，但修改前会提示人工核对，避免拿任意一台覆盖整批。
- 每次 DUT UBUS 查询或配置结束时，程序会调用 `Device.X_SDMC_Login.logout()` 释放设备端session，再关闭本机HTTP连接；WAN查询日志会显示注销TX和结果，避免连续第二次查询因上一轮session残留而被设备拒绝。
- “2.4G WiFi配置”和“5G WiFi配置”分别配置指定SSID索引（1–8）的WiFi名称、密码、信道、信道带宽、启用/隐藏、认证/加密模式、WiFi协议类型、发射功率、最大接入数和WMM，并共享一个“启用双频合一”全局选项。勾选双频合一后，当前页会同时显示当前频段和另一频段两个独立“射频参数”区域：2.4G与5G的信道、信道带宽、协议类型分别选择；发射功率作为公共参数写入两个Radio。取消勾选后隐藏另一频段区域，只修改当前Tab对应Radio。两个页面各自提供默认关闭的“SSID递增”：关闭时所有已选DUT使用同一名称；开启时输入名称必须以数字结尾，第一台使用输入值，后续按DUT目标表固定顺序逐台加1并保持数字位数，例如`Aouxue_001 → Aouxue_002 → Aouxue_003`。无数字尾缀或任一生成名称按UTF-8超过32字节时会整批拒绝，不会自动追加或截断；执行确认框和主日志逐台显示`通道/VLAN → 最终SSID`。当已选多台且开启SSID递增时，程序先向全部目标下发参数，只在批次最后一台显示并执行一次可停止的60秒稳定等待，随后重新逐台登录并回读校验；等待期间停止时，已下发但未回读的目标不会标记成功。单台设置或未开启递增的批量设置仍保持每台下发后等待60秒再回读。2.4G与5G递增开关互相独立，开启双频合一时同一台DUT仍使用本批为它生成的同一个SSID同步两个频段。首次打开或设备未返回能力字段时使用兼容候选：2.4G为auto或1–13、20/40MHz/20MHz/40MHz及b、b/g、b/g/n、b/g/n/ax；5G为常用36–165信道、20/40/80/160MHz及a、a/n、a/n/ac、a/n/ac/ax；发射功率兜底为20/40/60/80/100%，认证兜底包含开放、WPA2/WPA3及混合模式。开放网络会隐藏密码并且不下发遗留密码，加密网络密码必须为8–63字符或64位十六进制密钥。
- 两个WiFi页点击“查询当前…”后，都会只读解析当前SSID索引对应的`Device.WiFi.X_SDMC_Mapping_2G/5G`和两个Radio能力，为双频开关随时提供两套真实候选；不会因从2.4G页进入就复用到5G。查询只执行`bbfdm.get`，逐台显示完整当前状态，全部目标成功且公共参数、两套Radio参数及能力完全一致时才同步表单。认证/加密模式按AP Security的`ModesSupported`加载，两个频段的信道分别按各自`X_SDMC_ChannelsSupported`加载，带宽和协议分别按各自`X_SDMC_ModeBWMap`加载，发射功率优先按两个Radio的`TransmitPowerSupported`及兼容厂商字段加载；双频开启后公共发射功率候选取两个Radio均支持的值。切换目标或多台能力不一致时旧能力候选立即失效并要求重新查询。执行双频配置时，SSID名称、启用/隐藏、认证密码、最大接入数和WMM同步到2.4G与5G；两个Radio分别下发自己的信道、带宽和协议，公共发射功率分别写入两个Radio，等待稳定后同时回读校验。
- “语音配置”批量设置SIP线路、账号开关、显示名、认证账号密码、代理/出站代理/注册服务器、端口、DTMF、注册有效期、SIP模式、5项编码和DigitMap。点击“查询当前语音”后，DTMF候选按VoIPProfile支持字段加载，SIP模式按`X_SDMC_SIPModeSupported`兼容字段加载，编码按标准`Device.Services.VoiceService.1.Capabilities.Codecs.`能力表加载；设备缺少对应能力字段时才使用兼容候选，当前实际值始终保留。所选值原样写入设备，未知或当前DUT不支持的值会在下发前被拒绝；下发后回读SIP路径，账号启用时会先检查必填项。

## 验收步骤

1. 启动软件后，确认界面能列出 `network_card_ip.ini` 中已有的 `channel_1`、`channel_2` 等通道。
2. 点击“刷新网卡”，确认下拉框里能看到当前 PC 的网卡名称，例如 `a虚拟网卡2口`。
3. 选择一个通道，填写：
   - 样机接入网卡
   - PC 静态 IP
   - 样机管理 IP
   - 子网掩码
   - 是否启用
4. 勾选或取消勾选通道，确认 `Auto_power_on_off_tool/config/network_card_ip.ini` 立即更新，并且只保留已勾选通道的 `[channel_x]` 配置节。
5. 人工接好线路后，点击“自动上/下电”，选择程控电源 COM 口和操作类型（默认“上电”），并确认影响通道。
   - 选择“上电”时，软件会按勾选顺序发送开启帧，相邻帧间隔 1 秒，且不会先关闭任何通道。
   - 选择“下电”时，软件只会向勾选通道发送关闭帧，相邻帧间隔 1 秒，不会发送全部断电帧。
   - 确认后主程序直接发送程控电源串口帧，不会启动旧 EXE 或点击外部 GUI；最后一条帧后不额外等待。
6. 回到新软件，点击“检查当前通道”或“已上电，开始检查全部启用通道”。
7. 观察日志：
   - 通过：显示 `[通过] channel_x ping xxx 成功`。
   - 失败：显示通道、网卡、PC IP、样机 IP，并提示检查上电、网线、接错口、IP 配置。
8. 打开“样机升级”，选择“页面升级”，确认已勾选通道都有 PC 静态 IP 和样机管理 IP，选择固件后点击“开始升级”。
   - 软件会二次确认将通过 UBUS 上传固件并触发升级。
   - 软件会先启用目标通道对应网卡；如果启用失败，会在日志和失败弹窗中提示。
   - 日志会显示每台样机的 HTTP/HTTPS 登录、上传、升级状态和重启上线结果。
9. 打开“写样机参数”，先使用“生成批量参数表...”为已勾选 VLAN 生成 Excel 表，或选择已有 `.xlsx` / `.xlsm` / `.xls` / `.csv` 参数表；确认预检清单中的 VLAN、COM、MAC 一一对应。
   - 并行数可选 1–8 台，默认 1；修改后会保存，下一次打开“写样机参数”会恢复上次关闭前的有效值，不影响“样机升级”的并行数。
   - 点击“写入参数”后，确认框会提示清空参数、工厂模式和两次重启；仅在确认后才实际下发命令。
   - 现场先以 2 台独立 VLAN / COM 样机验证，确认每台写入后读回校验成功、密码明文便于核对，并确认设备已完成退出工厂模式后的重启。
10. 打开“测试项配置”，可加载并编辑 `Auto_power_on_off_tool/config/test_project_config.ini`，并在“开关机运行参数”页编辑 `config.ini [ui_defaults]`，详见下方「测试项配置窗口」。

## 测试项配置窗口

主界面工具栏「测试项配置」按钮用于编辑测试配置；“测试项”页提供独立的单次预备测试，“项目信息”页提供版本查询。预备测试不加入全流程子任务。

### 单次预备测试

1. 在主界面勾选目标通道，配置各通道网卡、PC 静态 IP、掩码及样机管理 IP。
2. 打开“测试项配置”，填写 Telnet 登录参数，在“测试项”页点击“执行全部命令（预备测试）”。检查确认框列出的全部目标后开始。
3. 使用当前页面内容（包括未保存修改），按通道列表和命令列表顺序执行。每条命令只下发一次，忽略正式测试的重试次数及间隔，不自动保存配置。
4. 沿用现有多段期望、`&&` 和否定匹配；单条不匹配或回显超时标红后继续下一条。无期望时显示“未配置结果校验”，不计为成功；登录失败、连接中断或网络准备失败终止当前设备，继续下一个已确认目标。
5. 主界面日志记录源/目标 IP、下发命令、设备回显、逐条结果及汇总，成功绿色、失败红色，未校验/停止黄色。内容自动追加到当前主执行日志文件（文本文件保留时间戳和状态文字，不保存字体颜色）。
6. “停止执行”阻止后续命令与目标；已经下发的命令无法撤回。连接或网络操作退出后恢复按钮，汇总已执行与未执行数量。运行时关闭配置窗口或主程序会先请求停止，待日志保存后再关闭。

预备测试会按目标配置准备网卡并登录 Telnet；请保证设备 Telnet 已开启。登录成功提示符为 `>` 时，先发送当前 Telnet 页的“登录后命令”一次并等待 1 秒，再执行测试命令；确认框会列出该登录后行为，空值仍发送一次回车。它不触发电源、WiFi、升级或正式开关机测试流程；实际设备行为由当前页面中的命令决定。

新版预备测试、测试项执行和项目信息查询在登录成功提示符严格为 `>` 时，连接后直接等待设备主动输出的用户名提示符（包括已经收到的历史内容），不先发送回车，避免 CMS 将其当作空用户名。主日志依次提示等待用户名、用户名已发送、密码已发送（隐藏）和等待 `>`；密码后出现空行或 `Entering CMS CLI:` 不影响匹配。未收到提示符时按原超时结束，不盲发账号或额外回车。`#` 等其它提示符继续使用原登录起始方式；本次不改变共享连接超时、换行或登录后命令规则。

### 配置编辑

Telnet 页保留“免用户名密码登录”“仅执行上下电”两个“是/否”下拉框。任意一项为“是”时，登录用户名和密码输入框置灰；两项都为“否”时恢复编辑。置灰保留原有内容，保存、重新加载和关闭重开均保留用户名、密码及对应选项；免认证失败时仍沿用原有凭据回退流程。“是否需要输入密码”已取消，其旧回车探测不再执行；旧配置中该项为1也不生效，加载不改写文件，保存时兼容键统一写回0。

- **六 Tab 结构**：
  - **Telnet** —— 编辑 `[telnet]` 段的 12 个可见字段。界面只显示中文含义：设备默认已开启 Telnet、Telnet 开启地址、登录用户名、登录密码（明文）、Telnet 端口、连接超时时间、用户名提示符、密码提示符、登录成功提示符、登录后命令、免用户名密码登录、仅执行上下电；INI 原始键名和数字保存格式保持兼容，废弃项按上文处理。密码输入框右侧小眼睛可在 `*` 密文 / 明文之间切换。“登录后命令”输入框与上方“登录成功提示符”等宽，保持左对齐，不随窗口横向拉伸；对应 `login_after_input_str`，缺键时默认 `sh`，自定义值或空值均可保存、重载和关闭重开恢复。仅在登录成功且成功提示符严格为 `>` 时发送，空值只发送回车；`#` 等其它提示符跳过。新版测试项预备测试、执行及版本查询发送后统一等待 1 秒，不额外等待 `#`，日志中的“已下发”不代表已验证进入 Shell；登录后命令不计测试条数或重试次数。旧开关机 Telnet 客户端在移除废弃回车探测后，其余登录后命令发送与等待时序保持。
  - **测试项** —— 编辑 `[order]` 段：顶部全局 Spinbox「指令重试间隔（秒）」默认 60，唯一保存到 `config.ini [other_config] command_fail_retry_interval_time`；`test_project_config.ini [order]` 只保存测试命令。中间滚动列表每条命令一行（命令 + 重试次数 Spinbox 1-99 + 删除按钮），不同命令组之间保留加宽的纵向留白，展开后是「期望」子表单（否定勾选 + 动态段列表 + 增加/删除段按钮）；底部提供「+ 新增测试项」和「恢复默认」。默认模板固定为 `Auto_power_on_off_tool/config/test_project_config.default.ini`；点击「恢复默认」并确认后会先清除当前页面全部测试命令，再恢复全部默认命令，不改变当前指令重试间隔、Telnet、WiFi、项目信息，恢复到界面后需再点击窗口底部「保存」才写入正式配置。
  - **WiFi** —— 保留连接主控、2.4G/5G、ONU方案、指定无线网卡和刷新功能，并提供“连接测试模式”“自动识别认证参数”和可选“无线 Ping”。只编辑或保存不会连接网络。当前正式Telnet测试仅支持openwrt方案；bcm/mtk历史值可显示，但启用测试时会明确提示暂不支持。
    - 默认“分别验证频段”：每个已选频段须实际连接到目标样机对应BSSID，并核对频率；同名SSID连接两次不代表双频通过。“双频合一”模式允许连接目标样机任一已确认频段，只产生一项接入结果，原频段勾选禁用但保留。双频合一状态读取失败时显示未知，不凭SSID同名推断。
    - 默认自动识别认证参数；取消勾选后展开高级手动认证/加密，原值始终保留。自动方式按目标BSS安全信息及Windows/网卡能力匹配，手动方式按指定约束核验；实际认证、加密、SSID、BSSID、频段会写入主日志。目标Mapping/BSSID信息缺失、网卡不支持或Windows权限不足会明确报测试环境异常，不改用其它样机或认证方式。
    - “启用无线 Ping”默认关闭；开启后填写IPv4地址或域名，不接受URL、端口、IPv6、回环、广播、多播和本机地址。每项发送4包、每包超时2秒、包间隔1秒，至少1个有效回复通过，同时显示丢包率及最小/平均/最大时延。关闭时保留目标，不解析域名、不发探测包。
    - 分频段模式在每个已选频段连接核验通过后分别Ping；合一模式只Ping一次。最多等待30秒获取无线IPv4；域名使用所选无线接口解析A记录，最多5秒，使用第一个IPv4。本项Ping固定无线源IP及出口接口，不通过有线网卡兜底，也不修改IP、DNS、路由或样机参数。启用Ping需原始socket权限，权限不足时提示以管理员身份运行。
    - 测试将断开所选无线网卡当前连接，使用不保存到系统的临时配置，结束时断开临时连接，保留原有无线配置，不主动连接其它网络。按FIFO由一个通道连续完成连接、核验和可选Ping后再交给下一通道。每频段合计最多4次尝试（首次加最多3次重试），扫描、连接及Ping阶段共用次数，进入Ping不重新计数。每次扫描/连接/连续2秒稳定核验共约20秒，重试间隔10秒；Ping阶段（含等待无线IP及结束后的连接复核）若掉线、SSID/BSSID、实际频率/频段或认证/加密核验失败，先断开并确认清理，再重新扫描、连接、核验和重跑本频段Ping，不累计先前尝试的回复。Ping全部无有效回复仍直接失败；DNS/IP/socket等环境异常沿用原处理。
    - Ping期间离开目标样机、分频段模式切换频段、接口或源IP丢失时，该项不通过，即使已收到回复。用户停止不计设备失败、不推进轮次、不继续下一频段或后续有线Ping；失败通道续跑重新读取样机信息。原有有线Ping仍独立执行，不替代无线Ping。新连接判据及无线Ping仍需负责人真实样机复验。
  - **项目信息** —— `[project_info]` 段：4 个可手动编辑的字符串字段（项目名称 / 软件版本 / 内部软件版本 / ONU 软件编译时间）。点击“查询当前样机版本”会使用主界面当前选中通道的 PC 静态 IP、样机管理 IP，以及 Telnet 页当前账号/提示符锁源连接样机；成功提示符为 `>` 时，先确认并发送当前“登录后命令”，等待 1 秒，再执行两条只读查询 `cat /etc/config/deviceinfo` 和 `cat /proc/version`，从前者读取 `software_version` / `inner_sw_version`，从后者提取编译时间。取消确认不会连接样机。三项查询结果显示在下方独立的只读文本框，不能手动修改，也不会覆写上方输入框或写入 INI；可拖拽选择后按 Ctrl+C，或鼠标右键选择“复制全部”。仍只有操作员编辑后点击窗口底部“保存”才写入 INI。开关机开始前及失败通道续跑的版本预检以当前选定方案中已保存的三项为准：去除首尾空白后三项全空表示不需要预检，项目名称不参与判断；部分填写必须补齐或全部清空后保存，全部填写则严格校验。
- **开关机运行参数** —— 加载 `Auto_power_on_off_tool/config/config.ini [ui_defaults]`，页面只展示 `startup_time`、`interval_time`、`number_of_tests`、`wait_command_done` 四项。界面左侧使用黑色中文名称（设备启动等待时间、每轮断电等待时间、测试循环次数、命令完成后等待时间），不显示原始键名，也没有右侧灰色说明列。`communication_method`、`baud_rate`、`selected_profile` 和 `telnet_enable` 不展示，保存时保留前三项原值；`telnet_enable` 由 Telnet 页 `telnet_default_on` 按 `1 → 0`、`0 → 1` 反向计算并自动写入。
  - **消息推送（第六页）** —— 读取 `config.ini [dingtalk_config]`，可修改“启用钉钉推送”、Webhook 地址、加签密钥和“@所有人”。两个开关选中保存为 `1`，未选保存为 `0`；地址和密钥直接显示，关闭推送仍可编辑。缺失字段默认关闭或空白，允许空文本，不允许换行。使用窗口底部“保存”统一确认并写入，“重新加载”恢复磁盘值；关闭或重新加载前会提示放弃未保存修改。保存保留其它段、未知字段及注释，日志不打印地址或密钥；编辑和保存不发送消息，既有自动发送时机保持不变。

“消息推送”页的“发送测试消息”使用当前页面地址、密钥和 @所有人设置，无需先保存推送配置，即使自动推送开关关闭也可手动试发。发送文本“项目：{project_name}”后换行，再附“LineCheckAssistant 消息推送测试：收到此消息表示钉钉机器人推送正常。”；填写密钥时自动加签，留空则不加签。若机器人设置关键词，需确保该文本满足规则。后台请求超时为10秒，不自动重试；发送中禁用按钮并阻止关闭配置窗口。页内与主日志显示结果；成功表示钉钉接口已接受，请在群中确认收到。网络异常结果未知时先检查群消息，再决定是否重试。不会保存配置或更改自动推送开关。

正式完成/异常通知的标题与正文，以及测试消息中的项目名，均在每次发送时读取 `Auto_power_on_off_tool/config/test_project_config.ini [project_info] project_name` 的已保存值，不再使用 `config.ini [config] test_project` 或固定项目名。“项目信息”页面修改项目名称后需先保存；未保存的名称不用于试发。项目名缺失、空白或文件读取失败时，提示失败并跳过发送。主执行日志记录项目名读取、实际 POST 下发及成功、跳过或失败阶段，凭据不写入日志。
- **底部按钮**：「重新加载」（从磁盘重读 ini，丢弃未保存改动）/「保存」（二次确认后写回 ini）/「关闭」。
- **Dirty 跟踪**：任意控件改动标记 dirty，「重新加载」和「关闭」在 dirty 时弹「放弃修改？」二次确认；「保存」成功后 dirty 清零。
- **窗口显示**：首次创建采用标准`Toplevel`自然映射，不执行`withdraw()`隐藏构建、`after(0)`强制恢复或嵌套`update()`；固定960×940尺寸直接用于居中，避免弹出前强制刷新复杂控件树；映射后20ms先执行一次立即恢复的1像素客户区快速刷新，并保留120ms和360ms两次兜底，强制Windows整体重绘五个Tab且不改变窗口尺寸；再次打开已有窗口也会补充刷新。
- **保存行为**：保存会把 Telnet、测试命令、WiFi 和项目信息写入 `test_project_config.ini`，把指令重试间隔仅写入 `config.ini [other_config]`，并更新 `config.ini [ui_defaults]`；WiFi原有8项键继续保留，新增 `connection_test_mode / security_source / wireless_ping_enable / wireless_ping_target`。旧配置缺键时采用分频段、自动认证、无线Ping关闭和目标空值，不自动写文件或覆盖原频段、网卡及手动认证值。测试项 ini 的原注释会丢失，`config.ini` 的其它配置段、未知键和注释保持不变。测试项 ini 不存在时打开窗口会提示「将以空白表单打开」，保存后自动创建。
- **「期望」拼接规则**：每段独立勾选「否定」→ 该段前加 `!`；多段 → 用 `&&` 拼接；空段不写入拼接结果。例如第二段的 `00:00:00:00:00:00` 勾否定、`UP BROADCAST` 不勾，保存为 `!00:00:00:00:00:00&&UP BROADCAST`（前者应**不**出现，后者应**出现**）。
- **「重试间隔」语义**：本字段名为 `command_fail_retry_interval_time`，唯一保存到 `config.ini [other_config]`，不会写入 `test_project_config.ini [order]`；与老工具 `wait_time_N`（sleep 秒数，**语义不同**）不共用。它是全流程测试项命令失败后的重试等待时间，测试项页面和全流程执行都从这一唯一位置加载。
- **主执行日志**：保存成功 / 失败都会写一条主程序执行日志；成功日志同时记录测试项命令数和更新的旧工具参数数量。
- **执行边界**：本窗口不会因编辑或保存立即连接 WiFi、执行 telnet、上下电或运行测试命令；“测试项配置（[order] 执行）”已从全流程子任务中移除。但保存的 WiFi 参数会在以后勾选全流程子任务7“执行开关机测试”时由无 GUI 旧业务读取并生效。

### 旧工具顶部参数配置

旧 `Auto_power_on_off_tool/Auto_Power_On_Off_Tool.py` 顶部的通信方式、波特率、默认方案及运行时间参数从 `Auto_power_on_off_tool/config/config.ini [ui_defaults]` 读取。旧工具 `Telnet Enable` 与新工具 `test_project_config.ini [telnet] telnet_default_on` 使用反向关系：`telnet_default_on=1` 表示设备默认已开启，旧工具 `telnet_enable=0`；`telnet_default_on=0` 时旧工具 `telnet_enable=1`。旧工具启动时直接按此关系加载，新工具保存测试项配置时同时更新 `config.ini [ui_defaults] telnet_enable` 镜像值并保留其它内容。`command_fail_retry_interval_time` 只保存在 `config.ini [other_config]`。旧工具的 `serial_num` 与新工具“程控电源 COM”严格共用同一值，固定读取 `network_card_ip.ini [power_supply] serial_port`；新工具 COM 为空时旧工具同样为空，不回退、不自动选择其它 COM。“电源控制”的 channel 1～16 复选框也严格同步同一文件中的新工具选中配置：存在且 `enabled=1` 的 `channel_N` 才勾选，其余通道全部取消。全流程子任务7还会把当前测试方案 `[connect_wifi]` 的 8 项 WiFi 参数映射到旧业务 `OnuCongfig`；主控关闭时跳过 WiFi，指定网卡为空或运行电脑不存在该网卡时明确失败且不静默改用其它网卡。程控电源直连、升级和其它主程序路径仍不调用旧 GUI 或旧 EXE。

### 开关机测试的 WiFi 排队与停止

- **WiFi重试/失败历史**：点击主界面“通道概览”的通道卡，在现有“重试/失败历史”窗口查看该通道本次WiFi重试、最终失败和重试后成功。记录包含实际轮次、频段、已知尝试次数和原因（有错误码时保留）；同次重试的失败原因与等待提示合为一条，最终失败只记录一次，通道失败摘要也显示具体WiFi原因。只有本频段测试及清理确认完成才记“重试后成功”，首次成功不增加异常历史。WiFi信息读取、扫描、连接核验、无线Ping/DNS及清理异常均纳入；停止、跳过和正常排队不新增失败。失败续跑保留原历史，新尝试独立记录，不补录修改前运行的历史；主日志精简不影响历史记录。

- **双频切换与扫描恢复（2026-11-07）**：每次临时连接下发断开后，程序按0.2秒间隔查询真实无线接口状态，连续断开至少0.5秒才继续，最多等待5秒；这段确认仍持有网卡使用权，不启动下一频段/尝试。超时报“临时连接断开未确认”，结束当前通道，不反复发送断开；成功摘要也须等清理确认完成后才显示。正常状态轮询不刷日志，停止时完成既有必要断开后取消确认等待及后续动作，未确认时如实提示。
- 扫描的异步失败、扫描超时，以及API暂未就绪/忙碌/请求中止/要求重试/超时，可按原10秒间隔重试，但计入本频段原有最多4次尝试，每次扫描/连接/稳定核验仍共用20秒预算，不额外重扫。权限不足、接口/句柄错误、无线服务不可用及其它未分类API错误立即结束；四次扫描异常用尽仍归“测试环境异常”，不当作密码错误或通过。日志给出频段、尝试次数、来源、数值/十六进制错误码、原因及后续动作；未提供原因码或解码失败时保留实际可得信息。Ping全部无有效回复仍不重连；Ping阶段连接核验失败按上述每频段共用4次预算重试，不改变SSID/BSSID/认证及Ping通过标准；断开确认最多额外5秒，不占下一次20秒预算。

- **独立WiFi文件**：正式Telnet开关机测试及失败续跑中，每个通道首次产生可保存的WiFi摘要后，自动创建`Auto_power_on_off_tool/test_results/device_N/device_N_wifi_YYYYMMDDHHMMSSffffff.log`，其中`ffffff`为微秒；一次执行的所有轮次使用同一文件，续跑另建`device_N_wifi_微秒时间戳_resume_尝试编号.log`。路径从当前程序目录推导，文件排他创建，时间戳冲突时递增微秒，不覆盖历史文件；仅有被隐藏的过程消息时不创建空文件。
- 主界面、主日志文件和独立WiFi文件使用同一套关键摘要：首次双频SSID/明文密码、实际排队及等待、带尝试编号的连接下发、最终连接/Ping合并结果、重试原因、警告/错误、重要跳过、取消及未知消息。正常成功必须等到本频段最终成功事件后才显示，核验成功或收到Ping回复本身不会提前显示“测试通过”；Ping关闭时最终结果注明“Ping未启用”。独立文件每行带时间戳、级别、通道及轮次，逐条刷新，正常/失败/停止退出时关闭，主界面记录创建/关闭路径；强制终止只保留已刷新的内容。
- 创建、写入、刷新或关闭失败时，主界面显示通道、路径、原因和“设备测试继续”，当前执行尝试的WiFi文件记录停用且只告警一次；原消息仍完整转发用于进度、异常历史和结果判断，主日志继续按摘要保存，新执行/续跑重新尝试。原命令结果文件及历史文件保持原样。

- Telnet正式测试的多个通道同时进入WiFi阶段时，按到达顺序排队，一个通道连续完成已启用的2.4G/5G后才交给下一通道。未指定网卡仍选第一张；排队不计连接尝试、不因等待判为失败，等待会拉长本轮开机时间。仅竞争网卡时显示排队及当前占用，取得使用权后显示实际等待时长；无竞争的即时取得/释放及周期等待不再显示或保存。
- 每个频段最多4次连接（首次＋3次重试），每次约20秒、间隔10秒；某频段最终失败时结束该通道测试并释放网卡，其它通道继续。连接成功仍只表示网卡报告“已连接”，不代表SSID/BSSID或无线Ping核验；多网卡并行不在本轮范围。
- 点击“停止测试”后，等待、连接轮询、重试间隔和WiFi信息读取会响应取消；停止后不再开始下一频段或后续Ping。取消显示“已停止”，保留已完成轮次，不作为WiFi故障或发送WiFi失败通知。驱动调用本身卡住时仍依赖10秒子进程终止兜底。
- WiFi摘要采用`[WiFi] 通道N 第M轮`前缀，每个正常频段通常两条：`2.4G 第1/4次下发连接`和`2.4G 测试通过；SSID=...；Ping发送4/接收3，丢包25%`。Ping开启时合并源IP、目标/实际IP和时延汇总，合一模式注明实际频段。正常信息读取、扫描、认证参数、DNS列表、逐包Ping和临时清理细节不再显示或写入两类日志文件，最终失败、清理异常等重要消息立即保留。DUT配置查询、串口原始日志和其它功能日志保持原样，不改写历史文件。
- 按负责人要求，每个通道每次执行或失败续跑首次成功读取后，在主界面和主日志文件中按原值明文打印一次双频SSID和密码摘要；连接重试及使用缓存的后续轮次不重复打印密码，原始设备回显仍按既有规则省略。每次失败通道续跑重新读取WiFi信息，运行中续跑进入同一队列；原有重试/失败历史保留。

## 检查更新与手动换版

点击主界面工具栏右侧“检查更新”，使用电脑普通网络连接访问公开仓库 `oscarouxue-coder/Power_OnOff_Assistant` 的 GitHub Releases。仅在点击后联网，不在启动时自动检查，也不使用设备 VLAN 的锁源连接。测试电脑需要能访问 GitHub 和其附件下载域名；失败不会改动测试配置或停止正在执行的测试。

- 检查期间显示“正在检查…”并禁止重复点击；版本号按三段数字比较，例如 `v1.1.10` 高于 `V1.1.9`。只检查 GitHub 标记为 Latest 的正式发布，草稿和预发布不会作为更新提供。远端不高于本机时提示“当前已是最新版本”；本机版本未标注、断网、超时、限流、版本/附件不可访问或发布不完整时显示具体失败原因，可重新检查。
- 发现新版本后显示当前版本、最新版本、发布日期、更新说明和便携 ZIP 大小，点击“下载”选择保存位置；默认文件名包含新版本号。“暂不下载”或取消保存不下载文件；已有目标文件须另行确认覆盖。
- 程序显示下载和 SHA256 校验进度，支持取消。使用本次专属 `.part` 临时文件，只有下载大小、SHA256 和 ZIP 格式检查全部通过后才生成最终 ZIP；取消或失败清理本次临时文件，原目标文件保留。窗口关闭会取消所属任务，旧任务不会刷新后来打开的新窗口；网络读取中的取消可能需要等待读取结束或超时。退出程序时先等待更新任务取消与清理完毕。
- 下载成功后可点击“打开所在文件夹”。程序不会自动解压、替换 EXE、启动新版或迁移配置；检查、实际 GET 请求、下载、校验、取消/跳过及失败均写入主执行日志。

手动换版：先结束测试并退出旧程序，备份旧便携目录及其 `Auto_power_on_off_tool/config`；将新 ZIP **完整解压到另一个新目录**。保留新包默认配置副本，再按版本发布说明迁移需要保留的本机 INI 和自定义测试方案，核对网卡/COM、账号、项目和文件路径后启动新版。不要把新包的默认配置覆盖到旧目录；保留旧版与备份，直到新版确认正常。已有旧 EXE 没有此按钮，首次需要手动安装包含此功能的版本。当前发布版为 [V1.2.3（2026-10-17）](https://github.com/oscarouxue-coder/Power_OnOff_Assistant/releases/tag/v1.2.3)，包含开关机开始前版本校验可选化：三项全空跳过、部分填写拦截、全填严格校验，失败通道续跑采用相同规则；并修复Python 3.9源码启动兼容问题，保留网卡名称检查与确认改名。GitHub Releases 每次发布后只保留最新版及其附件，请自行保留需要的旧版本地备份。

## 打包与免安装发布

在 `Cheating_machine_execution_tool` 目录执行标准构建脚本（自动准备独立环境与固定依赖，跨电脑步骤见根 `README.md`）：

```powershell
.\build_line_check_assistant.ps1
```

构建会将 `assets\\icons\\line_check_assistant_network_topology_v1.ico` 写入 EXE 的 Windows 图标资源。一次构建会生成三种输出：

- `dist\LineCheckAssistant.exe`：单文件 EXE，仅适合开发侧留档或手工配套配置。
- `dist\LineCheckAssistant_portable\`：可直接复制的完整免安装目录。
- `dist\LineCheckAssistant_portable.zip`：推荐复制到另一台电脑的压缩包；必须完整解压后再运行，不能只取出 EXE。

另生成 `dist\LineCheckAssistant_portable.zip.sha256.txt`，格式为 `SHA256值 *LineCheckAssistant_portable.zip`，用于程序内下载校验。本地EXE、便携目录、EXE校验文件、版本/构建说明、第三方声明及构建报告继续保留，完整基线、EXE/PYZ、脱敏配置、Tcl/Tk、ZIP CRC和哈希门禁保持。

GitHub 更新发布约定（从2026-11-05确认后的下一次构建/发布开始执行）：先更新 `line_check_assistant/packaging_assets/VERSION_INFO.txt` 的版本与说明，再构建并检查交付物；Release 标签统一为 `v主版本.次版本.修订号`，数字必须与包内版本一致。创建草稿 Release，填写更新说明，**只上传**以下两个**同一次构建**的附件，核对大小/SHA256后发布并标记为 Latest：

- `LineCheckAssistant_portable.zip`
- `LineCheckAssistant_portable.zip.sha256.txt`

发布为Latest后，匿名完整下载并核对两个附件的大小/SHA256、验证源码更新客户端，再删除旧Release及附件；保留Git标签和源码历史。公开发布说明只指引下载完整ZIP及ZIP校验文件，不再单独提供EXE下载。版本说明、第三方声明及EXE校验文件继续包含在ZIP内。V1.2.6及其六份附件、历史发布记录保持原样。

不要把 GitHub 自动生成的源码 ZIP 当作便携包，也不要使用包内仅用于 EXE 的哈希代替 ZIP 哈希；附件缺失时客户端明确提示发布不完整。现有更新客户端已支持只包含这两个附件的发布，哈希不符仍阻止保存为最终ZIP。创建/上传 Release 单独执行，构建脚本不会自动发布或上传。

便携目录包含 EXE、`PORTABLE_README.txt`、`VERSION_INFO.txt`（版本号与本版变更说明）、第三方声明、SHA256 文件和程序所需的 `Auto_power_on_off_tool\config`。构建时只把当前配置当作字段/业务模板，自动清空当前电脑的 OLT/DUT/升级账号密码、OLT/源IP、ONU ID、钉钉和远程控制信息、固件/参数表路径、项目版本，以及网卡、串口和无线网卡绑定；C600业务映射等业务默认模板继续保留。另一台电脑首次运行前必须重新填写网络、测试项、升级/写参和ONU注册配置。

Tkinter资源同时兼容既有PyInstaller 5和当前PyInstaller 6：EXE内部保留`tcl`和`tk`根目录，并增加6所需的`_tcl_data`和`_tk_data`。构建脚本会在生成便携包前检查归档中的`tcl\init.tcl`、`tk\tk.tcl`、`_tcl_data\init.tcl`和`_tk_data\tk.tcl`；缺失时构建直接失败，不能交付。若目标电脑曾解压过旧包，应将新包完整解压到新目录并按上文备份/迁移配置，避免混用旧EXE或覆盖本机配置。

生成的 `.spec` 文件统一保存到 `line_check_assistant\packaging_specs`。

每次重新打包出最新版 EXE 后，不在当前 PC 直接运行 `dist\LineCheckAssistant.exe`或便携目录中的 EXE；只检查构建结果、ZIP清单、配置脱敏和SHA256，并向用户报告输出路径。

打包后程序会从 EXE 所在目录、上级目录中查找 `Auto_power_on_off_tool/config` 文件夹；程控电源协议已内置，不再依赖 `Auto_Power_On_Off_Tool.exe`。

# 开关机测试环境搭建助手

## 当前实现

这是用于配置测试通道、自动上/下电、检查线路和升级样机的桌面工具。

本文后续出现的 `config/...` 均指 `Auto_power_on_off_tool/config/...`；主程序不再使用 `Cheating_machine_execution_tool/config`。

- 读取和实时维护 `Auto_power_on_off_tool/config/network_card_ip.ini` 的通道配置。
- 主界面内容区不重复显示应用名称和功能说明，只在 Windows 标题栏保留“开关机测试环境搭建助手”；“执行日志”标题下不再显示“运行步骤、检查结果和异常信息”提示行，日志框与“清空日志”按钮保持不变；管理员权限状态显示在“常用工具”栏右侧、“刷新串口”左边，权限就绪为绿色，缺少权限为红色警示。刷新串口、刷新网卡按钮顺序保持不变。
- 主界面「程控电源串口」下拉框首项为空值。未选择 COM 时，「通道对应 VLAN」下拉框展示 PC 中所有已识别网卡；自动上/下电、全包升级和全流程执行的确认框会要求操作员先手动重启样机，点击“是”确认已重启后才开始后续步骤，且不会向任何 COM 口下发上下电指令。选择 COM 后，下拉框只展示该电源对应的 8 个 VLAN 网卡：`COM101` 为 `VLAN101`–`VLAN108`，`COM102` 为 `VLAN109`–`VLAN116`，后续 COM 口按每组 8 个 VLAN 顺延；切换 COM 口不会自动改写已保存的通道 VLAN 配置。
- 主界面顶部提供“样机升级”入口，支持“页面升级”和“全包升级”两类流程。
- 样机升级窗口支持自定义项目/型号、输入超级用户凭据、选择升级固件、同步主界面目标 VLAN，并显示实时状态和进度。
- 样机升级窗口会保存上一次关闭时的升级方式、固件传输方式、`Tftp指令` / `Tftp Put` 的执行方式（串行/并行）、恢复出厂选项、超级用户名、密码和固件路径；恢复出厂显示会按真实保存值刷新，开始升级确认框会明确显示“恢复出厂：开启/关闭”；状态保存到本机 `Auto_power_on_off_tool/config/sample_upgrade_settings.ini`，该文件不提交 Git。
- 选择“页面升级”后，点击“开始升级”会按主界面已勾选通道并行执行 UBUS 页面升级；每台样机会先启用通道对应网卡，再使用通道的 PC 静态 IP 作为请求绑定 IP、样机管理 IP 作为目标 IP，自动尝试 HTTP/HTTPS 登录 `/ubus/`，上传固件到 `/cgi-bin/cgi-upload`，调用 `Device.DeviceInfo.X_SDMC_Upgrade()`，查询升级状态并等待设备重启上线。若勾选“恢复出厂”，仅在该样机已确认升级成功、重启且 UBUS 重新登录成功后，才调用 `bbfdm.operate` 的 `Device.FactoryReset()`；主程序执行日志会记录开启、实际下发 `TX UBUS Device.FactoryReset()` 或关闭跳过，恢复出厂调用失败会将该样机页面升级标记为失败。
- 选择“全包升级 + Tftp指令”后，可选择默认“串行”或“并行（最多 8 台）”，并行数由执行窗口右侧 Spinbox 进一步调整到 1–8。并行模式完成即补位，单台失败不会停止其它样机；程控电源 COM 帧仍按通道串行发送，后续 Boot、TFTP、重启等待和最终登录可并行。每台 TFTPy Server 及其后续数据传输 socket 都严格绑定当前 VLAN 的 PC IP；设置网卡 IP 后会最多等待 15 秒，直到 Windows 确认该 IP 可绑定，仍不可绑定才报网卡/重复 IP/驱动错误，不回退到 `0.0.0.0`。所选固件映射为设备固定请求名 `tclinux_allinone`，设备仍执行 `tftp <通道IP>:tclinux_allinone`。
- 选择“全包升级 + Tftp Put”后，程序先对当前通道下电再上电；串口就绪后等待 1 秒并循环发送回车，检测到 `UserName:` 后按 boot 账号 `telecomadmin / nE7jA%5m` 登录。随后仍由 TFTPy Client 从当前通道 IP 上传到固定设备 `192.168.1.1:69`，并绑定该源 IP，避免多张 `.1` 网卡造成错误选路或启动变慢；远端文件名使用所选固件 basename。可选择“串行”或“并行（最多 8 台）”，并行数仍由 Spinbox 调整；并行模式完成即补位，单台失败不会停止其它样机，共享程控电源 COM 由 coordinator 复用同一长连接。
- `Tftp指令` 和 `Tftp Put` 的并行模式可在执行窗口的 Spinbox 调整 1–8 台（默认 2，存于 `sample_upgrade_settings.ini` 的 `parallel_count`）；串行 `Tftp Put` 保持原有首错即停语义。全包升级全程不临时改写 `Auto_power_on_off_tool/config/network_card_ip.ini`；所有串口和 TFTPy Client/Server 都由本程序在 `finally` 中关闭，不查找或关闭外部 CRT/Tftpd 进程。一次并行批次内共享的程控电源 COM 由 `UpgradePowerCycleCoordinator` 持有长连接 `ProgrammablePowerSupply`，仅在首台样机上下电前打开一次，最后一台完成后由 `coordinator.close()` 关闭，避免逐台反复 open/close。
- `Tftp指令` 仍以串口的 `done` 与 `write` 同时出现作为设备处理完成判据；`Tftp Put` 则以 TFTPy 上传成功作为传输完成判据。随后保留 90 秒 boot 观察、`Boot/Bood` 后延迟 1 秒发送一次 `reset`、120 秒等待或重新上电、最终系统五次登录重试，以及恢复出厂“命令→1 秒→回车→8 秒”时序；仅当实际发送恢复出厂命令后，主程序执行日志才显示 `TX firstboot -y;reboot`。
- `Tftp指令` 在样机串口同时出现 `ARP Retry count exceeded` 与 `U-Boot>` 提示符时会自动重发同一 `tftp` 命令，最多 3 次、每次间隔 1 秒；单次等待窗口 5 分钟，由按秒轮询替代阻塞 `wait_for_all`，避免已知快速失败场景消耗完整超时。每次重试和最终成功/失败都会写入主程序执行日志，例如“检测到 ARP Retry count exceeded...，剩余 2 次自动重试”、“自动重试 TFTP 命令：第 2/3 次发送...”、“TFTP 命令在第 2 次尝试时检测到完成标记”或“TFTP 命令已重试 3 次仍未成功...”。仅 `ARP Retry count exceeded` 但未回到 `U-Boot>`（样机仍卡在 Loading）时按普通超时处理，不重试。
- Boot 登录会在上电完成后先等待 1 秒再发送首个回车；仅当完整 `UserName:` / `User Name:` 在 1 秒稳定窗口内未夹带旧 `Password:` / `Passvord:` 时才提交用户名。用户名回车后重新从串口新数据中等待完整密码提示符，避免首轮上电过渡日志或旧缓存导致账号、密码错位。`Tftp Put` 的 UserName 后直连 boot 登录会在写用户名前记录密码游标、在写密码前记录 shell 游标，确保同批回显里的 `Password:` 或 `ECNT>` 不会漏检。
- 主界面“串口日志记录”已改为内置多通道终端：按 VLAN/COM 分页实时显示、开始/停止、清屏、手动命令发送和日志保存。“打开全部”会依次启用窗口当前全部 VLAN/COM Tab。每个 Tab 的命令输入框按下 `Enter` 即等价于点击「发送」按钮（输入框非空则发送文本并清空，等价「发送」；输入框为空时发送纯回车，等价「回车」）；自动升级占用某通道时仍显示输出，但手动发送（含按 Enter）被锁定；高频串口输出以最多约每 33ms 一轮的节奏渲染，只有当前 Tab 实时重绘，其他 Tab 切换后显示最新缓冲；每个 Tab 的屏幕只保留最近 5000 行，避免长时间高频输出导致 Tk 无响应。屏幕缓冲超过 64KiB 时会提示已合并字符，但原始日志始终完整写入磁盘；日志文件名按打开监控当日保存为 `vlan名_COM口_YYYYMMDD.log`，例如 `vlan112_COM12_20260808.log`，手动打开、“打开全部”和全流程预启动规则一致；文件内每个落盘行都以 `YYYY-MM-DD_HH:MM:SS` 开头并保留 RX/TX/STATE/ERROR 方向，例如 `2026-08-08_19:12:10 RX 打印内容`，半行分包会先拼接，不会重复添加时间戳；全包升级自动打开的终端会在本批串口释放并写入关闭状态后自动关闭，手动打开的终端不会被自动关闭；`reboot`、`reset`、`firstboot`、`tftp`、`upgrade` 类手动命令需要二次确认；默认日志目录或本机终端状态文件不可写时会弹出明确错误提示。
- 凡主程序需要准备 VLAN 网卡的流程，都会先查询目标网卡的启用状态和现有 IPv4/前缀：已经启用且地址完全匹配时直接复用，不再重复启用或设置静态 IP；仅有一项不满足时只修复该项，无法读取状态时按原流程完整准备。该规则覆盖线路 Ping、页面升级、全包升级 TFTP 网卡、写参用户/工厂模式切网、测试项执行、DUT 配置和“查询现有 WAN”；原来具有源 IP 可绑定确认的流程仍会继续确认，后续 Ping、UBUS/Telnet 登录或 TFTP 成功判据不变。
- 主界面“串口日志”右侧提供“DUT配置”入口。窗口包含“Telnet配置”“WAN配置”“2.4G WiFi配置”“5G WiFi配置”“语音配置”“TR069配置”六个 Tab，均使用主界面已勾选通道作为目标；UBUS 账号、密码和并行数与 Telnet 页共享，账号密码与“写样机参数”的首次登录凭据一致并明文显示。每台完成上述按需网络准备后仍等待源 IP 可绑定，再从该源 IP 登录样机 UBUS；支持 1–8 台并行（默认1）、单台失败隔离和停止后不再启动后续 DUT，同一时间只运行一个 DUT 配置批次。
- “Telnet配置”点击“开启 Telnet”并确认后，通过 UBUS 开启 `Device.Firewall.<X_SDMC_>Security.AccessCtrl` 下的 LAN-telnet 规则，再从对应 VLAN 源 IP 验证 TCP 23 端口；只有 UBUS 和端口验证均成功才判定成功。点击“查询当前Telnet”只读取AccessCtrl总开关和LAN Telnet规则，并锁源探测TCP 23，不执行set/add；“当前状态”区域逐台显示总开关、规则、SourceInterface和端口可连接状态。
- “WAN配置”支持新增、修改和删除指定 WAN，并按当前选择实时只展示有效字段：新增隐藏现有连接索引，修改显示索引和配置项，删除只保留现有连接选择。修改/删除时，“现有连接名/索引”是只读下拉框；点击旁边“查询现有 WAN”后，程序会对主界面当前已勾选的每台 DUT 执行网络准备和锁源 UBUS 登录，通过只读 `bbfdm.get Device.IP.Interface.` 获取现有连接。单台时显示该 DUT 的连接；多台批量时只显示所有目标名称完全一致的共同 WAN，不按相同数字索引合并不同业务；任一 DUT 查询失败或停止都不会生成下拉列表。目标 DUT 变化或执行过 WAN 配置后会清空旧列表并要求重新查询。桥接仅展示业务类型、业务 VLAN、优先级和端口绑定，业务类型限定为IPTV/INTERNET/OTHER；路由才展示接入方式、协议、MTU、NAT和地址参数。端口绑定使用LAN1–LAN8原生多选框，分别对应位掩码1、2、4、8、16、32、64、128，多选自动按位合并；新建桥接且未选择端口时默认勾选LAN1，查询现有WAN时会把例如 `PortBind=8` 反向显示为LAN4。修改现有WAN时会保留设备返回的WiFi等非LAN绑定，切回新增时不继承这些不可见旧位。当业务类型为IPTV时，路由和桥接都会额外显示可选“组播 VLAN ID”；留空表示不单独配置，填写时必须在1–4094范围内并以 `MulticastVLANID` 下发，切换到非IPTV后该字段隐藏且旧值不会误下发。IPoE隐藏PPPoE账号密码、切换时自动回填默认MTU 1500；PPPoE显示账号密码、自动回填默认MTU 1492，并只允许动态地址。IPv4只显示IPv4地址方式，IPv6只显示IPv6地址方式，IPv4+IPv6双栈同时显示两者；DHCP/SLAAC/DHCPv6隐藏对应静态地址项，选择静态才显示地址、网关、DNS和掩码/前缀。IPoE双栈仅允许DHCP+SLAAC、DHCP+DHCPv6、静态IPv4+静态IPv6；PPPoE双栈仅允许动态IPv4+SLAAC或动态IPv4+DHCPv6。界面下方会显示当前组合说明，业务预检也会再次拒绝非法组合；MTU自动值仍可按设备需要在576–2000范围内调整。程序不提供删除全部 WAN，删除前会再次提示不可自动恢复。
- “查询现有 WAN”现会一次只读获取 IP Interface、Ethernet/VLAN、PPP、Bridge、DHCP、DNS 和 NAT 关联信息，并把同一批结果逐台显示在WAN页“当前状态”区域，不会为状态展示重复查询设备。查询成功后默认选中第一条，切换下拉项会把当前连接的业务类型、业务 VLAN、组播 VLAN、优先级、模式、端口绑定、接入方式、IP协议、地址方式、MTU、NAT，以及设备可返回的静态地址/DNS/PPPoE凭据同步到表单；例如 `3_INTERNET_R_VID_172` 会显示 `INTERNET` 和 VLAN `172`，不会沿用新增页原来的 TR069/VLAN默认值。多台批量时，只有同名 WAN 的完整参数在所有目标上也一致才自动回填；参数不一致仍保留共同名称供删除选择，但修改前会提示人工核对，避免拿任意一台覆盖整批。
- 每次 DUT UBUS 查询或配置结束时，程序会调用 `Device.X_SDMC_Login.logout()` 释放设备端session，再关闭本机HTTP连接；WAN查询日志会显示注销TX和结果，避免连续第二次查询因上一轮session残留而被设备拒绝。
- “2.4G WiFi配置”和“5G WiFi配置”分别配置指定SSID索引（1–8）的WiFi名称、密码、信道、信道带宽、启用/隐藏、认证/加密模式、WiFi协议类型、发射功率、最大接入数和WMM，并共享一个“启用双频合一”全局选项。2.4G信道支持auto或1–13，带宽支持20/40MHz、20MHz、40MHz，协议支持b、b/g、b/g/n、b/g/n/ax；5G提供常用36–165信道、20/40/80/160MHz及a、a/n、a/n/ac、a/n/ac/ax。发射功率下拉提供20/40/60/80/100%，最大接入数允许0–32。认证/加密模式支持开放、WPA2-Personal、WPA3-Personal、WPA3-Personal-Transition和WPA/WPA2混合；开放网络会隐藏密码并且不下发遗留密码，加密网络密码必须为8–63字符或64位十六进制密钥。
- 两个WiFi页点击“查询当前…”后，会先读取 `Device.WiFi.X_SDMC_Mapping_2G/5G`，再读取Radio、AccessPoint和SSID节点的 `X_SDMC_Instance`，把页面SSID索引解析成设备真实对象路径；查询只执行`bbfdm.get`，逐台显示完整当前状态，全部目标成功且参数完全一致时才同步表单。执行配置使用同一真实路径并在下发后回读校验。开启双频合一时，当前SSID的名称、启用/隐藏、认证密码、最大接入数和WMM同步到2.4G与5G；信道、带宽、协议和功率仍只修改当前Tab对应Radio，避免把两个频段的射频参数错误设成相同值。
- “语音配置”批量设置SIP线路、账号开关、显示名、认证账号密码、代理/出站代理/注册服务器、端口、DTMF、注册有效期、SIP模式、5项编码和DigitMap；SIP模式在原有 `SIP/UDP/TCP/TLS` 基础上增加ONT支持的 `IMSSIP`，下拉顺序为 `SIP/IMSSIP/UDP/TCP/TLS`，所选值原样写入 `X_SDMC_SIPMode`，未知值会在下发前被拒绝；下发后回读SIP路径，账号启用时会先检查必填项。点击“查询当前语音”会按当前线路索引只读获取上述完整状态并逐台显示。
- “TR069配置”批量设置ACS URL与账号密码、周期Inform、HTTP连接请求账号和证书开关，并回读`Device.ManagementServer.`；勾选“配置后手动 Inform”时，会继续触发一次Inform并等待最终结果，等待期间可点击“停止”。点击“查询当前TR069”会只读获取ManagementServer当前状态；“配置后手动 Inform”是操作动作，不会因查询结果自动勾选。
- 语音/TR069/WiFi状态查询会复用当前目标、网卡状态预检、锁源IP、并行数、停止和失败隔离，并在每次登录后注销设备session。Tab内“当前状态”区域逐台展示结果；单台或多台状态完全一致时同步回填当前配置表单，多台不一致或存在失败时不会拿任意一台覆盖整批表单。目标变化或执行对应配置后会提示重新查询；主日志保留每个实际 `bbfdm.get` 路径、完整返回状态和注销结果，查询不会执行配置 `bbfdm.set`。
- 六个 DUT Tab 都有“当前状态”区域；目标变化或执行对应配置后旧状态会失效并提示重新查询。主执行日志记录关键阶段、明文 `session.login`、实际 `bbfdm get/set/add/operate` 路径与参数、成功、跳过、失败及批次汇总。WAN的LAN1–LAN8端口绑定和“启用 NAT”、两个WiFi页各四个选项、语音“启用 SIP 账号”以及TR069页的四个选择框均使用原生勾选框，选中显示“✓”、未选为空框；默认值和执行语义不变。六页当前均为代码与单元测试通过，仍需Windows桌面和真实样机验收。

- 主界面顶部提供“ONU注册”入口，窗口默认尺寸为 `896x580`，支持输入 OLT IP（首次默认 `172.18.18.151`，后续恢复上一次关闭时保存的值）、用户名和密码，密码框支持小眼睛切换明文/密文显示；点击 Telnet 连通性测试并确认后，会先检查 OLT Telnet 23 端口，连通后使用用户填写的用户名和密码登录 OLT，并下发 `configure terminal` 进入全局模式；OLT IP 右侧只显示 Telnet 连通性结果，登录和全局模式状态显示在查询入口下方，查询/注册状态栏支持长结果自动换行；点击“开始查询”会登录 OLT 并执行 `show gpon onu uncfg`，以复选框列表显示所有 PON 口下未注册 ONU 的接口、SN 和状态，并支持全选/取消全选；勾选 ONU 后点击“开始注册”会二次确认并优先按已确认的 SD-41 模板下发注册配置、业务 VLAN 和 `pon-onu-mng` 服务配置，如新增业务配置命令报错，会自动查询并删除已注册但未在线的 ONU，优先删除和新 ONU 同 PON 口的不在线 ONU，再删除其它 PON 口不在线 ONU，删除后重新下发新 ONU 注册配置；注册完成后会询问是否保存 OLT 最新配置，用户确认后先退出到 `ZXAN#` 执行模式再执行 `write` 写入启动配置；ONU 注册输入框会保存到本机 `config/onu_registration.ini`，该文件不提交 Git；后续扩展结果导出流程。
- 为每个通道选择实际接入的 Windows 网卡名称。
- 网卡列表优先读取 `Get-NetAdapter -IncludeHidden`，可显示禁用、断开和隐藏网卡；界面显示状态，例如 `[Connected]`、`[Disconnected]`。
- 保存每个通道的 PC 静态 IP、样机管理 IP、子网掩码、启用状态。
- 自动上电和全包升级均由主程序直接控制程控电源，不启动 `Auto_Power_On_Off_Tool.exe` 或其 GUI。
- 程控电源使用所选 COM 口的 `19200 8N1` 串口参数；“自动上/下电”二级弹窗提供“上电/下电”下拉框，默认“上电”。

当前版本使用 Python 标准库 `tkinter` 实现桌面界面，不需要安装 PySide6；依赖见 `requirements.txt`（`pyserial==3.5`、`tftpy==0.8.7`、`requests>=2.31,<3`、`openpyxl`、`xlrd`）。

## 运行方式

首次运行前，在 `Cheating_machine_execution_tool` 目录安装依赖：

```powershell
python -m pip install -r .\requirements.txt
```

随后启动主程序：

```powershell
python .\run_line_check_assistant.py
```

修改网卡静态 IP 需要管理员权限。正式检查线路时，请用管理员权限打开 PowerShell 或打包后的 EXE。

### VS Code 运行

1. 用 VS Code 打开 `F:\Aouxue\Power_OnOff_Assistant` 工作区，并选择解释器 `.venv_serial_upgrade\Scripts\python.exe`。
2. 打开 `Cheating_machine_execution_tool\run_line_check_assistant.py`。
3. 在“运行和调试”中选择 `LineCheckAssistant` 后按 `F5`，或使用右上角“运行 Python 文件”。

`LineCheckAssistant` 会以 `Cheating_machine_execution_tool` 为工作目录启动，确保可正确导入主程序模块并读取项目配置。

## 验收步骤

1. 启动软件后，确认界面能列出 `network_card_ip.ini` 中已有的 `channel_1`、`channel_2` 等通道。
2. 点击“刷新网卡”，确认下拉框里能看到当前 PC 的网卡名称，例如 `a虚拟网卡2口`。
3. 选择一个通道，填写：
   - 样机接入网卡
   - PC 静态 IP
   - 样机管理 IP
   - 子网掩码
   - 是否启用
4. 勾选或取消勾选通道，确认 `Auto_power_on_off_tool/config/network_card_ip.ini` 立即更新，并且只保留已勾选通道的 `[channel_x]` 配置节。
5. 人工接好线路后，点击“自动上/下电”，选择程控电源 COM 口和操作类型（默认“上电”），并确认影响通道。
   - 选择“上电”时，软件会按勾选顺序发送开启帧，相邻帧间隔 1 秒，且不会先关闭任何通道。
   - 选择“下电”时，软件只会向勾选通道发送关闭帧，相邻帧间隔 1 秒，不会发送全部断电帧。
   - 确认后主程序直接发送程控电源串口帧，不会启动旧 EXE 或点击外部 GUI；最后一条帧后不额外等待。
6. 回到新软件，点击“检查当前通道”或“已上电，开始检查全部启用通道”。
7. 观察日志：
   - 通过：显示 `[通过] channel_x ping xxx 成功`。
   - 失败：显示通道、网卡、PC IP、样机 IP，并提示检查上电、网线、接错口、IP 配置。
8. 打开“样机升级”，选择“页面升级”，确认已勾选通道都有 PC 静态 IP 和样机管理 IP，选择固件后点击“开始升级”。
   - 软件会二次确认将通过 UBUS 上传固件并触发升级。
   - 软件会先启用目标通道对应网卡；如果启用失败，会在日志和失败弹窗中提示。
   - 日志会显示每台样机的 HTTP/HTTPS 登录、上传、升级状态和重启上线结果。
9. 打开“写样机参数”，先使用“生成批量参数表...”为已勾选 VLAN 生成 Excel 表，或选择已有 `.xlsx` / `.xlsm` / `.xls` / `.csv` 参数表；确认预检清单中的 VLAN、COM、MAC 一一对应。
   - 点击“写入参数”后，确认框会提示清空参数、工厂模式和两次重启；仅在确认后才实际下发命令。
   - 现场先以 2 台独立 VLAN / COM 样机验证，确认每台写入后读回校验成功、密码明文便于核对，并确认设备已完成退出工厂模式后的重启。
10. 打开“测试项配置”，可加载并编辑 `Auto_power_on_off_tool/config/test_project_config.ini`，并在“开关机运行参数”页编辑 `config.ini [ui_defaults]`，详见下方「测试项配置窗口」。

## 测试项配置窗口

主界面工具栏「测试项配置」按钮打开的窗口是一个**编辑入口**，不接主程序执行流程（Q1=A 决策）：

- **五 Tab 结构**：
  - **Telnet** —— 编辑 `[telnet]` 段的 12 个字段。界面只显示中文含义：设备默认已开启 Telnet、Telnet 开启地址、登录用户名、登录密码（明文）、Telnet 端口、连接超时时间、用户名提示符、密码提示符、登录成功提示符、是否需要输入密码、免用户名密码登录、仅执行上下电；INI 原始键名和保存格式保持不变。密码输入框右侧小眼睛可在 `*` 密文 / 明文之间切换。
  - **测试项** —— 编辑 `[order]` 段：顶部全局 Spinbox「指令重试间隔（秒）」默认 60，唯一保存到 `config.ini [other_config] command_fail_retry_interval_time`；`test_project_config.ini [order]` 只保存测试命令。中间滚动列表每条命令一行（命令 + 重试次数 Spinbox 1-99 + 删除按钮），不同命令组之间保留加宽的纵向留白，展开后是「期望」子表单（否定勾选 + 动态段列表 + 增加/删除段按钮）；底部提供「+ 新增测试项」和「恢复默认」。默认模板固定为 `Auto_power_on_off_tool/config/test_project_config.default.ini`；点击「恢复默认」并确认后会先清除当前页面全部测试命令，再恢复全部默认命令，不改变当前指令重试间隔、Telnet、WiFi、项目信息，恢复到界面后需再点击窗口底部「保存」才写入正式配置。
  - **WiFi** —— 完整映射旧“WIFI 连接参数”窗口：连接 WiFi 主控、2.4G、5G、ONU 方案类型、认证方式、加密算法、指定无线网卡和无线网卡名称；界面只显示中文含义，不显示 INI 原始键名。产品方案候选为 openwrt / bcm / mtk（保存时统一小写），认证候选与旧窗口一致，加密候选为 AES / TKIP / TKIP+AES；点击“刷新无线网卡”通过 pywifi 读取当前可用无线接口并记录成功、无网卡或失败日志。
  - **项目信息** —— `[project_info]` 段：4 个字符串字段（项目名称 / 软件版本 / 内部软件版本 / ONU 软件编译时间），全部按自由文本存取；**仅做编辑器，不被主程序消费**，用于操作员在执行测试时肉眼对照样机输出的版本 / 编译时间。
- **开关机运行参数** —— 加载 `Auto_power_on_off_tool/config/config.ini [ui_defaults]`，页面只展示 `startup_time`、`interval_time`、`number_of_tests`、`wait_command_done` 四项。界面左侧使用黑色中文名称（设备启动等待时间、每轮断电等待时间、测试循环次数、命令完成后等待时间），不显示原始键名，也没有右侧灰色说明列。`communication_method`、`baud_rate`、`selected_profile` 和 `telnet_enable` 不展示，保存时保留前三项原值；`telnet_enable` 由 Telnet 页 `telnet_default_on` 按 `1 → 0`、`0 → 1` 反向计算并自动写入。
- **底部按钮**：「重新加载」（从磁盘重读 ini，丢弃未保存改动）/「保存」（二次确认后写回 ini）/「关闭」。
- **Dirty 跟踪**：任意控件改动标记 dirty，「重新加载」和「关闭」在 dirty 时弹「放弃修改？」二次确认；「保存」成功后 dirty 清零。
- **窗口显示**：打开时先在隐藏状态完成五个 Tab 和测试项命令控件布局，当前按钮回调结束后的下一轮事件循环再显示窗口，并主动处理一次完整绘制队列；无需移动鼠标触发界面绘制。
- **保存行为**：保存会把 Telnet、测试命令、WiFi 和项目信息写入 `test_project_config.ini`，把指令重试间隔仅写入 `config.ini [other_config]`，并更新 `config.ini [ui_defaults]`；WiFi 的 8 项键为 `enable / test_2g_enable / test_5g_enable / product_solution / auth_mode / cipher / choose_wireless_card / wireless_card_name`。测试项 ini 的原注释会丢失，`config.ini` 的其它配置段、未知键和注释保持不变。测试项 ini 不存在时打开窗口会提示「将以空白表单打开」，保存后自动创建。
- **「期望」拼接规则**：每段独立勾选「否定」→ 该段前加 `!`；多段 → 用 `&&` 拼接；空段不写入拼接结果。例如第二段的 `00:00:00:00:00:00` 勾否定、`UP BROADCAST` 不勾，保存为 `!00:00:00:00:00:00&&UP BROADCAST`（前者应**不**出现，后者应**出现**）。
- **「重试间隔」语义**：本字段名为 `command_fail_retry_interval_time`，唯一保存到 `config.ini [other_config]`，不会写入 `test_project_config.ini [order]`；与老工具 `wait_time_N`（sleep 秒数，**语义不同**）不共用。它是全流程测试项命令失败后的重试等待时间，测试项页面和全流程执行都从这一唯一位置加载。
- **主执行日志**：保存成功 / 失败都会写一条主程序执行日志；成功日志同时记录测试项命令数和更新的旧工具参数数量。
- **执行边界**：本窗口不会因编辑或保存立即连接 WiFi、执行 telnet、上下电或运行测试命令；“测试项配置（[order] 执行）”已从全流程子任务中移除。但保存的 WiFi 参数会在以后勾选全流程子任务7“执行开关机测试”时由无 GUI 旧业务读取并生效。

### 旧工具顶部参数配置

旧 `Auto_power_on_off_tool/Auto_Power_On_Off_Tool.py` 顶部的通信方式、波特率、默认方案及运行时间参数从 `Auto_power_on_off_tool/config/config.ini [ui_defaults]` 读取。旧工具 `Telnet Enable` 与新工具 `test_project_config.ini [telnet] telnet_default_on` 使用反向关系：`telnet_default_on=1` 表示设备默认已开启，旧工具 `telnet_enable=0`；`telnet_default_on=0` 时旧工具 `telnet_enable=1`。旧工具启动时直接按此关系加载，新工具保存测试项配置时同时更新 `config.ini [ui_defaults] telnet_enable` 镜像值并保留其它内容。`command_fail_retry_interval_time` 只保存在 `config.ini [other_config]`。旧工具的 `serial_num` 与新工具“程控电源 COM”严格共用同一值，固定读取 `network_card_ip.ini [power_supply] serial_port`；新工具 COM 为空时旧工具同样为空，不回退、不自动选择其它 COM。“电源控制”的 channel 1～16 复选框也严格同步同一文件中的新工具选中配置：存在且 `enabled=1` 的 `channel_N` 才勾选，其余通道全部取消。全流程子任务7还会把当前测试方案 `[connect_wifi]` 的 8 项 WiFi 参数映射到旧业务 `OnuCongfig`；主控关闭时跳过 WiFi，指定网卡为空或运行电脑不存在该网卡时明确失败且不静默改用其它网卡。程控电源直连、升级和其它主程序路径仍不调用旧 GUI 或旧 EXE。

## 全流程执行窗口（2026-07-20）

主界面「检查并执行测试」按钮按下后，弹出本窗口（替代旧实现的「直接跑 ping 检查」）。完成二次确认并成功启动后台线程后，全流程配置窗口会自动隐藏；运行期间再次点击主入口只提示查看主界面状态，不会重新弹出配置窗口，流程结束后再次点击才重新显示。主界面同一卡片会持续显示“未运行 / 正在执行 / 正在停止 / 已完成 / 已停止 / 执行失败”，并提供“停止测试”按钮；该停止按钮已从全流程弹窗移到主界面，运行时启用，其余状态禁用。完成和失败状态通过主程序 UI 任务队列回到 Tk 主线程，不依赖已隐藏窗口的 `after()`；若检测到后台线程已经结束但主界面仍残留运行态，主入口或停止按钮会自动恢复为“未运行”，不会交替提示“仍在执行”和“没有正在执行”。完成、部分失败和异常提示均以可见主界面为父窗口。操作员可勾选 7 个子任务；界面保留 1→7 行布局，但若勾选“串口日志”，实际执行时会在全流程开始先预启动终端，其余勾选子任务仍按 **1→7 相对顺序** 串行执行。任一致命失败会停止后续子任务，串口日志失败不阻塞后续。“测试项配置（[order] 执行）”已从全流程列表和调度中移除，主界面的“测试项配置”编辑器继续保留。

只要勾选“1. 自动上/下电”且它后面还有任意已勾选子任务，子任务1成功完成后会固定等待 **120 秒**，再启动下一个子任务；后续不必是子任务2。只勾选子任务1、子任务1已经是最后一项或子任务1执行失败时不会等待。等待期间可点击主界面“停止测试”立即中断并跳过后续子任务，主执行日志会记录等待开始、完成或停止结果。

- **7 个子任务**（每行勾选框 + 必填项状态 + 「去配置」按钮）：窗口首次打开时全部不勾选，由操作员按本次需要明确选择；选中时白底黑边小方框内显示“✓”，未选时保持空框；点击小方框或任务标题都可切换。
  1. **自动上/下电**（默认不勾）—— 必填项：程控电源 COM、上/下电选项和至少一个已勾选通道。
  2. **环境线路检查**（默认不勾）—— 逐通道启用网卡、设置 PC 静态 IP 并 Ping 样机管理 IP；这是第 2 个致命步骤，失败会停止后续子任务；必填项为至少一个启用通道及每通道 VLAN、网卡、PC IP、样机 IP。
  3. **样机升级**（默认不勾）—— 必填项：升级方式、固件及对应凭据或传输方式；全包升级由主程序当前入口统一接收，再按当前选择分流到独立的 `Tftp指令` 或 `Tftp Put` 链路。
  4. **写样机参数**（默认不勾）—— 必填项：参数表路径和首次登录账号、密码。
  5. **ONU 注册**（默认不勾）—— 必填项：OLT IP、用户名、密码。
  6. **串口日志（全流程期间持续记录）**（默认不勾）—— 界面仍保留第 6 行；勾选后会在全流程开始时先显示多 VLAN 终端，再自动执行窗口中的“打开全部”，确认当前全部串口已启用后才进入上下电、环境检查、升级和写参，以覆盖后续全部串口输出；这是非致命子任务。
  7. **执行开关机测试**（默认不勾）—— 不启动旧工具 GUI 或 EXE，在独立无 GUI 子进程复用旧 Start All 的 Telnet/SSH、程控电源和通道业务。参数来自当前 `config.ini [ui_defaults]`、当前测试方案和 `network_card_ip.ini`；只启动新工具当前勾选通道。初始化会先下发全通道断电帧，因此启动确认框会明确提示危险操作。转入新工具的旧日志采用精简模式：保留每轮开始、关键登录/连接/Ping/WiFi/重试结果、全部警告/错误、实际电源帧和最终结论，过滤配置路径、原始命令回显等底层 INFO；2 秒内同级同文重复日志只显示一次，连续出现的同级同文旧日志即使超过 2 秒也只保留第一条，出现其它可见日志或执行阶段后下一条相同结果可再次显示；`IP登录成功` 在本次开关机测试中按 IP 各显示一次，例如 `113/112/113/112` 最终只保留113和112各一条，重新启动测试后重新计数；旧英文网卡 Ping 成功行会根据当前测试方案实际目标转换为 `Ping 成功：源网卡 192.168.1.112 → 目标样机 192.168.1.1`；其中 `通道 【N】 开始第M次测试` 正文使用绿色字体。旧工具结果文件中形如 `2026-08-08 15:37:41.904434: 通道9下挂的设备在第1次测试时正常` 的每轮正常结论也会实时显示为新工具的 `[旧工具Logs][INFO]`，原结果文件照常完整保存。该项会等待所有通道执行结束，任一通道失败会停止全流程。
- **开关机轮次进度**：主界面“环境检查与开关机测试”卡片的进度条在全流程启动时重置；子任务7开始后，最大值读取本次 `config.ini [ui_defaults] number_of_tests`，右侧显示“开关机测试进度：当前轮次/总轮次”。普通测试按每轮正常结论推进；仅上下电模式不写正常结论时，以进入第 N 轮确认前 N-1 轮已经完成，并在最终成功时补齐满格。多通道并行时按所有已选通道均已完成的最小轮次推进，避免快通道使总体进度提前到 100%。停止或失败时保留最后已完成轮次。
- **必填项状态展示**：每行右侧实时显示当前 store / main UI 状态（绿色就绪 / 红色「缺: 字段1, 字段2」），打开窗口时自动计算，勾选 / 切换 Checkbutton 时也会刷新；底部「刷新状态」可在去配置后立即手动重算，不执行任何设备操作。
- **升级 / ONU 配置刷新**：从「去配置」窗口填写或修改升级超级用户凭据、固件路径、OLT 凭据后，管道状态会直接读取当前输入；关闭配置窗口并回到全流程窗口时自动刷新，不必等待本机配置文件延迟保存。
- **异步任务顺序**：子任务 3「样机升级」、子任务 4「写样机参数」均在 Tk 主线程显示确认框并启动各自后台 worker；管道会等待当前 worker 的完成结果（成功或失败）后才开始下一子任务。写参开始前会重新打开有效的写参窗口，因此不会引用已关闭窗口而报 `bad window path name`。
- **串口日志预启动**：全流程子任务编排在后台线程运行，但“显示串口终端 + 打开当前全部串口”会作为一个动作投回 Tk 主线程；全部打开成功后才开始其它子任务，避免只显示窗口却仍处于“COM 未打开”状态。任一串口打开失败时，主执行日志记录失败 VLAN，串口日志任务按既有非致命规则继续后续子任务。
- **自动上/下电去配置**：点击后弹出程控电源 COM 与上电/下电选择框；确认只保存全流程配置并刷新本行状态，不会下发任何程控电源指令。
- **全流程自动上电**：选择「上电」时只向已勾选通道发送开启帧，不会先发送关闭帧；选择「下电」时才发送关闭帧。
- **二次确认**：点击「开始执行」时若任一勾选子任务就绪 = False，弹「必填项未就绪」警告询问是否继续；继续后弹「确认全流程执行」显示**实际执行顺序**，已勾选的串口日志位于首位并标注“全流程开始时提前启动”；若子任务1后还有任务，确认框同时提示“子任务1完成后等待120秒”；若勾选子任务7，确认框同时提示旧 Start All 初始化会先全通道断电。操作员点「是」后启动后台线程。
- **失败处理**：任一「致命」子任务抛异常 → 整个全流程停止，弹「全流程执行失败」错误框；串口日志失败只记结果不阻塞。
- **状态徽标与「停止测试」按钮**：主界面“环境检查与开关机测试”卡片以 11 号粗体彩色徽标显示当前状态，“正在执行”为深绿色底白字，其它状态使用灰、警告黄、成功绿或危险红；停止按钮在全流程运行期间启用，点击后状态先变为“正在停止”，编排器在当前子任务安全退出后终止后续子任务。执行旧 Start All 时停止事件会直接传入旧业务；全流程弹窗不再重复显示停止按钮。
- **子任务底层不重写**：窗口复用主程序既有业务入口；编排器只负责调度、状态展示和失败传播。

新增持久化字段（`Auto_power_on_off_tool/config/sample_upgrade_settings.ini`）：

- `power_operation`（默认 `up`，非法值回退 `up`）—— 全流程执行「自动上/下电」子任务的上/下电选项。
- `parameter_table_path`（默认空串）—— 全流程执行「写样机参数」子任务的参数表文件路径（`.xlsx`/`.xls`/`.csv`）。

## 打包建议

安装 PyInstaller 后，可在 `开关机执行工具` 目录执行：

```powershell
.\build_line_check_assistant.ps1
```

生成的 EXE 位于 `dist\LineCheckAssistant.exe`。
生成的 `.spec` 文件统一保存到 `line_check_assistant\packaging_specs`。

每次重新打包出最新版 EXE 后，不在当前 PC 直接运行 `dist\LineCheckAssistant.exe`；只确认打包成功，并向用户报告输出路径。

打包后程序会从 EXE 所在目录、上级目录中查找 `Auto_power_on_off_tool/config` 文件夹；程控电源协议已内置，不再依赖 `Auto_Power_On_Off_Tool.exe`。

### 远程管理（2026-11-15，源码版，待现场复验）

在常用工具打开“AI诊断”，进入“远程管理”，再选择“钉钉”或“飞书”子页签。两套接入配置直接显示在页内；测试项配置第六页现名为“消息推送”，管理Webhook推送及试发。

两套表单分别使用“保存应用配置”，不由测试项配置底部的“保存”代存。切换页签或隐藏AI助手保留未保存输入，重新打开继续编辑；首次保存后仍需按页面提示重启程序。关闭AI助手会取消尚未完成的群绑定，已启用的远程AI、消息通知、聊天及监控继续运行。切换页签只暂停界面状态刷新，不取消绑定；回到远程管理恢复显示。配置读取失败仅影响对应平台，检查配置后重新进入远程管理可重试。

### 钉钉项目机器人排障（2026-11-14，源码版，待现场复验）

每个挂测项目目录可绑定一个独立的钉钉应用机器人，同时用于测试通知和文字AI排障。同一台电脑运行多个项目时，各项目分别创建应用并使用不同凭据；同群@哪个项目机器人，就由哪个项目实例处理。旧的自定义Webhook机器人只有推送能力，不能接收@消息，不能用其加签密钥代替应用Client Secret。需要能创建/发布应用机器人，并将它加入可使用的企业内部群。

配置步骤：

1. 在[钉钉开发者后台](https://open-dev.dingtalk.com/)创建企业内部应用，添加机器人能力，选择Stream消息接收模式，发布应用与机器人并设置可用范围；将机器人加入目标群。获取Client ID（AppKey）、Client Secret（AppSecret）、Robot Code，以及该应用机器人入群后的群Webhook和加签密钥（如有）。每个项目分别配置，不能让多个实例共用同一应用凭据。
2. 打开“AI诊断助手 → 远程管理 → 钉钉”，填写应用凭据与新应用机器人的群Webhook，点击“保存应用配置”。这会同时将现有测试通知的Webhook/加签密钥切到新机器人，保留通知开关和@所有人；已打开的“测试项配置 → 消息推送”页同步新地址和密钥，保留其它未保存输入及原有未保存提醒。保存后重启程序，使当前项目改用独立AI数据。
3. 重启后重新进入钉钉子页签，点击“开始绑定群”。五分钟内在目标群发送 `@项目机器人 绑定 页面显示的绑定码`，回到本地核对群名称与群ID，再点击“确认绑定”。绑定过程不会调用模型或操作设备。
4. 勾选“启用指定群 AI 排障”，确认该群所有成员可以调用当前项目排障工具且回复发送到该群。后台连接不需要打开AI窗口，也不需要公网IP或端口映射。可使用“测试项配置 → 消息推送”的“发送测试消息”检查测试通知；AI收发需另发排障问题核对。

首条问题可以发送 `@项目机器人 通道3 检查刚才断网的原因`，后续发送 `@项目机器人 继续检查`。也可直接描述问题，通过对话确定通道或“本机电脑”；普通问答无需设备目标，设备目标不明时追问。设备范围为当前项目已勾选且有效的通道；目标配置、模型或挂测批次变化后自动选择匹配会话或新建，旧记录保留。模型须在本地保存并选择，执行工具还须通过现有工具能力验证。

支持 `帮助`、`状态`、`通道 N`、`新会话`、`停止`、`批准 编号`、`拒绝 编号`。群里的每位成员、每个目标分别保持连续会话，本地工作台可查看带“钉钉”来源的历史和处理具体批准；本地新提问使用独立的本地会话。“停止”只停止该成员当前会话的本轮AI排障，原挂测继续；运行中追加问题会明确提示未排队。首版不接收图片、语音或附件，也不增加整套挂测远程启动/停止接口。

钉钉新会话默认“帮我批准”，不继承本地记住的完全访问偏好。普通操作独立AI审查后执行；危险、风险不明或审查失败的操作在群里展示具体内容与编号，由原发起人发送明确批准/拒绝指令，或在本地处理。编号十分钟内单次有效，停止、内容变化、目标/模型/批次变化和重启后不能继续使用。特别长的操作内容要求回本地核对完整内容。本地仍可为该会话选择三档权限，完全访问必须按原流程确认，且授权只在本进程有效；通用系统操作可能影响同机其它项目。

项目AI数据位于当前Windows用户的 `%LOCALAPPDATA%\LineCheckAssistant\projects\<程序目录身份>`。首次保存只复制旧库中的模型配置、加密凭据、所选模型及容量缓存，不复制会话/报告、监控设置、待恢复任务或完全访问授权；之后各项目独立维护。已确认案例由下述本机共用库统一维护，不随项目隔离。旧数据库保留，工作台不再提供旧库历史查看入口。当前项目的历史对话通过“排障会话”下拉框切换，并通过“管理会话”管理；报告通过“诊断报告”查看。停用接入后仍使用该项目独立库；移动或重命名程序所在目录会形成新的项目数据身份，需要重新配置，旧数据仍留在原位置，共用案例库不受影响。

新增Client Secret使用当前Windows账号DPAPI加密保存，不能直接复制到另一台电脑或另一Windows账号使用。群回复过滤已知模型、机器人和设备凭据；主程序本地日志规则保持。重复回调不会重复执行，程序重启不会自动重放待处理指令；回复失败或发送结果未知时查看本地工作台与主执行日志，不会因此重新执行设备命令。停用接入会停止接收并取消钉钉排障，等待必要恢复；退出程序会等待后台线程收尾。

首次仅需安装更新后的项目依赖；本轮源码改动不包含新EXE。真实钉钉收发、应用机器人测试通知、完整Windows界面及实际模型/设备操作仍须现场复验。

### 飞书 AI 接入与测试通知（2026-11-14，源码版，待现场复验）

入口为“AI诊断助手 → 远程管理 → 飞书”。飞书与钉钉可同时使用，飞书配置不覆盖钉钉地址、密钥或开关。每个独立项目目录使用独立的飞书企业自建应用机器人；普通群自定义Webhook机器人不能用于本功能。首版支持企业内文字消息，不接收图片、文件或语音，不新增整套挂测的远程启动/停止。

1. 在飞书开放平台创建企业自建应用，开启机器人能力，申请 `im:message.group_at_msg:readonly`（群内@消息）、`im:message.p2p_msg:readonly`（单聊消息）和 `im:message:send_as_bot`（应用发消息）权限。设置需要使用机器人的应用可用范围，发布并完成企业管理员要求的审核。无需申请读取群内所有消息或通讯录权限。
2. 在飞书子页签填写App ID（`cli_`开头）、App Secret，点击“保存应用配置”。秘密按当前Windows用户加密保存在本项目AI数据目录，首次打开或重启后Secret留空，留空保存会保留原值；仅隐藏再打开会保留未保存输入。首次准备项目AI库后需要重启程序；模型配置可从原库导入，会话、报告和权限保持项目隔离，案例按当前共用案例库规则使用。
3. 在飞书应用后台订阅“接收消息v2.0”（`im.message.receive_v1`），订阅方式选择“使用长连接接收事件”。若后台要求先建立连接，可在程序中点击“绑定群…”或启用单聊，待动态状态显示已连接后保存订阅，再发布应用配置。长连接只需本机能访问飞书公网服务，无需公网IP或端口映射。
4. 将该应用机器人加入目标群，在程序中点击“绑定群…”，五分钟内在目标群@**该机器人**发送动态状态中的“绑定 编号”。本机收到申请后核对群ID，点击“确认绑定”；绑定本身不会启用群排障或自动通知。绑定期间可从“更多操作”或右键菜单取消申请，关闭配置窗口也会取消当前申请。
5. 按需分别勾选“启用指定群 AI 排障”“启用单聊 AI 排障”“启用飞书测试通知”，三项默认关闭。群排障仅接收已绑定群内@本机器人的文字。单聊启用需本机确认，允许此自建应用可用范围内的所有企业成员调用当前项目排障工具，不要求逐人绑定。群聊与单聊会话独立，单聊结果只回复原单聊。
6. 从“更多操作 → 发送飞书测试消息”（右键也可进入）验证绑定群收信；手动试发不受自动通知开关限制，不依赖模型或AI排障开关。自动通知与现有挂测通知触发点一致，分别发送项目、通道和完成/异常结果，不附远程工具名称、识别码、验证码或设备命令。项目名读取“项目信息”已保存的磁盘值。钉钉和飞书均启用时分别发送，任一平台失败不改变原测试结果；接口接受后仍需在群中核对实际收到。

在本地AI工作台保存并选择模型；设备排障时需勾选有效目标。群内@机器人或在单聊发送“通道3 检查断网原因”。后续问题沿用此人在该聊天中选择的通道；支持对话切换、新建或切回通道及本机电脑会话；设备目标不明时会在对话中追问，不默认选择第一个。支持“帮助”“状态”“通道 N”“新会话”“停止”“批准 编号”“拒绝 编号”。会话按平台、应用、企业、群聊/单聊、人员和通道隔离；本地可查看历史和处理具体批准，本地新提问使用独立的本地会话。

新飞书群聊/单聊会话默认“完全访问”，有效目标内的本机命令、文件读写及设备操作（包括登录、升级、重启、恢复出厂、供电和系统/网络修改）跳过独立审查和常规逐项批准；群/单聊启用确认显示访问及回复范围。本地可为会话降低权限，并单独记忆飞书的新会话偏好，不影响本地和钉钉。降低权限后，危险或不明操作按所选规则由发起人对具体编号批准；结果不明的同一操作重试，即使完全访问也须具体批准。编号绑定原聊天、会话及操作指纹，十分钟单次有效；本地与飞书批准只能成功一次。设备/共享资源占用保护及停止保持；AI回复过滤已知凭据，正文过长分段，发送失败不重新执行工具，内容可在本地工作台核对。

飞书回复排版（2026-11-15，源码版）：AI正文、状态和批准提示统一使用富文本，支持加粗、标题、列表、引用、行内代码及代码块。项目、通道和成员独立显示在标题中，单条回复不再显示`[1/1]`，长回复分段时才显示编号。状态与权限分段展示，批准消息按原因、操作、JSON参数和批准/拒绝编号分区，操作员仍回复“批准 编号”或“拒绝 编号”。仅省略独立的“本轮恢复状态：无临时修改”消息；实际恢复结果、恢复失败、未恢复、结果待核实及通用操作不自动回滚提醒继续显示，完整记录保留在本地工作台及日志。部分富文本样式需要新版飞书客户端，桌面端和手机端显示、代码复制效果仍待现场复验；测试结果通知格式保持原有方式。

停用群排障只取消本项目飞书群会话，停用单聊只取消飞书单聊会话，钉钉及原挂测继续。修改应用凭据前须关闭三项开关、取消绑定申请并等待连接、会话及通知清理；更换应用或Secret会清除群绑定。程序退出会取消排队消息并等待正在进行的网络请求和必要清理；重复事件不重复执行，重启不重放中断的远程操作。同一App ID在本机不能由多个项目同时建立长连接，避免飞书集群模式将消息随机投递给其它项目。

源码依赖新增固定版本 `lark-oapi==1.7.5` 及配套HTTP/加密依赖，请按项目依赖安装。现有EXE尚未包含本功能，后续标准构建须通过全部原门禁。完整Windows源码界面、真实飞书群/单聊收发、通知、模型及DUT联动仍待现场复验。

- 全包升级新增“进入 Boot 方式”下拉框：默认“账号密码登录”保持既有流程；选择“SDMC 指令进入”时，上电稳定 1 秒后立即发送 `sdmc` 加回车，每 1 秒重复一次，检测到 `=>`、`ECNT>`、`U-Boot>`、`#` 或 `>` 后停止发送，不发送 Boot 用户名或密码。`UserName:`、`Password:`、`done/write` 不作为该分支成功标志；600 秒未进入则当前通道失败。两种固件传输方式均适用。选项保存到 `sample_upgrade_settings.ini` 的 `boot_entry_method`，旧配置默认账号密码登录；独立升级确认显示实际方式，主执行日志记录 TX、成功标志与失败原因。下文循环回车/Boot账号说明指默认账号密码方式；SDMC仅替换进入Boot步骤，最终系统凭据及恢复出厂规则不变。
- 全包升级中的 `Tftp指令` / `Tftp Put` 与主界面的“样机管理 IP”和通道已保存的 PC 静态 IP 隔离：无论两者填写何值，均将当前 VLAN 网卡准备为固定 `192.168.1.<VLAN尾号>`，样机固定使用 `192.168.1.1`；运行时切网不改写 `network_card_ip.ini`。`web打开网关` 则使用主界面填写的样机管理 IP 和对应通道 PC 静态 IP/掩码，详见下文；页面升级、写参和线路 Ping 保持各自原有地址配置。
- 选择“全包升级 + Tftp指令”后，只显示可调的并行数 Spinbox（1–8）；程序始终按该并行数完成即补位，单台失败不会停止其它样机。程控电源 COM 帧仍按通道串行发送，后续 Boot、TFTP、重启等待和最终登录可并行。每台 TFTPy Server 及其后续数据传输 socket 都严格绑定当前 VLAN 的 PC IP；设置网卡 IP 后会最多等待 15 秒，直到 Windows 确认该 IP 可绑定，仍不可绑定才报网卡/重复 IP/驱动错误，不回退到 `0.0.0.0`。所选固件映射为设备固定请求名 `tclinux_allinone`，设备仍执行 `tftp <通道IP>:tclinux_allinone`。
- 选择“全包升级 + Tftp Put”后，程序先对当前通道下电再上电；上电帧下发后等待 1 秒稳定，随即循环发送回车，检测到 `UserName:` 后按 boot 账号 `telecomadmin / nE7jA%5m` 登录。随后仍由 TFTPy Client 从当前通道 IP 上传到固定设备 `192.168.1.1:69`，并绑定该源 IP，避免多张 `.1` 网卡造成错误选路或启动变慢；远端文件名使用所选固件 basename。上传后同样观察 90 秒 Boot/Bood 标记：检测到则发送 `reset`，未检测到则对当前通道执行后备下电再上电；后备上下电沿用普通电源默认时序，不使用首轮进入 boot 的 1 秒/1 秒专用时序。未勾选恢复出厂时，完成 reset 或后备上电后仅等待 3 秒即结束当前通道，不登录最终系统；勾选恢复出厂时才保留 120 秒等待、最终系统登录及恢复出厂。该流程同样始终按 Spinbox 的并行数运行，单台失败不会停止其它样机，共享程控电源 COM 由 coordinator 复用同一长连接。
- `Tftp指令` 和 `Tftp Put` 均可在执行窗口的 Spinbox 调整并行数 1–8 台（默认 2，存于 `sample_upgrade_settings.ini` 的 `parallel_count`）；全包升级全程不临时改写 `Auto_power_on_off_tool/config/network_card_ip.ini`；所有串口和 TFTPy Client/Server 都由本程序在 `finally` 中关闭，不查找或关闭外部 CRT/Tftpd 进程。一次并行批次内共享的程控电源 COM 由 `UpgradePowerCycleCoordinator` 持有长连接 `ProgrammablePowerSupply`，仅在首台样机上下电前打开一次，最后一台完成后由 `coordinator.close()` 关闭，避免逐台反复 open/close。
- 全包升级进入 boot 前，`Tftp指令` 与 `Tftp Put` 的程控电源时序统一为“关闭当前通道 → 等待 1 秒 → 开启当前通道 → 等待 1 秒 → 立即放行串口循环回车”；不会再补足 10 秒启动等待或叠加第二个 1 秒等待。主执行日志会输出上电稳定完成及开始进入 boot。该调整只用于样机全包升级，普通自动上/下电等其他电源流程保持原有默认时序。
- `Tftp指令` 仍以串口的 `done` 与 `write` 同时出现作为设备处理完成判据；`Tftp Put` 则以 TFTPy 上传成功作为传输完成判据。两条路径传输后均观察 90 秒 boot 标记：`Boot/Bood` 后延迟 1 秒发送一次 `reset`，未检测到时已配置程控电源则对当前通道执行一次后备下电再上电；后备上下电保持普通默认时序。**未勾选恢复出厂**时，完成 reset 或后备动作后只等待 3 秒，记录当前通道升级完成并跳过最终系统登录。**勾选恢复出厂**时，才等待 120 秒、执行最终系统五次登录重试，再按“命令→1 秒→回车→8 秒”执行恢复出厂；最终登录只能由独立的 shell 提示符行判定成功，密码回显中的 `#` 或 `>` 不会触发恢复出厂。仅当实际发送恢复出厂命令后，主程序执行日志才显示 `TX firstboot -y;reboot`。未配置程控电源时会记录跳过后备上电；未勾选恢复出厂仍等待 3 秒后结束当前通道。
- `Tftp指令` 在样机串口同时出现 `ARP Retry count exceeded` 与 `U-Boot>` 提示符时会自动重发同一 `tftp` 命令，最多 3 次、每次间隔 1 秒；单次等待窗口 5 分钟，由按秒轮询替代阻塞 `wait_for_all`，避免已知快速失败场景消耗完整超时。每次重试和最终成功/失败都会写入主程序执行日志，例如“检测到 ARP Retry count exceeded...，剩余 2 次自动重试”、“自动重试 TFTP 命令：第 2/3 次发送...”、“TFTP 命令在第 2 次尝试时检测到完成标记”或“TFTP 命令已重试 3 次仍未成功...”。仅 `ARP Retry count exceeded` 但未回到 `U-Boot>`（样机仍卡在 Loading）时按普通超时处理，不重试。
- Boot 登录在上电帧后的 1 秒稳定窗口结束后立即发送首个回车；仅当完整 `UserName:` / `User Name:` 在 1 秒稳定窗口内未夹带旧 `Password:` / `Passvord:` 时才提交用户名。用户名回车后重新从串口新数据中等待完整密码提示符，避免首轮上电过渡日志或旧缓存导致账号、密码错位。`Tftp Put` 的 UserName 后直连 boot 登录会在写用户名前记录密码游标、在写密码前记录 shell 游标，确保同批回显里的 `Password:` 或 `ECNT>` 不会漏检。
- 主界面“串口日志记录”已改为内置多通道终端：按 VLAN/COM 分页实时显示、开始/停止、清屏、手动命令发送和日志保存。每个Tab优先打开该通道“通道对应 COM口”的实际选择；历史配置没有`serial_port`时才按`vlan{N} → COM{N-100}`兼容推导。手动打开、“打开全部”、全流程预启动以及自动升级附加日志使用同一映射。“打开全部”会依次启用窗口当前全部 VLAN/COM Tab。每个 Tab 的命令输入框按下 `Enter` 即等价于点击「发送」按钮（输入框非空则发送文本并清空，等价「发送」；输入框为空时发送纯回车，等价「回车」）；自动升级占用某通道时仍显示输出，但手动发送（含按 Enter）被锁定；高频串口输出以最多约每 33ms 一轮的节奏渲染，只有当前 Tab 实时重绘，其他 Tab 切换后显示最新缓冲；每个 Tab 的屏幕只保留最近 5000 行，避免长时间高频输出导致 Tk 无响应。屏幕缓冲超过 64KiB 时会提示已合并字符，但原始日志始终完整写入磁盘；日志文件名按打开监控当日保存为 `vlan名_COM口_YYYYMMDD.log`，例如 `vlan112_COM12_20260808.log`，手动打开、“打开全部”和全流程预启动必须记录实际选择的COM；文件内每个落盘行都以 `YYYY-MM-DD_HH:MM:SS` 开头并保留 RX/TX/STATE/ERROR 方向，例如 `2026-08-08_19:12:10 RX 打印内容`，半行分包会先拼接，不会重复添加时间戳；全包升级自动打开的终端会在本批串口释放并写入关闭状态后自动关闭，手动打开的终端不会被自动关闭；`reboot`、`reset`、`firstboot`、`tftp`、`upgrade` 类手动命令需要二次确认；默认日志目录或本机终端状态文件不可写时会弹出明确错误提示。
- 凡主程序需要准备 VLAN 网卡的流程，都会先查询目标网卡的启用状态和现有 IPv4/前缀：已经启用且地址完全匹配时直接复用，不再重复启用或设置静态 IP；仅有一项不满足时只修复该项，无法读取状态时按原流程完整准备。该规则覆盖线路 Ping、页面升级、全包升级 TFTP 网卡、写参用户/工厂模式切网、测试项执行、DUT 配置和“查询现有 WAN”；原来具有源 IP 可绑定确认的流程仍会继续确认，后续 Ping、UBUS/Telnet 登录或 TFTP 成功判据不变。
- **串口关闭与显示收尾（2026-11-13）**：停止或关闭监控后，若串口仍在接收，界面会显示正在停止/关闭并保存日志；收尾完成后才移除标签或允许重开同一端口，其余串口继续工作。高负载可能合并或跳过部分屏幕显示事件，主执行日志会给出累计提示，原始串口文件独立完整保存。关闭失败会保留状态和原因，可按提示重试。

- **单独关闭串口**：每个串口标签右侧均有“×”，点击后直接停止该标签监控并移除标签，已保存日志保留，其他串口继续记录。未打开或已停止的标签也可移除；自动升级占用时会提示“当前串口正在自动升级，升级结束后可关闭”，保留连接和标签。点击标签正文只切换页面；在“×”上按下后拖离再松开不会关闭。关闭最后一个标签后窗口仍保留；再次点击主界面“串口日志”入口可按当前勾选通道恢复标签，再点击“打开全部”启用。关闭不修改主界面通道配置；成功、占用跳过和失败会记录在主执行日志中。多个标签使用同一COM时仅移除本标签监控，其余持有者继续使用连接。

- 主界面“串口日志”右侧提供“DUT配置”入口。窗口包含“Telnet配置”“WAN配置”“2.4G WiFi配置”“5G WiFi配置”“语音配置”“TR069配置”六个 Tab。主界面已勾选通道只作为候选范围；六页目标表共享独立“选择”列和“全选/清除”按钮，首次加载默认选中全部候选，在任一页勾选或取消都会同步到其它页，所有配置和只读查询只处理DUT窗口内当前选中的目标。因此主界面可同时保持vlan112、vlan113启用，再在DUT窗口取消vlan113，仅操作vlan112。刷新相同候选范围会保留手动取消状态，主界面新增候选默认选中、移除候选自动删除；选择变化后旧查询状态和WAN下拉失效，未选择目标时禁止启动。UBUS 账号、密码和并行数与 Telnet 页共享，账号密码与“写样机参数”的首次登录凭据一致并明文显示。每台完成上述按需网络准备后仍等待源 IP 可绑定，再从该源 IP 登录样机 UBUS；支持 1–8 台并行（默认1）、单台失败隔离和停止后不再启动后续 DUT，同一时间只运行一个 DUT 配置批次，批次运行期间不能修改目标选择。
- “Telnet配置”点击“开启 Telnet”并确认后，通过 UBUS 开启 `Device.Firewall.<X_SDMC_>Security.AccessCtrl` 下的 LAN-telnet 规则，再从对应 VLAN 源 IP 验证 TCP 23 端口；只有 UBUS 和端口验证均成功才判定成功。点击“查询当前Telnet”只读取AccessCtrl总开关和LAN Telnet规则，并锁源探测TCP 23，不执行set/add；“当前状态”区域逐台显示总开关、规则、SourceInterface和端口可连接状态。
- “WAN配置”支持新增、修改和删除指定 WAN，并按当前选择实时只展示有效字段：新增隐藏现有连接索引，修改显示索引和配置项，删除只保留现有连接选择。修改/删除时，“现有连接名/索引”是只读下拉框；点击旁边“查询现有 WAN”后，程序会对DUT窗口当前已选中的每台目标执行网络准备和锁源 UBUS 登录，通过只读 `bbfdm.get Device.IP.Interface.` 获取现有连接。单台时显示该 DUT 的连接；多台批量时只显示所有目标名称完全一致的共同 WAN，不按相同数字索引合并不同业务；任一目标查询失败或停止都不会生成下拉列表。目标 DUT 或DUT窗口选择变化、执行过 WAN 配置后会清空旧列表并要求重新查询。桥接仅展示业务类型、业务 VLAN、优先级和端口绑定，业务类型限定为IPTV/INTERNET/OTHER；路由才展示接入方式、协议、MTU、NAT和地址参数。端口绑定使用LAN1–LAN8原生多选框，分别对应位掩码1、2、4、8、16、32、64、128，多选自动按位合并；新建桥接且未选择端口时默认勾选LAN1，查询现有WAN时会把例如 `PortBind=8` 反向显示为LAN4。修改现有WAN时会保留设备返回的WiFi等非LAN绑定，切回新增时不继承这些不可见旧位。当业务类型为IPTV时，路由和桥接都会额外显示可选“组播 VLAN ID”；留空表示不单独配置，填写时必须在1–4094范围内并以 `MulticastVLANID` 下发，切换到非IPTV后该字段隐藏且旧值不会误下发。IPoE隐藏PPPoE账号密码、切换时自动回填默认MTU 1500；PPPoE显示账号密码、自动回填默认MTU 1492，并只允许动态地址。IPv4只显示IPv4地址方式，IPv6只显示IPv6地址方式，IPv4+IPv6双栈同时显示两者；DHCP/SLAAC/DHCPv6隐藏对应静态地址项，选择静态才显示地址、网关、DNS和掩码/前缀。IPoE双栈仅允许DHCP+SLAAC、DHCP+DHCPv6、静态IPv4+静态IPv6；PPPoE双栈仅允许动态IPv4+SLAAC或动态IPv4+DHCPv6。界面下方会显示当前组合说明，业务预检也会再次拒绝非法组合；MTU自动值仍可按设备需要在576–2000范围内调整。程序不提供删除全部 WAN，删除前会再次提示不可自动恢复。

## 样机升级：停止升级（2026-10-14）

- “停止升级”位于“开始升级”旁，覆盖页面升级、Tftp指令、Tftp Put 和 web打开网关。仅升级运行时可点击；点击直接请求停止，不弹确认框。
- 状态立即变为“正在停止”。排队样机不再启动，当前样机在安全步骤退出；等待资源释放期间不能再次升级。关闭窗口不停止批次，重新打开后可查看状态并停止。
- 正在进行的电源下电/上电组合会完成；正在传输的 TFTP 或 HTTP 请求保留至返回、失败或原超时。Tftp指令已发送时保留当前完成标记等待，但不再自动重试。页面升级已触发时继续只读观察升级状态至成功、失败或原超时。
- Web 已点击提交时，仍完成固定30秒等待，并等本次上传请求结束或原超时后关闭本次专用浏览器和代理。未观察到上传请求时最多使用600秒传输等待预算；已开始的请求遵循其原网络超时。等待结束不代表设备固件写入成功。
- 停止后不再发起 reset、后备上下电、最终登录和恢复出厂。已经开始的设备命令无法撤销；日志会注明“已提交/已下发，设备结果待确认”。正在停止时不要依靠重新启动批次来判断设备已完成刷写。
- 完成摘要区分成功、失败、已停止和未开始跳过；“已停止”不是“升级成功”。主执行日志保留每个通道的停止位置、跳过项及汇总。
- 样机升级保留独立入口和本窗口“停止升级”；全流程不再包含升级，主界面“停止测试”继续用于当前全流程。独立启动的升级不受无关全流程停止影响。
- 新增停止功能已完成模拟设备回归；Windows源码版按钮布局/关闭重开及真实样机各阶段停止，仍待项目负责人现场验收。

## 验收步骤

1. 启动软件后，确认界面能列出 `network_card_ip.ini` 中已有的 `channel_1`、`channel_2` 等通道。
2. 点击“刷新串口/网卡”，确认下拉框里能看到当前 PC 的网卡名称，例如 `a虚拟网卡2口`。
3. 选择一个通道，填写：
   - 样机接入网卡
   - PC 静态 IP
   - 样机管理 IP
   - 子网掩码
   - 是否启用
4. 勾选或取消勾选通道，确认 `Auto_power_on_off_tool/config/network_card_ip.ini` 立即更新，并且只保留已勾选通道的 `[channel_x]` 配置节。
5. 人工接好线路后，点击“自动上/下电”，选择程控电源 COM 口和操作类型（默认“上电”），并确认影响通道。
   - 选择“上电”时，软件会按勾选顺序发送开启帧，相邻帧间隔 1 秒，且不会先关闭任何通道。
   - 选择“下电”时，软件只会向勾选通道发送关闭帧，相邻帧间隔 1 秒，不会发送全部断电帧。
   - 确认后主程序直接发送程控电源串口帧，不会启动旧 EXE 或点击外部 GUI；最后一条帧后不额外等待。
6. 回到新软件，点击“检查当前通道”或“已上电，开始检查全部启用通道”。
7. 观察日志：
   - 通过：显示 `[通过] channel_x ping xxx 成功`。
   - 失败：显示通道、网卡、PC IP、样机 IP，并提示检查上电、网线、接错口、IP 配置。
8. 打开“样机升级”，选择“页面升级”，确认已勾选通道都有 PC 静态 IP 和样机管理 IP，选择固件后点击“开始升级”。
   - 软件会二次确认将通过 UBUS 上传固件并触发升级。
   - 软件会先启用目标通道对应网卡；如果启用失败，会在日志和失败弹窗中提示。
   - 日志会显示每台样机的 HTTP/HTTPS 登录、上传、升级状态和重启上线结果。
9. 打开“写样机参数”，先使用“生成批量参数表...”为已勾选 VLAN 生成 Excel 表，或选择已有 `.xlsx` / `.xlsm` / `.xls` / `.csv` 参数表；确认预检清单中的 VLAN、COM、MAC 一一对应。
   - 并行数可选 1–8 台，默认 1；修改后会保存，下一次打开“写样机参数”会恢复上次关闭前的有效值，不影响“样机升级”的并行数。
   - 点击“写入参数”后，确认框会提示清空参数、工厂模式和两次重启；仅在确认后才实际下发命令。
   - 现场先以 2 台独立 VLAN / COM 样机验证，确认每台写入后读回校验成功、密码明文便于核对，并确认设备已完成退出工厂模式后的重启。

主界面工具栏「测试项配置」按钮用于编辑测试配置；“测试项”页提供独立的单次预备测试，“项目信息”页提供版本查询。预备测试不加入全流程子任务。

### 单次预备测试

1. 在主界面勾选目标通道，配置各通道网卡、PC 静态 IP、掩码及样机管理 IP。
2. 打开“测试项配置”，填写 Telnet 登录参数，在“测试项”页点击“执行全部命令（预备测试）”。检查确认框列出的全部目标后开始。
3. 使用当前页面内容（包括未保存修改），按通道列表和命令列表顺序执行。每条命令只下发一次，忽略正式测试的重试次数及间隔，不自动保存配置。
4. 沿用现有多段期望、`&&` 和否定匹配；单条不匹配或回显超时标红后继续下一条。无期望时显示“未配置结果校验”，不计为成功；登录失败、连接中断或网络准备失败终止当前设备，继续下一个已确认目标。
5. 主界面日志记录源/目标 IP、下发命令、设备回显、逐条结果及汇总，成功绿色、失败红色，未校验/停止黄色。内容自动追加到当前主执行日志文件（文本文件保留时间戳和状态文字，不保存字体颜色）。
6. “停止执行”阻止后续命令与目标；已经下发的命令无法撤回。连接或网络操作退出后恢复按钮，汇总已执行与未执行数量。运行时关闭配置窗口或主程序会先请求停止，待日志保存后再关闭。

预备测试会按目标配置准备网卡并登录 Telnet；请保证设备 Telnet 已开启。登录成功提示符为 `>` 时，先发送当前 Telnet 页的“登录后命令”一次并等待 1 秒，再执行测试命令；确认框会列出该登录后行为，空值仍发送一次回车。它不触发电源、WiFi、升级或正式开关机测试流程；实际设备行为由当前页面中的命令决定。

新版预备测试、测试项执行和项目信息查询在登录成功提示符严格为 `>` 时，连接后直接等待设备主动输出的用户名提示符（包括已经收到的历史内容），不先发送回车，避免 CMS 将其当作空用户名。主日志依次提示等待用户名、用户名已发送、密码已发送（隐藏）和等待 `>`；密码后出现空行或 `Entering CMS CLI:` 不影响匹配。未收到提示符时按原超时结束，不盲发账号或额外回车。`#` 等其它提示符继续使用原登录起始方式；本次不改变共享连接超时、换行或登录后命令规则。

Telnet 页保留“免用户名密码登录”“仅执行上下电”两个“是/否”下拉框。任意一项为“是”时，登录用户名和密码输入框置灰；两项都为“否”时恢复编辑。置灰保留原有内容，保存、重新加载和关闭重开均保留用户名、密码及对应选项；免认证失败时仍沿用原有凭据回退流程。“是否需要输入密码”已取消，其旧回车探测不再执行；旧配置中该项为1也不生效，加载不改写文件，保存时兼容键统一写回0。

- **六 Tab 结构**：

  - **WiFi** —— 保留连接主控、2.4G/5G、ONU方案、指定无线网卡和刷新功能，并提供“连接测试模式”“自动识别认证参数”和可选“无线 Ping”；底部不再常驻显示主控、方案与网卡规则说明。只编辑或保存不会连接网络。当前正式Telnet测试仅支持openwrt方案；bcm/mtk历史值可显示，但启用测试时会明确提示暂不支持。

    - 测试将断开所选无线网卡当前连接，使用不保存到系统的临时配置，结束时断开临时连接，保留原有无线配置，不主动连接其它网络。按FIFO由一个通道连续完成连接、核验和可选Ping后再交给下一通道。每频段合计最多4次尝试（首次加最多3次重试），扫描、连接及Ping阶段共用次数，进入Ping不重新计数。每次扫描/连接/连续2秒稳定核验共约20秒，重试间隔10秒；Ping阶段（含等待无线IP及结束后的连接复核）若掉线、SSID/BSSID、实际频率/频段或认证/加密核验失败，先断开并确认清理，再重新扫描、连接、核验和重跑本频段Ping，不累计先前尝试的回复。Ping全部无有效回复仍直接失败；DNS/IP/socket等环境异常沿用原处理。

- **开关机运行参数** —— 加载 `Auto_power_on_off_tool/config/config.ini [ui_defaults]`，页面只展示 `startup_time`、`interval_time`、`number_of_tests`、`wait_command_done` 四项。界面左侧使用黑色中文名称（设备启动等待时间、每轮断电等待时间、测试循环次数、命令完成后等待时间），不显示原始键名，也没有右侧灰色说明列。`communication_method`、`baud_rate`、`selected_profile` 和 `telnet_enable` 不展示，保存时保留前三项原值；`telnet_enable` 由 Telnet 页 `telnet_default_on` 按 `1 → 0`、`0 → 1` 反向计算并自动写入。

支持钉钉 `https://oapi.dingtalk.com/robot/send?access_token=...` 和飞书 `https://open.feishu.cn/open-apis/bot/v2/hook/...`，其它域名或路径在发送时提示错误。飞书这里填写群自定义机器人的Webhook及其签名校验密钥；不要填写App Secret。切换平台时需同时更换对应机器人的密钥，未启用签名校验则清空密钥。此处Webhook推送与“飞书 AI 接入”中的应用测试通知各自独立；同时启用且发送到同群时可能收到两条通知。

“消息推送”页的“发送测试消息”使用当前页面地址、密钥和 @所有人设置，无需先保存推送配置，即使自动推送开关关闭也可手动试发。发送文本“项目：{project_name}”后换行，再附“LineCheckAssistant 消息推送测试：收到此消息表示{钉钉或飞书}机器人推送正常。”，平台名称由地址自动确定；填写密钥时自动按平台加签，留空则不加签。若机器人设置关键词，需确保该文本满足规则；@所有人仍受群机器人和群权限限制。后台请求超时为10秒，不自动重试；发送中禁用按钮并阻止关闭配置窗口。页内与主日志显示实际平台及结果；成功表示对应平台接口已接受，请在群中确认收到。网络异常结果未知时先检查群消息，再决定是否重试。不会保存配置或更改自动推送开关。保存飞书Webhook并启用消息推送后，正式完成/异常通知同样发往飞书，包含项目名、结果及测试详情，不附远程客户端信息。

正式完成/异常通知的标题与正文，以及测试消息中的项目名，均在每次发送时读取 `Auto_power_on_off_tool/config/test_project_config.ini [project_info] project_name` 的已保存值，不再使用 `config.ini [config] test_project` 或固定项目名。“项目信息”页面修改项目名称后需先保存；未保存的名称不用于试发。项目名缺失、空白或文件读取失败时，提示失败并跳过发送。主执行日志记录项目名读取、实际 POST 下发及成功、跳过或失败阶段，凭据不写入日志。
- **底部按钮**：「重新加载」（从磁盘重读 ini，丢弃未保存改动）/「保存」（二次确认后写回 ini）/「关闭」。
- **Dirty 跟踪**：任意控件改动标记 dirty，「重新加载」和「关闭」在 dirty 时弹「放弃修改？」二次确认；「保存」成功后 dirty 清零。
- **窗口显示**：首次创建采用标准`Toplevel`自然映射，不执行`withdraw()`隐藏构建、`after(0)`强制恢复或嵌套`update()`；固定960×940尺寸直接用于居中，避免弹出前强制刷新复杂控件树；映射后20ms先执行一次立即恢复的1像素客户区快速刷新，并保留120ms和360ms两次兜底，强制Windows整体重绘五个Tab且不改变窗口尺寸；再次打开已有窗口也会补充刷新。
- **保存行为**：保存会把 Telnet、测试命令、WiFi 和项目信息写入 `test_project_config.ini`，把指令重试间隔仅写入 `config.ini [other_config]`，并更新 `config.ini [ui_defaults]`；WiFi原有8项键继续保留，新增 `connection_test_mode / security_source / wireless_ping_enable / wireless_ping_target`。旧配置缺键时采用分频段、自动认证、无线Ping关闭和目标空值，不自动写文件或覆盖原频段、网卡及手动认证值。测试项 ini 的原注释会丢失，`config.ini` 的其它配置段、未知键和注释保持不变。测试项 ini 不存在时打开窗口会提示「将以空白表单打开」，保存后自动创建。
- **「期望」拼接规则**：每段独立勾选「否定」→ 该段前加 `!`；多段 → 用 `&&` 拼接；空段不写入拼接结果。例如第二段的 `00:00:00:00:00:00` 勾否定、`UP BROADCAST` 不勾，保存为 `!00:00:00:00:00:00&&UP BROADCAST`（前者应**不**出现，后者应**出现**）。
- **「重试间隔」语义**：本字段名为 `command_fail_retry_interval_time`，唯一保存到 `config.ini [other_config]`，不会写入 `test_project_config.ini [order]`；与老工具 `wait_time_N`（sleep 秒数，**语义不同**）不共用。它是全流程测试项命令失败后的重试等待时间，测试项页面和全流程执行都从这一唯一位置加载。
- **主执行日志**：保存成功 / 失败都会写一条主程序执行日志；成功日志同时记录测试项命令数和更新的旧工具参数数量。
- **执行边界**：本窗口不会因编辑或保存立即连接 WiFi、执行 telnet、上下电或运行测试命令；“测试项配置（[order] 执行）”已从全流程子任务中移除。但保存的 WiFi 参数会在以后勾选全流程子任务3“执行开关机测试”时由无 GUI 旧业务读取并生效。

### 旧工具顶部参数配置

旧 `Auto_power_on_off_tool/Auto_Power_On_Off_Tool.py` 顶部的通信方式、波特率、默认方案及运行时间参数从 `Auto_power_on_off_tool/config/config.ini [ui_defaults]` 读取。旧工具 `Telnet Enable` 与新工具 `test_project_config.ini [telnet] telnet_default_on` 使用反向关系：`telnet_default_on=1` 表示设备默认已开启，旧工具 `telnet_enable=0`；`telnet_default_on=0` 时旧工具 `telnet_enable=1`。旧工具启动时直接按此关系加载，新工具保存测试项配置时同时更新 `config.ini [ui_defaults] telnet_enable` 镜像值并保留其它内容。`command_fail_retry_interval_time` 只保存在 `config.ini [other_config]`。旧工具的 `serial_num` 与新工具“程控电源 COM”严格共用同一值，固定读取 `network_card_ip.ini [power_supply] serial_port`；新工具 COM 为空时旧工具同样为空，不回退、不自动选择其它 COM。“电源控制”的 channel 1～16 复选框也严格同步同一文件中的新工具选中配置：存在且 `enabled=1` 的 `channel_N` 才勾选，其余通道全部取消。全流程子任务3还会把当前测试方案 `[connect_wifi]` 的 8 项 WiFi 参数映射到旧业务 `OnuCongfig`；主控关闭时跳过 WiFi，指定网卡为空或运行电脑不存在该网卡时明确失败且不静默改用其它网卡。程控电源直连、升级和其它主程序路径仍不调用旧 GUI 或旧 EXE。

## 全流程执行窗口（2026-11-12 精简）

主界面「检查并执行测试」打开全流程窗口，仅提供环境线路检查、串口日志和执行开关机测试。自动上/下电、样机升级、写样机参数、ONU 注册保留主界面的独立入口，不再加入全流程；“本次无人值守”选项一并移除。

- **3 个子任务**：每行使用 Windows 原生勾选框，选中显示标准勾号、未选为空框；首次打开全部不勾选。点击勾选框或标题均可切换，右侧提供必填项状态和「去配置」。
  1. **环境线路检查**—— 至少选择一个启用通道，填写 VLAN、网卡、PC IP、样机 IP；逐通道按需准备网卡并 Ping 样机，任一通道失败停止后续任务。
  2. **串口日志（全流程期间持续记录）**—— 勾选后在全流程开始时先显示多 VLAN 终端并执行“打开全部”，记录后续环境检查和开关机测试；串口打开失败记入日志，不阻止后续任务。
  3. **执行开关机测试**（默认不勾）—— 不启动旧工具 GUI 或 EXE，在独立无 GUI 子进程复用旧 Start All 的 Telnet/SSH、程控电源和通道业务。参数来自当前 `config.ini [ui_defaults]`、当前测试方案和 `network_card_ip.ini`；只启动新工具当前勾选通道。启动旧业务前，按当前选定方案“项目信息”中已保存的三项版本基准决定是否预检。三项去除首尾空白后全部为空时，确认框和主执行日志明确显示“三项版本基准均为空，跳过开始前版本校验”，不建立预检 Telnet 连接、不下发预检登录后命令或版本查询命令，继续原开关机测试流程；项目名称不参与判断。部分填写时提示缺少字段并阻止启动，需补齐三项或全部清空后保存。配置缺失、不可读或解析失败均报错，不能当作三项全空。全部填写时，确认框说明将执行预检及实际选定方案的登录后命令；逐台锁源 Telnet 登录成功且提示符为 `>` 时先下发配置命令（空值仅回车）并等待 1 秒，再查询已勾选通道的 `software_version`、`inner_sw_version` 和 `/proc/version` 编译时间，并与当前测试方案“项目信息”中手动保存的软件版本、内部软件版本、ONU 软件编译时间逐项严格比对；启用预检时，任一通道查询失败或任一字段不一致都会记录差异并终止，绝不下发断电帧或启动开关机测试。启用预检时全部通道三项均一致后才继续。初始化仅断电本次已勾选通道：按通道顺序去重后逐个发送单通道关闭帧，每帧后等待0.5秒，全部下发完成后才启动测试；不发送全通道断电帧，未勾选通道保持原电源状态。启动确认框列出本次通道并提示危险操作；主执行日志记录目标通道、实际十六进制帧和下发结果，下发完成不代表已回读确认电源状态。初始化中停止或写入异常时不继续剩余通道、不启动测试，也不自动恢复已断电通道。每轮测试时序及失败通道续跑保持原规则。转入新工具的旧日志采用精简模式：保留每轮开始、关键登录/连接/Ping/WiFi/重试结果、全部警告/错误、实际电源帧和最终结论，过滤配置路径、原始命令回显等底层 INFO；2 秒内同级同文重复日志只显示一次，连续出现的同级同文旧日志即使超过 2 秒也只保留第一条，出现其它可见日志或执行阶段后下一条相同结果可再次显示；`IP登录成功` 在本次开关机测试中按 IP 各显示一次，例如 `113/112/113/112` 最终只保留113和112各一条，重新启动测试后重新计数；旧英文网卡 Ping 成功行会根据当前测试方案实际目标转换为 `Ping 成功：源网卡 192.168.1.112 → 目标样机 192.168.1.1`；其中 `通道 【N】 开始第M次测试` 正文使用绿色字体。旧工具结果文件中形如 `2026-08-08 15:37:41.904434: 通道9下挂的设备在第1次测试时正常` 的每轮正常结论也会实时显示为新工具的 `[旧工具Logs][INFO]`，原结果文件照常完整保存。该项会等待所有通道执行结束，任一通道失败会停止全流程。

实际执行顺序为：已勾选串口日志提前启动 → 已勾选环境线路检查 → 已勾选开关机测试。串口日志预启动和环境检查完成后均不额外等待；原编排器其余任务间120秒等待及停止机制保留，当前三项组合不会产生额外的子任务间等待。

点击「开始执行」后，已选任务缺项时先询问是否继续，再显示实际顺序的总确认；选择开关机测试时明确提示初始化仅断电已勾选通道及本次版本预检策略。取消任一确认均不启动线程、不隐藏窗口。确认并成功启动后台线程后窗口自动隐藏，运行期间主入口只提示查看主界面；结束后可再次打开。完成、部分失败和异常提示均以主界面为父窗口，通过主程序 UI 队列返回 Tk 主线程；检测到线程已结束时清理残留运行态。

- **开关机轮次进度**：主界面“环境检查与开关机测试”卡片的进度条在全流程启动时重置；开关机测试开始后，最大值读取本次 `config.ini [ui_defaults] number_of_tests`，右侧显示“开关机测试进度：当前轮次/总轮次”。普通测试按每轮正常结论推进；仅上下电模式不写正常结论时，以进入第 N 轮确认前 N-1 轮已经完成，并在最终成功时补齐满格。多通道并行时按所有已选通道均已完成的最小轮次推进，避免快通道使总体进度提前到 100%；总进度条下方的“通道概览”另显示“当前第 N 轮已完成 X/Y、运行中/重试/失败数量”，每个通道以独立轮次小卡展示，只有落后、重试或失败项进入“关注”行。停止或失败时保留最后已完成轮次和通道详情。
- **必填项状态展示**：每行右侧实时显示当前 store / main UI 状态（绿色就绪 / 红色「缺: 字段1, 字段2」），打开窗口时自动计算，勾选 / 切换 Checkbutton 时也会刷新；底部「刷新状态」可在去配置后立即手动重算，不执行任何设备操作。
- **串口日志预启动**：全流程子任务编排在后台线程运行，但“显示串口终端 + 打开当前全部串口”会作为一个动作投回 Tk 主线程；全部打开成功后才开始其它子任务，避免只显示窗口却仍处于“COM 未打开”状态。任一串口打开失败时，主执行日志记录失败 VLAN，串口日志任务按既有非致命规则继续后续子任务。
- **串口日志目录同步**：全流程第2项与“串口日志记录”窗口共用当前日志目录。在串口窗口点击“浏览…”选择新目录后，已打开且未运行的全流程窗口立即更新，执行确认框也显示同一目录；尚未打开串口窗口时读取上次保存的有效目录，无有效记录则显示默认 `D:\Serial_Log`。取消选择或选择失败保持原值。新目录用于之后新打开的监控；已打开的监控继续写原日志文件，如需切换请先停止对应监控再重新打开。
- **停止、关闭与界面动作失效（2026-11-13）**：全流程尚未被主界面领取的动作默认排队最多30秒，超时、停止或退出后失效，不会稍后自动启动。已开始的操作按原安全停止边界收尾，期间不能重复启动；关闭已完成的配置窗口不影响原失败通道续跑。程序退出时保留界面处理后台收尾，待任务及串口日志结束后再关闭。

- **失败处理**：任一「致命」子任务抛异常 → 整个全流程停止，弹「全流程执行失败」错误框；串口日志失败只记结果不阻塞。

## AI占用保护与接收历史监测（2026-11-15）

- 本机通用命令和文件写入在设备或共享资源忙碌时拦截，包含AI只选择部分通道、其它通道仍在挂测的情况；批准后转忙也不会下发。无害的通用命令也可能被保守拦截，不通过降低权限检查绕过。历史材料分析、证据检索、本机文件只读、被动串口和报告生成保留；需要主动访问DUT的步骤仍受占用保护。
- AI在发送前检查当前Shell和连接。Boot、重新登录、断线、超时或发送结果未知时停止复用，不自动重发；临时恢复也不能向不确定的会话发送命令，恢复未完成时保留记录。三档权限、凭据显示和业务测试判据不变。
- 源码程序后台每60秒记录一次资源快照，保存在本次主执行日志目录的`resource_monitor/transport_history_*.jsonl`。通道以实际COM/VLAN/会话标识关联；包含RSS、历史/待写半行大小、文件大小和可观察状态。开始、异常和结束经主执行日志反馈，不增加固定按钮。未开启的串口不会因此自动打开；监测不发送设备命令。
- `received_bytes`运行时由当前只追加的历史长度推导，非独立驱动计数；`history_limit_bytes=null`表示当前未设上限。文件大小包含时间戳/方向/文本换行，不能与接收字节直接相等比较；`last_flush_confirmed=null`与`unverified`表示不能确认，不是写入成功。专项测试另使用独立驱动计数、序列号和摘要校验。
- 当前文本日志不是字节保真原始归档。跨块UTF-8、无换行待写尾部及写盘异常仍有风险；只读监测不能追回未保存数据或获知已被忽略的全部错误。本轮不限制、截断或清理原日志，不改动接收、写入和原始内存历史。后续完整归档和告警方案须另行确认。

便携目录包含 EXE、`PORTABLE_README.txt`、`VERSION_INFO.txt`（版本号与本版变更说明）、第三方声明、SHA256 文件和程序所需的 `Auto_power_on_off_tool\config`。构建时只把当前配置当作字段/业务模板，自动清空当前电脑的 OLT/DUT/升级账号密码、OLT/源IP、ONU ID、钉钉和远程控制信息、固件/参数表路径、项目版本，以及网卡、串口和无线网卡绑定；C600业务映射等业务默认模板继续保留。另一台电脑首次运行前必须重新填写网络、测试项、升级/写参和ONU注册配置。

Tkinter资源同时兼容既有PyInstaller 5和当前PyInstaller 6：EXE内部保留`tcl`和`tk`根目录，并增加6所需的`_tcl_data`和`_tk_data`。构建脚本会在生成便携包前检查归档中的`tcl\init.tcl`、`tk\tk.tcl`、`_tcl_data\init.tcl`和`_tk_data\tk.tcl`；缺失时构建直接失败，不能交付。若目标电脑曾解压过旧包，应将新包完整解压到新目录并按上文备份/迁移配置，避免混用旧EXE或覆盖本机配置。

生成的 `.spec` 文件统一保存到 `line_check_assistant\packaging_specs`。

每次重新打包出最新版 EXE 后，不在当前 PC 直接运行 `dist\LineCheckAssistant.exe`或便携目录中的 EXE；只检查构建结果、ZIP清单、配置脱敏和SHA256，并向用户报告输出路径。

打包后程序会从 EXE 所在目录、上级目录中查找 `Auto_power_on_off_tool/config` 文件夹；程控电源协议已内置，不再依赖 `Auto_Power_On_Off_Tool.exe`。

# DUTPilot

在 Qt 工作台中，鼠标停在下拉框或数字输入框上滚动时，当前值保持不变。在可滚动的表单内可继续用滚轮翻页。展开下拉列表后，用滚轮浏览候选项，点击或按回车确认选择。数字可用键盘或输入框旁的上下箭头调整。

## Windows Qt 候选版与源码工作台

右键点击青绿色顶栏，勾选或取消「显示全局工具栏」，即可切换右侧工具区。即使侧栏和工具区都已隐藏，仍可右键顶栏恢复工具区。键盘可按 Ctrl+Shift+T 切换，也可按 Alt+V 后回车。窄窗中点最右侧的「更多工具栏操作」（»）可找到放不下的命令，键盘可用 Tab 定位后按空格打开。下次启动时右侧工具区默认显示。

源码工作台的「系统状态」默认显示资源占用摘要，点「展开」查看详细指标。窗口较小时，侧栏和实时日志默认收起，可用顶栏导航按钮和日志的「展开」恢复。手动调整后，缩放窗口时保留本次会话的显示选择。

总览的卡片和列表默认先显示运行中、需关注和其他活动项目。可继续按项目名搜索、筛选状态或点击列表表头排序。开关机显示已有的完成轮次、进度和阶段。全业务老化显示监测时长、业务健康和最近检测，缺少记录时会显示未知或暂无观测。

在 Qt 工作台按 Ctrl+N，填写「项目与测试类型」，在「确认项目」核对后点「创建项目」。老化时长、业务项和采集来源在第一页。「保存到」选择已存在的父目录。「最终路径」随项目名称、类型和保存位置更新，目录名为 `项目名_开关机挂测` 或 `项目名_全业务老化`。目标已存在时，请更换名称或保存位置。

如果创建失败，向导和主执行日志会显示同一条原因。看到「项目档案校验失败」时，用「上一步」返回对应页面，修改提示指出的字段，再回到确认页创建。若提示「项目目录已创建，工作区载入失败」，请通过项目菜单打开最终路径。

建项前可点「保存草稿」，下次新建时继续。旧草稿的有效通道设置会随项目创建，确认页会提示。旧版仅存最终路径时，重新选择「保存到」。已有项目通过「项目 → 项目向导…」编辑项目档案和测试计划。

在项目主界面点「环境配置」，设置管理 IP、通道和串口。开关机项目也可选择程控电源。通道保存后按启用通道生成 DUT，默认名称为 CH01 等，项目 SN 可留空。右键已启用通道可填写样机名称、目标固件、ADB 标识和其他设备。旧老化 DUT 可在同一窗口绑定启用通道或「移出本批」，两种选择都保留历史。

Qt 工作台提示需要核对配置、目标或任务时，点击「前往确认」可打开原项目的对应页面，并定位相关字段、通道、模块页签或资源记录。比如提示 CH01、CH02、CH07 缺少已保存的 DUT 映射时，会打开「环境配置」、标出三个通道并定位到 CH01。若同一项目的另一配置窗口仍开着，先处理该窗口的草稿，关闭后会继续定位。核对完毕后仍须通过原入口保存或重新确认操作。弹窗也可直接点「确定」关闭。

在自动开关机项目点击「开始测试」。确认框列出本批已保存的启用通道，执行前核对 DUT 映射、轮数和实际资源。轮数在「测试项配置 → 测试循环次数」设置。更改通道或目标后，保存再确认。详情按 DUT 显示各阶段、轮次和回执。

全业务老化的「开始监测」检查环境配置中已启用的 DUT，按保存的业务项持续监测。旧档案在完成环境配置迁移前沿用原目标。启动时确认 DUT 和监测业务，执行前核对资源。详情按所选业务显示检查来源、最近成功时间及异常时长。可选择一条业务记录进行日检或期末检查，从「检查记录…」按批次查看及导出 CSV。现场核对 48 小时专项和 7 天验收时，还需查看各业务实际观测区间和检查记录。

进入项目的「运行概览」，开关机先显示运行时长、成功、失败和异常，再显示完成轮次、当前阶段以及通道矩阵或列表。全业务老化先显示监测时长、业务健康和最近检测时间，然后显示业务和 DUT 观测。业务计数按 DUT 与业务的组合统计，未知状态单独显示。界面用 `—` 表示缺少数据，尚无可用健康趋势时会直接提示。

点击「成功」或「失败」卡片可按 DUT 和通道查看本次任务的轮次记录。点击「当前异常」可查看失败通道或结果未知任务的状态、阶段和已有原因。卡片显示 `—` 时也可以打开详情，窗口会显示已有回执或提示暂无记录。可用 Tab 聚焦卡片，再按回车或空格打开。

在页面下方展开「项目日志」，可按项目、当前任务或通道查看执行记录。原始串口日志可从串口日志窗口查看。运行参数和资源配置在右侧，空间较小时可用「测试配置」展开。运行概览空间较小时，配置和日志会按可用宽高收起。手动展开或收起后，本次会话保留该选择。

重开开关机项目时，如果最近任务是已结束的开关机批次，总览显示所有参测 DUT 都已达到的轮数。有 DUT 缺少完成回执时，会提示回执尚不完整。批次有开始和结束记录时可查看运行时长。

在「归档日志…」里选择结构化工作区记录，可按项目、DUT、通道和等级逐页检索。检索结果保留原始消息、步骤、任务和运行批次。旧项目的文本日志仍可从原归档入口查看。

### 查看资源保护与声明 ADB 设备

长挂采集串口时，每个会话在内存中最多保留最近 256 KiB 的原始接收历史。较早的数据写入当前 Windows 用户的临时目录，供终端和正在执行的任务从原游标回读。临时空间用量随本次接收量增加，持有该会话的最后一个读取者释放后自动清理。需要长期留档时仍可按原方式启用串口日志。临时存储失败会提示错误，依赖串口标记的操作须核对本次回执。

打开「设备管理 → 资源保护」，可按资源标识、项目 ID 和「Job / 持有者」查看占用。两个项目同名时以项目 ID 区分。「已持有」表示本工作区已有任务取得使用权。「受保护」表示原持有者或端口尚需完成释放，详情见主执行日志。

在主界面「环境配置」中右键启用通道，可选填「ADB 设备标识」。按现场确认的标识原样填写，包括大小写，无此资源可留空。保存后两类任务按本批 DUT 申请使用权，标识被另一项目持有时会提示冲突。可在资源页核对已租用的 ADB 标识，设备在线状态仍需根据现场观测确认。

### 保存与应用型号模板

同一型号需要重复建项时，先在源项目填好产品型号、测试类型和方案，保存项目。在已保存项目的向导右上角打开「项目操作」→「保存为型号模板…」并确认。同一型号与测试类型再次保存会更新模板版本。侧栏「测试模板」可查看已打开项目的保存版本并进入源项目。

按 Ctrl+N，在新建向导的「型号模板」下拉框核对型号、测试类型和版本，点击「应用模板」。向导会填入型号、类型，以及老化时长、监测业务和采集来源。开关机轮数从「测试项配置」读取。已有不同方案时，确认后才替换。项目名称、目录、自填软件版本及要求沿用当前输入。

### 接入现场采集结果

在全业务老化向导勾选要监测的业务，再在对应来源下拉框选择「现场采集」。保存项目和环境配置并开始监测后，工作台显示本批采集文件的绝对路径，可选中并复制。

采集端先读取同一目录内的 `<批次 ID>.plan.json`，取得项目 ID、批次 ID、DUT ID 和已选业务。将上报追加到 `<批次 ID>.jsonl`，每行一个 UTF-8 JSON 对象，以换行结束。以下为 IPTV 的字段示例。使用时替换为本次计划中的实际标识、现场观测时间和原始结果。

```json
{"project_id":"项目 ID","job_id":"批次 ID","dut_id":"DUT ID","collector":"iptv","event_id":"stb-01-381","observed_at":"2026-11-22T09:15:30+08:00","outcome":"abnormal","detail":"机顶盒报告视频冻结 12 秒"}
```

`outcome` 可取 `healthy`、`abnormal` 或 `unknown`。同一次观测重发时沿用原事件 ID。工作台依据观测时间判断新鲜度，按 DUT 和业务分别计算成功率、连续失败和有效观测时长。检查记录保留现场观测与接收时间，整批记录可导出为 CSV。停报后的空白区间和每日人工检查单独保留，供工程师核对。

需要判断整机状态时，另行勾选「DUT 在线与启动状态」。此项固定使用现场采集，`collector` 填 `dut_presence`。采集端有明确设备证据时，用 `healthy` 上报在线、`abnormal` 上报离线；暂时无法判断时填 `unknown`。工作台逐台显示状态、最近设备观测和上次在线心跳。超出有效时间窗、采集文件中断或批次结束后，当前状态显示「未知」。

在线观测可附设备自身本次启动标识 `boot_id` 和实际读出的开机秒数 `uptime_seconds`。同一批次、同一 DUT 前后出现不同启动标识时，工作台记录一次已观测到的周期变化。「最近发现变化」显示采集端首次读到新标识的时间。样机重新出现但启动标识相同，累计值保持原数。可在检查历史和 CSV 核对每次原始上报。

在项目 A 的自动开关机挂测运行时，可以切到项目 B，核对 B 已保存的方案和通道，点击“开始测试”。两个项目分别占用各自的程控电源、通道串口和网卡。测试方案开启 WiFi 检测时还需占用本机无线资源。资源冲突会在启动前提示。切回 A 点击“停止测试”只停止 A，B 继续运行。其他类型的设备任务仍按工作台原有的并行限制执行。

Qt 工作台沿用原自动开关机执行器。每通道的启动等待从通电帧完整写入电源串口后开始。若串口写入异常或只写入部分字节，执行日志会记录通道与错误；同一电源队列停止下发后续命令。停止任务时，队列中尚未下发的动作会取消。完成写入表示串口驱动已接收该帧，实体电源输出仍需现场核对。

Windows Qt 便携包需要完整解压 `DUTPilot_portable.zip`，然后双击便携目录内的 `DUTPilot.exe`。启动前请退出已有工作台，以免打开请求转交给旧实例。源码启动方式见下文，正式使用仍按现场验收范围执行。[Qt 构建与验证](validation/pyside6_migration_20261118/QT_DIRECTORY_BUILD_REPORT.md)

Windows Qt 工作台的产品版本为 V1.3.0。可以使用项目工作台管理原项目，配置通道、查看串口，或从详情页进入原自动开关机及环境检查流程。源码启动使用 `python run_dutpilot_qt.py`。Qt 版本各项功能的自动化结果及现场待验范围见[迁移进度](validation/pyside6_migration_20261118/MIGRATION_PROGRESS.md)。

Qt 工作台的开关机轮次显示原引擎已确认的完成数。将鼠标停在通道卡片、切换列表或打开通道快照，可查看该通道最近上报的阶段。重试期间请同时核对已完成轮次与通道状态。关闭串口窗口时，若无法启动收尾线程，原监控与端口所有者继续保留，可在窗口内再次关闭剩余标签。其他已受理端口会继续收尾。若驱动报告关闭失败，相关串口继续受保护，退出原程序后重新打开项目可再次检查端口。

「运行概览 → 通道运行状态」的矩阵和列表只显示已启用的通道。可在「环境配置」启用或停用通道，保存后两种视图都会更新。矩阵卡片直接显示 VLAN 和 COM，例如 `VLAN116 / COM16`。只配置一项时仅显示该项。较长的名称可悬停查看完整值。显示任务快照时，卡片和列表均使用该任务的 VLAN 和 COM。

在 Qt 串口日志的通道输出区右键选择「查看串口诊断快照…」，可以查看采集时间、程序内监控与控制所有者、最近打开失败原因，以及已打开会话的近期接收内容。终端清屏后仍可读取会话保留的数据。快照窗口保留采集时的内容，需要更新时再次从菜单打开。关闭终端会同时关闭快照。

若串口日志或读线程未能启动，终端会报告实际错误。驱动确认关闭后可重试。若显示“关闭失败”，请记录通道、端口和错误信息，核实驱动状态；对应端口仍受保护，其他通道继续监控。

停止自动开关机后，界面先等待原业务退出。原业务明确回报用户停止时，任务历史显示「已停止」并保留原回执。若同时出现业务检测失败，或子进程超时被强制终止，任务历史保留失败及具体原因。

在主源码目录准备仓库外独立环境：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup_qt_environment.ps1 -WithBusinessDependencies
& "$env:LOCALAPPDATA\LineCheckAssistant\qt-dev-py39\Scripts\python.exe" .\run_dutpilot_qt.py --demo
& "$env:LOCALAPPDATA\LineCheckAssistant\qt-dev-py39\Scripts\python.exe" .\run_dutpilot_qt.py --showcase
& "$env:LOCALAPPDATA\LineCheckAssistant\qt-dev-py39\Scripts\python.exe" .\run_dutpilot_qt.py --workspace
```

`--showcase` 单独打开组件展示页。可以调整示例进度、切换状态，核对图标、颜色、卡片和日志。关闭窗口即结束预览。

工作台的项目树、项目卡、列表状态列和项目详情共用状态图标。项目树可悬停查看完整状态。处理异常时请以具体文字为准：「部分失败」表示全流程含失败项，「完成（含未校验）」表示预测试含未经结果校验的项目，「已确认手动重启」是人工操作回执。

项目卡、项目详情和新建向导用电源循环图标标示自动开关机，用心跳线标示全业务老化。测试类型和当前状态可分别按旁边的文字核对。窄窗口下可展开顶部工具栏右端的双箭头，访问「全局设置」和「项目」等收起的入口。

总览按已打开项目统计。同一项目的多个通道报错时，「需关注项目」只增加一个；正在运行的项目也可能需要关注。「最近任务已完成」表示最近一次任务已有成功回执，项目挂测验收请核对原始结果。用状态下拉框可在卡片和列表中查看对应项目。点击左侧「活动项目」可查看仍有活动任务的项目，点击「总览工作台」可重新显示全部项目。卡片上的「—」表示当前来源没有提供该项计数。

当前预测试上报判定结果后，成功数和失败数均以命令条数显示。开关机任务的「第几轮」来自原引擎的通道事件。重开项目后可查历史任务结果，缺少当次命令计数时显示「—」。

「测试模板」列出已打开项目的保存版本和草稿状态。双击或按 Enter 可查看源项目。需要复制时，使用原项目菜单的「另存为独立项目」。侧栏「设备管理」可查看缓存的设备和资源占用，需重新枚举时点击刷新。电源串口的占用记录只标识串口资源，逐通道占用和 DUT 在线状态需查看对应设备证据。

在底部全局实时日志选择项目，或选择「仅工作区」查看无项目归属的记录。可叠加级别和关键词筛选，再点「导出」保存当时匹配的缓冲记录。同名项目用项目 ID 区分；查看项目详情后返回总览，会恢复先前选择的日志项目。

`--demo`明确显示演示标记，不打开真实项目、不控制硬件。`--workspace`通过原服务新建/打开/保存/重命名/复制/关闭项目，菜单在顶栏“项目”和侧栏右键；也可在参数后显式传原项目文件或目录。保存/复制沿用原版本和独立项目身份，dirty草稿在关闭时仍需明确保存、放弃或取消。项目切换只切换页面。选择通道不等于正在运行，历史未完成记录显示结果未知，不会自动续跑或发送电源命令。

重复启动会将打开请求交给已有工作区。换用 Qt 前请先按安全退出流程关闭正在运行的旧版。通道诊断和监控可从「Ai助手」进入。

本机`%LOCALAPPDATA%\LineCheckAssistant`等旧数据路径保留，名称改变不会自动搬迁或清空数据。历史单项目版本按程序目录区分AI数据身份，移动程序目录的原有影响见AI数据章节。

## 多项目源码收尾与主程序验收（2026-11-17）

侧栏和本地AI项目查询共用运行状态：停止中、运行中、结果未知、失败、已停止及空闲。并行运行期间存在异常时显示`!`，悬停查看活动任务、未知数量和最近结果；切换项目不清除结果。最近结果由后续完成的业务更新，历史未知继续留存，设备占用随原任务收尾或旧进程退出而释放。预备测试未配置期望值时仍显示“未校验”，不冒充通过或执行未知。

## 统一工作台（2026-11-18，源码版，待Windows验收）

- 默认进入总览工作台。统计、项目卡片和列表读取已打开项目的真实任务状态；最近结果未知、未校验、失败、主动停止分别展示，不将进程存在或已勾选通道视为检测正常。
- 左侧按运行中/其它项目分组，可搜索、滚动和收起；卡片“查看详情”、项目菜单或侧栏均可进入项目。切换总览或项目不停止后台任务。卡片/列表选择保存为本机工作台偏好，不改变项目配置。
- 详情中的自动上/下电、样机升级、写样机参数、ONU注册、串口日志、DUT配置及Ai助手继续使用原入口；全局串口/网卡合并刷新和更新入口位于顶栏下方，操作当前显示的项目。各模块原确认及安全停止规则保持。
- 运行状态及通道概览在中央，配置摘要在右。“编辑配置”展开原参数表和通道选择，通过水平/垂直滚动查看完整VLAN/COM信息；折叠不丢弃输入，也不解除原运行中编辑限制。
- 底部执行日志可拖动高度、展开/收起，自动滚动默认开启；关闭自动滚动后仍继续记录。界面只保留末尾5000行且不超过1Mi字符，完整文件继续按原规则记录。清空日志只清当前显示，不删除日志文件。首页“工作区事件”是工作区事件摘要，完整设备执行日志仍在对应项目详情及文件中。
- 不同通道轮次不一致时总览显示实际范围；只有各通道轮次和目标相同时才显示比例。卡片的正常/失败是最近明确通道结果，未采集项不会默认计为正常。“开始于”是已有任务开始时间，不代表累计有效运行时长。
- 持续开机的“全业务老化”目前尚未实现，保留待接入；现有`aging.start`仍为开关机挂测。本轮不新增设备并行能力、重置/恢复任务或自动电源恢复，不改变测试周期、命令及PASS/FAIL标准。

当前源码验收使用 `python run_dutpilot_qt.py`。该阶段的 Windows/DPI 及长期挂测记录见[Phase 1报告与清单](validation/unified_workbench_20261118/PHASE1_REPORT.md)。

## 单实例多项目工作区（2026-11-17，源码版，待现场复验）

- 启动后通过左侧项目列表或顶部“项目”菜单新建、打开、切换项目。侧栏可收起；切换只改变显示，各项目的测试、升级、串口、写参、ONU、DUT及AI任务保留在原项目。
- 新建项目选择一个空文件夹，使用脱敏默认配置；打开已有项目选择该目录内的`project.linecheck.json`。最近项目、重命名、另存为/复制、打开项目目录、关闭及从最近列表移除均在项目菜单中；移除列表记录不删除文件。
- 正常退出工作台后，下次启动会按原顺序打开退出时仍打开的项目，并回到上次选中的项目或项目总览。若想下次从空工作台开始，请先关闭所有项目再退出。通过项目文件启动时，工作台会在恢复完成后选中指定项目。
- 如果项目已移走、被占用或目录中的项目身份已变化，工作台会继续打开其余项目，并在主执行日志中列出跳过原因。重新打开项目只恢复项目视图，设备测试仍须手动启动。
- 旧程序目录或`Auto_power_on_off_tool/config`通过“导入旧配置目录”导入到新的空目录，原配置不改写。配置与可识别AI历史保留；参数表复制到新项目，固件保留外部引用。导入的机器人配置保持停用；存在多份时通过“选择导入的接入配置”选择，再重启并在本机确认启用。旧审批、临时恢复操作及活动任务不会自动执行。
- “保存”或`Ctrl+S`提交当前项目配置；配置窗口中的“保存”也提交所在项目。通道及选项的原自动保存写入项目草稿，不覆盖已保存版本；未保存项目显示`*`，正式新设备任务启动前要求保存。测试项页面另有恢复草稿，可恢复暂时不合法的输入；恢复不启动业务。预备测试保留原“确认后使用当前页面输入”的独立语义。
- 运行任务固定使用启动时配置，运行中保存供后续任务使用。各项目的配置、日志、报告、停止信号、AI会话及权限隔离；相同通道编号可以并行，相同串口、电源、物理网卡、OLT或传输端点冲突时显示占用方并拒绝，不抢占。网卡身份或主机资源保护未就绪时不会放行相关设备任务。
- 模型账号统一加密保存在当前Windows用户的`%LOCALAPPDATA%/LineCheckAssistant/workspace/models`，各项目独立选择模型并保留会话；共用已确认案例库继续保留。更换Windows用户或电脑后重新绑定本机模型凭据与远程授权。
- 钉钉/飞书共用程序级连接。先在“项目 → 远程可访问项目”由本机操作员明确授权项目，再在远程发送`项目列表`、`切换项目 项目ID`或`项目 项目ID 问题`。本地切换不改变远程目标，原审批和回复继续归属原项目；撤销范围不取消已准入设备Job。统一网关沿用原实例身份和协议，在实例内使用同一项目选择语法。
- 关闭运行中的项目或退出程序需确认安全停止并等待收尾。重开后，工作台依据原执行进程和系统锁处理串口等旧占用，原操作结果保留在任务历史中。
- 工作台意外退出后，已经启动的开关机子进程可能继续执行。原子进程仍在运行或无法确认状态时，工作台保留资源保护，设备操作会提示实际原因。确认原子进程退出后自动释放失效占用，原批次仍显示「结果未知」。
- 项目目录内`draft`为恢复草稿、`revisions`为已保存版本、`runs`为任务配置快照、`history`为AI/业务历史、`ui`为项目界面状态、`inputs`为项目输入、`logs`为日志。项目整体复制、备份和移动时保留完整目录；使用“另存为/复制”获得新身份，不复制活动任务和授权。

### 命令行配置


   ```powershell

   python scripts/run_remote_gateway.py pair-code --scope-file "scope.json"
   ```

   钉钉和飞书都启用时使用`--platforms dingtalk,feishu`；只做隔离通信测试时省略平台参数，不连接机器人平台。配对码五分钟有效、单次使用；终端显示的码须私下交给目标实例操作员。

   ```powershell
   python scripts/run_remote_gateway.py pair-instance --url ws://10.8.0.2:18761 --vpn --name "测试机A/项目甲" --slot 1
   python scripts/run_remote_gateway.py show-instance --slot 1
   ```

   ```powershell
   python scripts/run_remote_gateway.py allow-instance --slot 1 --channels 1 --capabilities firmware.upgrade --confirm-local-scope
   python run_dutpilot_qt.py --gateway-slot 1
   ```

   同目录同时运行其它实例使用不同的已配对槽位，如`--gateway-slot 2`，不共用正在打开的数据库。实例更新程序可复用原槽位；每次启动生成新run_id，旧请求不能转到新启动实例。已准入业务不因网关断线或停止聊天而取消；关闭测试程序仍按原流程安全停止，崩溃后未知结果不自动重做。

默认测试项恢复先返回未保存草稿，确认内容后才按当前版本保存；全局重试间隔保留。消息推送配置合并保留未提供的密钥，首次目的地/密钥/提醒范围变更须本地审阅；试发仅向当前已保存且已审阅的目的地发送固定测试消息。报告可按版本接手排查，旧报告缺少目标时须明确关联并经本地审阅；案例可按版本启停或删除，根因和复测确认仍由真实操作员完成。明确指定多通道业务时由同一业务请求处理，已启动任务可独立查询。

启动返回业务任务编号，表示已准入而非升级完成。模型断线、工具超时、停止本轮排查或隐藏AI窗口不会取消合法运行的升级；明确要求停止业务时才请求原流程的安全停止。进程中断后的危险任务结果标为未知，不自动重刷。默认保留原升级收尾，不额外登录最终系统；结果明确是否回读版本，不能用旧快照证明当前状态。

三档权限、远程真实身份和设备范围、占用保护均保持。首次使用新的OLT/PON或解除未知结果须由本地负责人审核具体范围，不能由远程成员或AI自己批准。完全访问且已授权的范围不重复审查。参数表内容、目标绑定和固件SHA256会复核；同一轮的等价升级请求复用原任务，不能凭超时重刷。GUI确认弹窗返回后也会再次检查业务占用。

在发送按钮右键或Alt+↓菜单打开“业务任务与受控扩展…”，可查看独立任务详情、请求安全停止，或记录已经现场核实的未知结果。这里仅管理新业务接口启动的任务；旧GUI独立批次继续由原窗口查询和停止，尚未统一接管。所有窗口关闭/停止对话都不等于设备操作回滚。

受控扩展是本地负责人审阅的JSON业务模板，可组合固定参数/受限输入并绑定已实现业务的代码摘要、版本、风险、通道、有效期和次数。AI可在工作区准备模板，实际导入、核对摘要及批准在本地窗口完成；AI没有登记批准、提权或扩大范围接口。代码/schema变更、超范围、过期、次数耗尽或撤销会拦截执行。模板不能执行任意Python/PowerShell，也不能凭登记补齐尚未实现的底层业务，当前不构成系统沙箱。

接入业务runtime后，常规对话和自动监控不再开放任意PowerShell、自定义DUT Shell和任意文件写入，使用固定系统/网络/存储/进程/分区查询、原诊断工具、受控产物与正式业务。尚未提供等价业务的定制修改仍是矩阵中的待接入项，不能声称通用工具已全部等价迁移。配置写入暂限本地来源，拒绝旧revision及打开的编辑器；未提供的凭据保留，查询不返回密码。更新ZIP和生成参数表暂保存到项目业务工作区，不运行下载程序。

### Qt 聊天中的模型与用量

在空聊天窗口或空闲的普通会话中发送“你现在是什么模型？”，DUTPilot 会在聊天正文中回答当前配置的请求模型。此查询在本机完成，没有选择模型时会显示“未配置”。本地问答仅保留在当前工作区的临时显示记录中。

### 钉钉项目机器人排障（2026-11-14，源码版，待现场复验）

每个挂测项目目录可绑定一个独立的钉钉应用机器人，同时用于测试通知和文字AI排障。同一台电脑运行多个项目时，各项目分别创建应用并使用不同凭据；同群@哪个项目机器人，就由哪个项目实例处理。旧的自定义Webhook机器人只有推送能力，不能接收@消息，不能用其加签密钥代替应用Client Secret。需要能创建/发布应用机器人，并将它加入可使用的企业内部群。

配置步骤：

1. 在[钉钉开发者后台](https://open-dev.dingtalk.com/)创建企业内部应用，添加机器人能力，选择Stream消息接收模式，发布应用与机器人并设置可用范围；将机器人加入目标群。获取Client ID（AppKey）、Client Secret（AppSecret）、Robot Code，以及该应用机器人入群后的群Webhook和加签密钥（如有）。每个项目分别配置，不能让多个实例共用同一应用凭据。
2. 打开“Ai助手 → 远程管理 → 钉钉”，填写应用凭据与新应用机器人的群Webhook，点击“保存应用配置”。这会同时将现有测试通知的Webhook/加签密钥切到新机器人，保留通知开关和@所有人；已打开的“测试项配置 → 消息推送”页同步新地址和密钥，保留其它未保存输入及原有未保存提醒。保存后重启程序，使当前项目改用独立AI数据。
3. 重启后重新进入钉钉子页签，点击“开始绑定群”。五分钟内在目标群发送 `@项目机器人 绑定 页面显示的绑定码`，回到本地核对群名称与群ID，再点击“确认绑定”。绑定过程不会调用模型或操作设备。
4. 勾选“启用指定群 AI 排障”，确认该群所有成员可以调用当前项目排障工具且回复发送到该群。后台连接不需要打开AI窗口，也不需要公网IP或端口映射。可使用“测试项配置 → 消息推送”的“发送测试消息”检查测试通知；AI收发需另发排障问题核对。

首条问题可以发送 `@项目机器人 通道3 检查刚才断网的原因`，后续发送 `@项目机器人 继续检查`。也可直接描述问题，通过对话确定通道或“本机电脑”；普通问答无需设备目标，设备目标不明时追问。设备范围为当前项目已勾选且有效的通道；目标配置、模型或挂测批次变化后自动选择匹配会话或新建，旧记录保留。模型须在本地保存并选择，执行工具还须通过现有工具能力验证。

支持 `帮助`、`状态`、`通道 N`、`新会话`、`停止`、`批准 编号`、`拒绝 编号`。群里的每位成员、每个目标分别保持连续会话，本地工作台可查看带“钉钉”来源的历史和处理具体批准；本地新提问使用独立的本地会话。“停止”只停止该成员当前会话的本轮AI排障，原挂测继续；运行中追加问题会明确提示未排队。首版不接收图片、语音或附件，也不增加整套挂测远程启动/停止接口。

钉钉新会话默认“帮我批准”，不继承本地记住的完全访问偏好。普通操作独立AI审查后执行；危险、风险不明或审查失败的操作在群里展示具体内容与编号，由原发起人发送明确批准/拒绝指令，或在本地处理。编号十分钟内单次有效，停止、内容变化、目标/模型/批次变化和重启后不能继续使用。特别长的操作内容要求回本地核对完整内容。本地仍可为该会话选择三档权限，完全访问必须按原流程确认，且授权只在本进程有效；通用系统操作可能影响同机其它项目。

项目AI数据位于当前Windows用户的 `%LOCALAPPDATA%\LineCheckAssistant\projects\<程序目录身份>`。首次保存只复制旧库中的模型配置、加密凭据、所选模型及容量缓存，不复制会话/报告、监控设置、待恢复任务或完全访问授权；之后各项目独立维护。已确认案例由下述本机共用库统一维护，不随项目隔离。旧数据库保留，工作台不再提供旧库历史查看入口。当前项目的历史对话通过“排障会话”下拉框切换，并通过“管理会话”管理；报告通过“诊断报告”查看。停用接入后仍使用该项目独立库；移动或重命名程序所在目录会形成新的项目数据身份，需要重新配置，旧数据仍留在原位置，共用案例库不受影响。

新增Client Secret使用当前Windows账号DPAPI加密保存，不能直接复制到另一台电脑或另一Windows账号使用。群回复过滤已知模型、机器人和设备凭据；主程序本地日志规则保持。重复回调不会重复执行，程序重启不会自动重放待处理指令；回复失败或发送结果未知时查看本地工作台与主执行日志，不会因此重新执行设备命令。停用接入会停止接收并取消钉钉排障，等待必要恢复；退出程序会等待后台线程收尾。

首次仅需安装更新后的项目依赖；本轮源码改动不包含新EXE。真实钉钉收发、应用机器人测试通知、完整Windows界面及实际模型/设备操作仍须现场复验。

1. 在飞书开放平台创建企业自建应用，开启机器人能力，申请 `im:message.group_at_msg:readonly`（群内@消息）、`im:message.p2p_msg:readonly`（单聊消息）和 `im:message:send_as_bot`（应用发消息）权限。设置需要使用机器人的应用可用范围，发布并完成企业管理员要求的审核。无需申请读取群内所有消息或通讯录权限。
2. 在飞书子页签填写App ID（`cli_`开头）、App Secret，点击“保存应用配置”。秘密按当前Windows用户加密保存在本项目AI数据目录，首次打开或重启后Secret留空，留空保存会保留原值；仅隐藏再打开会保留未保存输入。首次准备项目AI库后需要重启程序；模型配置可从原库导入，会话、报告和权限保持项目隔离，案例按当前共用案例库规则使用。
3. 在飞书应用后台订阅“接收消息v2.0”（`im.message.receive_v1`），订阅方式选择“使用长连接接收事件”。若后台要求先建立连接，可在程序中点击“绑定群…”或启用单聊，待动态状态显示已连接后保存订阅，再发布应用配置。长连接只需本机能访问飞书公网服务，无需公网IP或端口映射。
4. 将该应用机器人加入目标群，在程序中点击“绑定群…”，五分钟内在目标群@**该机器人**发送动态状态中的“绑定 编号”。本机收到申请后核对群ID，点击“确认绑定”；绑定本身不会启用群排障或自动通知。绑定期间可点击“更多操作 → 取消当前群绑定申请”，关闭配置窗口也会取消当前申请。业务菜单仅通过点击“更多操作”按钮打开，页面右键不弹出该菜单。
5. 按需分别勾选“启用指定群 AI 排障”“启用单聊 AI 排障”“启用飞书测试通知”，三项默认关闭。群排障仅接收已绑定群内@本机器人的文字。单聊启用需本机确认，允许此自建应用可用范围内的所有企业成员调用当前项目排障工具，不要求逐人绑定。群聊与单聊会话独立，单聊结果只回复原单聊。
6. 点击“更多操作 → 发送飞书测试消息”验证绑定群收信；手动试发不受自动通知开关限制，不依赖模型或AI排障开关。自动通知与现有挂测通知触发点一致，分别发送项目、通道和完成/异常结果，不附远程工具名称、识别码、验证码或设备命令。项目名读取“项目信息”已保存的磁盘值。钉钉和飞书均启用时分别发送，任一平台失败不改变原测试结果；接口接受后仍需在群中核对实际收到。

在本地AI工作台保存并选择模型；设备排障时需勾选有效目标。群内@机器人或在单聊发送“通道3 检查断网原因”。后续问题沿用此人在该聊天中选择的通道；支持对话切换、新建或切回通道及本机电脑会话；设备目标不明时会在对话中追问，不默认选择第一个。支持“帮助”“状态”“通道 N”“新会话”“停止”“批准 编号”“拒绝 编号”。会话按平台、应用、企业、群聊/单聊、人员和通道隔离；本地可查看历史和处理具体批准，本地新提问使用独立的本地会话。

新飞书群聊/单聊会话默认“完全访问”，有效目标内的本机命令、文件读写及设备操作（包括登录、升级、重启、恢复出厂、供电和系统/网络修改）跳过独立审查和常规逐项批准；群/单聊启用确认显示访问及回复范围。本地可为会话降低权限，并单独记忆飞书的新会话偏好，不影响本地和钉钉。降低权限后，危险或不明操作按所选规则由发起人对具体编号批准；结果不明的同一操作重试，即使完全访问也须具体批准。编号绑定原聊天、会话及操作指纹，十分钟单次有效；本地与飞书批准只能成功一次。设备/共享资源占用保护及停止保持；AI回复过滤已知凭据，正文过长分段，发送失败不重新执行工具，内容可在本地工作台核对。

飞书回复排版（2026-11-15，源码版）：AI正文、状态和批准提示统一使用富文本，支持加粗、标题、列表、引用、行内代码及代码块。项目、通道和成员独立显示在标题中，单条回复不再显示`[1/1]`，长回复分段时才显示编号。状态与权限分段展示，批准消息按原因、操作、JSON参数和批准/拒绝编号分区，操作员仍回复“批准 编号”或“拒绝 编号”。仅省略独立的“本轮恢复状态：无临时修改”消息；实际恢复结果、恢复失败、未恢复、结果待核实及通用操作不自动回滚提醒继续显示，完整记录保留在本地工作台及日志。部分富文本样式需要新版飞书客户端，桌面端和手机端显示、代码复制效果仍待现场复验；测试结果通知格式保持原有方式。

停用群排障只取消本项目飞书群会话，停用单聊只取消飞书单聊会话，钉钉及原挂测继续。修改应用凭据前须关闭三项开关、取消绑定申请并等待连接、会话及通知清理；更换应用或Secret会清除群绑定。程序退出会取消排队消息并等待正在进行的网络请求和必要清理；重复事件不重复执行，重启不重放中断的远程操作。同一App ID在本机不能由多个项目同时建立长连接，避免飞书集群模式将消息随机投递给其它项目。

源码依赖新增固定版本 `lark-oapi==1.7.5` 及配套HTTP/加密依赖，请按项目依赖安装。现有EXE尚未包含本功能，后续标准构建须通过全部原门禁。完整Windows源码界面、真实飞书群/单聊收发、通知、模型及DUT联动仍待现场复验。

飞书重连提示（2026-11-16，源码版）：持续连接失败或断开时，主界面只提示本轮首次失败；后台仍自动重连，穿插“正在连接”或其它日志不会反复打印同一失败。真正恢复后显示一次“飞书连接已恢复”，之后再次断开可重新提示。正常首次连接仍不显示成功详情；连接停止后重置去重状态。每次连接尝试及失败的原始记录仍完整保存在本次主日志文件中，远程管理页动态连接状态照常更新；其它飞书错误继续显示。重启源码程序后生效。

### 诊断证据与本地日志

样机稳定性排查（2026-11-14，源码版）：自动诊断和对话排障会从已留存的本次目标材料中优先选取首次故障、相关原文及最新状态，整理panic、Oops、OOM、watchdog、启动序列、复位原因和上下电操作的文本线索。长日志优先保留线索附近及末尾，标记省略和片段位置，完整留存原文仍可由AI通过证据检索核对；主执行日志记录选取数量、来源、截断及资料命中情况。案例仅使用已人工确认且启用的记录，操作员说明只提供相关命中章节，未命中不补入无关内容。

这些线索不是已确认根因。AI应分别核对故障时、当前查询和恢复后的状态，区分计划上下电/升级与未解释的重启；采集时间、日志时间和内核相对时间分别说明，不假定时钟同步。串口无输出不能单独证明卡死，网络失联不能单独证明重启，OOM或watchdog记录不能直接判定整机重启或硬件故障。启动异常以最后有证据的阶段为准，命令不支持属于取证限制；深入定位调用栈可能需要准确固件版本和匹配符号。缺少证据时明确说明尚未确认及下一步验证方法，恢复正常与根因确认分开记录。

本轮不增加串口自动打开、持续采集或新的自动诊断触发。需要故障前后的串口现场时，请提前沿用现有串口日志功能打开目标监控，或在聊天中导入保留的文本日志；未采集的现场无法事后还原。现有取证工具、模型额度、三档权限、设备占用及停止规则保持。重启源码程序后生效；真实模型效果和真实样机仍待负责人复验。

主界面AI日志（2026-11-15，任务摘要）：正常排查保留开始和本轮结束摘要；开始提示注明已入队，结束不等同于排查成功。案例正常初始化、会话路由/自动授权、已知历史会话资格提示、证据来源及选取/截断统计、重复采集状态和工具额度提示不再刷屏。AI登录过程、实际命令、操作下发及无异常的逐项完成记录均收起，详细原文仍保存在本次主日志文件。正常临时操作恢复缩为简短收尾，执行过通用操作时保留“不自动回滚，待核实结果请人工核对”的提醒。

串口诊断结果保留一行，例如“COM16 串口诊断完成；已枚举；程序内已打开”，不再展开全部端口、PnP和驱动JSON；已枚举不代表可正常打开。枚举/PnP查询失败、打开错误、控制占用、关闭中及电源串口冲突仍有简短提示，PnP异常显示数量，完整原因和明细见本次主日志文件。已知连接失效提示缩为“连接失效，已下发结果待核实；不自动重试，请重新查询确认连接”，同一操作结果内重复的未下发说明只显示一次；不同采集/操作事件分别保留，不根据显示文字改判下发状态或执行结果。已隐藏的正常工具提示继续隐藏。

待批准、等待用户回答、失败/拦截、结果未知、停止、恢复待完成，以及容量读取失败、裁剪/重试和未知资格异常继续显示。对话与自动监控的批准、非普通风险审查和异常结果显示简短摘要；即使操作标为完成，只要存在错误、非零返回码、标准错误、输出截断或清理未确认仍显示，并使用错误/警告色。标准错误仅显示首行最多240字符，省略时注明完整文件位置。两处监控状态显示继续实时更新；钉钉/飞书AI正常连接和收发过程收起，启停、绑定、批准、断线重连和发送失败仍显示。只收起已识别的正常事件，未知格式和JSON解析失败时继续显示；命令正文即使包含换行或“失败”等字样，也按命令明细收起，不将正文当作实际执行异常。

主日志文件继续完整保存上述AI原文，包括界面隐藏的信息、操作JSON、文件正文和完整输出（执行器自身的输出上限保持）；已登记模型API密钥继续在进入日志前过滤。开关机WiFi测试继续沿用既有摘要和落盘规则；DUT日志按上文分流。重启源码程序后加载本次显示调整，AI窗口固定状态和上下文用量区保持。

### 排障工作台（2026-11-12）

新会话（2026-11-17，源码版）：右键发送按钮（或在该按钮按Alt+↓），选择第一行“新会话”，即可使用当前已保存模型创建并切换到空白普通对话。旧会话和后台任务保留，新会话不带入旧目标、聊天、报告或排查进展；目标由之后发送的问题确定。当前发送模式及输入框未发送的文字保留，输入框重新获得焦点。创建本身不调用模型或操作设备；正在识别上一条消息时暂时不能新建，缺少模型配置或创建失败会提示错误并保留原选择和输入。

连续诊断（2026-11-15，源码版）：右键发送按钮（或在该按钮按Alt+↓），选择“连续诊断（仅定位与建议）”，再输入本机故障或单个设备通道的问题。按钮变为“发送连续诊断 ▾”；同一菜单可以查看本会话排查进展或切回常规对话。默认保持常规对话，所选发送模式独立记忆，不改变原三档权限。多样机任务使用常规对话，远程入口与自动监控沿用原流程。

连续诊断会根据取证结果调整检查方向，保留检查步骤、已有证据、观察笔记和用户纠正；观察笔记仍须核对原文，不代表根因已经确认。每次最多24轮模型取证交互、48次工具请求、10分钟，并可追加一次无工具总结；在安全检查点发现连续三次失败/重复结果/空检索或预算用尽时，停止新增取证并说明缺口与建议。已开始的只读命令按原超时/停止机制结束，不因任务预算强杀其它操作。需要接线、指示灯等现场信息时等待你的回答，回答后发送即可继续；重启程序不会自动恢复执行。

该模式只允许固定只读取证、已有材料检索和有界文件读取，首次设备登录仍遵守原确认。即使选择完全访问，也不执行通用Shell、配置写入、重启、升级、抓包、日志跟踪或内核Debug；修复建议由你决定是否另行操作。运行中可以继续发送补充或纠正，下一安全节点采用，已开始的只读检查不会被强制中断；尚未开始的旧检查会跳过。待处理补充最多8条、合计65536字符，停止/异常也保留已接收原文。

普通问答、排障对话及连续诊断默认使用Chat Completions或Responses流式正文。本地边生成边显示，完整响应校验通过后才执行工具，不执行参数碎片；异常中断保留带“回复未完成”标记的正文，仅供查看，不作为完整结论或后续模型上下文，不自动重发模型请求。接口忽略流式参数而返回完整JSON时仍可正常工作；接口明确拒绝流式请求时显示失败，切换常规/连续诊断不会改变流式设置。模型API密钥继续过滤，材料及证据仍按既有信息发送范围处理。模式、检查、跳过、结束与异常详情写入执行日志，主界面保持任务摘要。

### AI流式回复与远程卡片（2026-11-17，源码版，待现场复验）

- 本地回复保留Markdown、滚动及复制；正在底部阅读时自动跟随，向上查看历史时保持位置。流式只展示正文，不展示模型内部思考。停止本轮后的部分内容标记未完成，已有业务任务继续按其原有取消规则处理。
- 飞书默认直接接入的群聊和单聊使用同一张卡片持续更新正文。应用需拥有原消息发送权限及`cardkit:card:write`（创建与更新卡片）权限，权限变更后在飞书开发者后台发布应用。正文完成或生成失败时收尾卡片；没有卡片权限时沿用原富文本完整回复。
- 钉钉默认直接接入的指定群在“远程管理 → 钉钉”的现有配置表单中增加可选“AI 卡片模板 ID”。在钉钉卡片平台创建并发布AI卡片模板：流式Markdown组件绑定字符串变量`msgContent`，使用AI模板的`flowStatus`状态变量；标题组件可绑定`title`。为机器人应用申请创建/投放卡片及AI卡片流式更新权限（`Card.Instance.Write`、`Card.Streaming.Write`），发布权限变更，再停用接入、等待清理、保存模板ID并重新启用。模板ID留空兼容旧配置，继续完整文字回复，不影响原群绑定或测试通知。
- 两个平台每张卡片约每秒最多刷新一次，正文完成立即收尾；长回复分段显示，已完成段落不重复刷新。状态、批准编号和测试通知继续使用原流程。远程外发仍过滤已知凭据，未接收完整的凭据前缀不会随流式片段发出。
- 缺少模板/权限或卡片接口明确拒绝时，自动降级完整回复并记录原因。投递/更新超时、结果未知或进程中断时，保守记录`unknown`并提示本地核对，不自动重复投递或重新执行排障工具。若最终正文已被接受而仅卡片状态收尾被拒绝，只提示收尾异常，不再重复正文。停用、换群或代次变化后不再向旧聊天更新卡片。

- 选择“全包升级 + Tftp指令”后，只显示可调的并行数 Spinbox（1–8）；程序始终按该并行数完成即补位，单台失败不会停止其它样机。程控电源 COM 帧仍按通道串行发送，后续 Boot、TFTP、重启等待和最终登录可并行。每台 TFTPy Server 及其后续数据传输 socket 都严格绑定当前 VLAN 的 PC IP；设置网卡 IP 后会最多等待 15 秒，直到 Windows 确认该 IP 可绑定，仍不可绑定才报网卡/重复 IP/驱动错误，不回退到 `0.0.0.0`。所选固件映射为设备固定请求名 `tclinux_allinone`，设备仍执行 `tftp <通道IP>:tclinux_allinone`。
- 选择“全包升级 + Tftp Put”后，程序先对当前通道下电再上电；上电帧下发后等待 1 秒稳定，随即循环发送回车，检测到 `UserName:` 后按 boot 账号 `telecomadmin / nE7jA%5m` 登录。随后仍由 TFTPy Client 从当前通道 IP 上传到固定设备 `192.168.1.1:69`，并绑定该源 IP，避免多张 `.1` 网卡造成错误选路或启动变慢；远端文件名使用所选固件 basename。上传后同样观察 90 秒 Boot/Bood 标记：检测到则发送 `reset`，未检测到则对当前通道执行后备下电再上电；后备上下电沿用普通电源默认时序，不使用首轮进入 boot 的 1 秒/1 秒专用时序。未勾选恢复出厂时，完成 reset 或后备上电后仅等待 3 秒即结束当前通道，不登录最终系统；勾选恢复出厂时才保留 120 秒等待、最终系统登录及恢复出厂。该流程同样始终按 Spinbox 的并行数运行，单台失败不会停止其它样机，共享程控电源 COM 由 coordinator 复用同一长连接。
- `Tftp指令` 和 `Tftp Put` 均可在执行窗口的 Spinbox 调整并行数 1–8 台（默认 2，存于 `sample_upgrade_settings.ini` 的 `parallel_count`）；全包升级全程不临时改写 `Auto_power_on_off_tool/config/network_card_ip.ini`；所有串口和 TFTPy Client/Server 都由本程序在 `finally` 中关闭，不查找或关闭外部 CRT/Tftpd 进程。一次并行批次内共享的程控电源 COM 由 `UpgradePowerCycleCoordinator` 持有长连接 `ProgrammablePowerSupply`，仅在首台样机上下电前打开一次，最后一台完成后由 `coordinator.close()` 关闭，避免逐台反复 open/close。
- 全包升级进入 boot 前，`Tftp指令` 与 `Tftp Put` 的程控电源时序统一为“关闭当前通道 → 等待 1 秒 → 开启当前通道 → 等待 1 秒 → 立即放行串口循环回车”；不会再补足 10 秒启动等待或叠加第二个 1 秒等待。主执行日志会输出上电稳定完成及开始进入 boot。该调整只用于样机全包升级，普通自动上/下电等其他电源流程保持原有默认时序。
- `Tftp指令` 仍以串口的 `done` 与 `write` 同时出现作为设备处理完成判据；`Tftp Put` 则以 TFTPy 上传成功作为传输完成判据。两条路径传输后均观察 90 秒 boot 标记：`Boot/Bood` 后延迟 1 秒发送一次 `reset`，未检测到时已配置程控电源则对当前通道执行一次后备下电再上电；后备上下电保持普通默认时序。**未勾选恢复出厂**时，完成 reset 或后备动作后只等待 3 秒，记录当前通道升级完成并跳过最终系统登录。**勾选恢复出厂**时，才等待 120 秒、执行最终系统五次登录重试，再按“命令→1 秒→回车→8 秒”执行恢复出厂；最终登录只能由独立的 shell 提示符行判定成功，密码回显中的 `#` 或 `>` 不会触发恢复出厂。仅当实际发送恢复出厂命令后，主程序执行日志才显示 `TX firstboot -y;reboot`。未配置程控电源时会记录跳过后备上电；未勾选恢复出厂仍等待 3 秒后结束当前通道。
- `Tftp指令` 在样机串口同时出现 `ARP Retry count exceeded` 与 `U-Boot>` 提示符时会自动重发同一 `tftp` 命令，最多 3 次、每次间隔 1 秒；单次等待窗口 5 分钟，由按秒轮询替代阻塞 `wait_for_all`，避免已知快速失败场景消耗完整超时。每次重试和最终成功/失败都会写入主程序执行日志，例如“检测到 ARP Retry count exceeded...，剩余 2 次自动重试”、“自动重试 TFTP 命令：第 2/3 次发送...”、“TFTP 命令在第 2 次尝试时检测到完成标记”或“TFTP 命令已重试 3 次仍未成功...”。仅 `ARP Retry count exceeded` 但未回到 `U-Boot>`（样机仍卡在 Loading）时按普通超时处理，不重试。
- `Tftp指令`、`Tftp Put` 和 `web打开网关` 的传统账号 Boot 登录统一采用同一流程：上电帧后的1秒稳定窗口结束后立即开始探测，每发送一个回车最多等待1秒查找完整 `UserName:` / `User Name:`；命中后暂停探测，再观察1秒确认未提前出现 `Password:` / `Passvord:`，若提前出现则丢弃本轮并重新探测。确认后发送用户名，等待1秒再发送回车，最多等待30秒查找密码提示；发送密码后等待1秒再发送回车，最多等待20秒查找 `#` / `>` Shell。用户名和密码回车后分别从新游标读取响应；失败沿用默认600秒外层尝试窗口重试，等待密码提示超时且响应含解码乱码时保留一次补发密码的既有补救。主执行日志记录开始及登录结果，串口日志记录实际收发；SDMC方式和各自传输/收尾保持原行为。
- 主界面“串口日志记录”已改为内置多通道终端：按 VLAN/COM 分页实时显示、开始/停止、清屏、手动命令发送和日志保存。每个Tab优先打开该通道“通道对应 COM口”的实际选择；历史配置没有`serial_port`时才按`vlan{N} → COM{N-100}`兼容推导。手动打开、“打开全部”、全流程预启动以及自动升级附加日志使用同一映射。“打开全部”会依次启用窗口当前全部 VLAN/COM Tab。每个 Tab 底部保留命令输入框、「回车」和「清屏」，不再显示「发送」按钮；输入框按下 `Enter` 发送输入文本并自动追加回车，输入框为空时只发送回车；点击「回车」只发送空回车，不发送输入框中的文字。两种发送方式成功后都会清空输入框；自动升级占用某通道时仍显示输出，但手动发送（含按 Enter）被锁定；高频串口输出以最多约每 33ms 一轮的节奏渲染，只有当前 Tab 实时重绘，其他 Tab 切换后显示最新缓冲；每个 Tab 的屏幕只保留最近 5000 行，避免长时间高频输出导致 Tk 无响应。屏幕缓冲超过 64KiB 时会提示已合并字符，但原始日志始终完整写入磁盘；日志文件名按打开监控当日保存为 `vlan名_COM口_YYYYMMDD.log`，例如 `vlan112_COM12_20260808.log`，手动打开、“打开全部”和全流程预启动必须记录实际选择的COM；文件内每个落盘行都以 `YYYY-MM-DD_HH:MM:SS` 开头并保留 RX/TX/STATE/ERROR 方向，例如 `2026-08-08_19:12:10 RX 打印内容`，半行分包会先拼接，不会重复添加时间戳；全包升级自动打开的终端会在本批串口释放并写入关闭状态后自动关闭，手动打开的终端不会被自动关闭；`reboot`、`reset`、`firstboot`、`tftp`、`upgrade` 类手动命令需要二次确认；默认日志目录或本机终端状态文件不可写时会弹出明确错误提示。

- 已注册ONU批量删除：查询后默认全部不选，“全选”“取消全选”与“查询已注册 ONU”在同一行；下方紧凑列表显示接口、SN、类型模板和状态及已选数量，支持滚动和逐台勾选。只处理当前PON，含在线和离线ONU。点击“删除选中 ONU（危险）”后，在可滚动的完整名单中核对OLT、源IP、PON、数量与目标身份；确认默认取消，删除在线ONU会立即中断业务。按列表顺序逐台独立登录，删除前核对接口和SN、删除后回读；SN缺失跳过，身份变化、CLI拒绝或回读失败记录后继续下一台，登录/通信故障、超时或手动停止则结束批次。下发后未完成回读的目标显示“结果待核实”，不自动重试。结束后逐行保留成功、失败、未执行及原因，清除勾选并锁定名单，需重新查询才可继续；未勾选目标不会处理。连接资料、型号或管理PON变化会清空旧名单，运行期间锁定相关操作。全程不执行write、不接入全流程自动删除；C300注册失败后的离线清理仍限明确单台，批量注册仍禁用清理。
- 为每个通道选择实际接入的 Windows 网卡名称。
- 网卡列表优先读取 `Get-NetAdapter -IncludeHidden`，可显示禁用、断开和隐藏网卡；界面显示状态，例如 `[Connected]`、`[Disconnected]`。
- 保存每个通道的 PC 静态 IP、样机管理 IP、子网掩码、启用状态。

## 样机升级：停止升级（2026-10-14）

- “停止升级”位于“开始升级”旁，覆盖页面升级、Tftp指令、Tftp Put 和 web打开网关。仅升级运行时可点击；点击直接请求停止，不弹确认框。
- 状态立即变为“正在停止”。排队样机不再启动，当前样机在安全步骤退出；等待资源释放期间不能再次升级。关闭窗口不停止批次，重新打开后可查看状态并停止。
- 正在进行的电源下电/上电组合会完成；正在传输的 TFTP 或 HTTP 请求保留至返回、失败或原超时。Tftp指令已发送时保留当前完成标记等待，但不再自动重试。页面升级已触发时继续只读观察升级状态至成功、失败或原超时。
- Web 已点击提交时，仍完成固定30秒等待，并等本次上传请求结束或原超时后关闭本次专用浏览器和代理。未观察到上传请求时最多使用600秒传输等待预算；已开始的请求遵循其原网络超时。等待结束不代表设备固件写入成功。
- 停止后不再发起 reset、后备上下电、最终登录和恢复出厂。已经开始的设备命令无法撤销；日志会注明“已提交/已下发，设备结果待确认”。正在停止时不要依靠重新启动批次来判断设备已完成刷写。
- 完成摘要区分成功、失败、已停止和未开始跳过；“已停止”不是“升级成功”。主执行日志保留每个通道的停止位置、跳过项及汇总。
- 样机升级保留独立入口和本窗口“停止升级”；全流程不再包含升级，主界面“停止测试”继续用于当前全流程。独立启动的升级不受无关全流程停止影响。
- 新增停止功能已完成模拟设备回归；Windows源码版按钮布局/关闭重开及真实样机各阶段停止，仍待项目负责人现场验收。

## 验收步骤

1. 启动软件后，确认界面能列出 `network_card_ip.ini` 中已有的 `channel_1`、`channel_2` 等通道。
2. 点击“刷新串口/网卡”，确认下拉框里能看到当前 PC 的网卡名称，例如 `a虚拟网卡2口`。
3. 选择一个通道，填写：
   - 样机接入网卡
   - PC 静态 IP
   - 样机管理 IP
   - 子网掩码
   - 是否启用
4. 勾选或取消勾选通道，确认 `Auto_power_on_off_tool/config/network_card_ip.ini` 立即更新，并且只保留已勾选通道的 `[channel_x]` 配置节。
5. 人工接好线路后，点击“自动上/下电”，选择程控电源 COM 口和操作类型（默认“上电”），并确认影响通道。
   - 选择“上电”时，软件会按勾选顺序发送开启帧，相邻帧间隔 1 秒，且不会先关闭任何通道。
   - 选择“下电”时，软件只会向勾选通道发送关闭帧，相邻帧间隔 1 秒，不会发送全部断电帧。
   - 确认后主程序直接发送程控电源串口帧，不会启动旧 EXE 或点击外部 GUI；最后一条帧后不额外等待。
6. 回到新软件，点击“检查当前通道”或“已上电，开始检查全部启用通道”。
7. 观察日志：
   - 通过：显示 `[通过] channel_x ping xxx 成功`。
   - 失败：显示通道、网卡、PC IP、样机 IP，并提示检查上电、网线、接错口、IP 配置。
8. 打开“样机升级”，选择“页面升级”，确认已勾选通道都有 PC 静态 IP 和样机管理 IP，选择固件后点击“开始升级”。
   - 软件会二次确认将通过 UBUS 上传固件并触发升级。
   - 软件会先启用目标通道对应网卡；如果启用失败，会在日志和失败弹窗中提示。
   - 日志会显示每台样机的 HTTP/HTTPS 登录、上传、升级状态和重启上线结果。
9. 打开“写样机参数”，先使用“生成批量参数表...”为已勾选 VLAN 生成 Excel 表，或选择已有 `.xlsx` / `.xlsm` / `.xls` / `.csv` 参数表；确认预检清单中的 VLAN、COM、MAC 一一对应。
   - 并行数可选 1–8 台，默认 1；修改后会保存，下一次打开“写样机参数”会恢复上次关闭前的有效值，不影响“样机升级”的并行数。
   - 点击“写入参数”后，确认框会提示清空参数、工厂模式和两次重启；仅在确认后才实际下发命令。
   - 现场先以 2 台独立 VLAN / COM 样机验证，确认每台写入后读回校验成功、密码明文便于核对，并确认设备已完成退出工厂模式后的重启。
10. 打开“测试项配置”，可加载并编辑 `Auto_power_on_off_tool/config/test_project_config.ini`，并在“开关机运行参数”页编辑 `config.ini [ui_defaults]`，详见下方「测试项配置窗口」。

### 单次预备测试

1. 在主界面勾选目标通道，配置各通道网卡、PC 静态 IP、掩码及样机管理 IP。
2. 打开“测试项配置”，填写 Telnet 登录参数，在“测试项”页点击“执行全部命令（预备测试）”。检查确认框列出的全部目标后开始。
3. 使用当前页面内容（包括未保存修改），按通道列表和命令列表顺序执行。每条命令只下发一次，忽略正式测试的重试次数及间隔，不自动保存配置。
4. 沿用现有多段期望、`&&` 和否定匹配；单条不匹配或回显超时标红后继续下一条。无期望时显示“未配置结果校验”，不计为成功；登录失败、连接中断或网络准备失败终止当前设备，继续下一个已确认目标。
5. 主界面日志记录源/目标 IP、下发命令、设备回显、逐条结果及汇总，成功绿色、失败红色，未校验/停止黄色。内容自动追加到当前主执行日志文件（文本文件保留时间戳和状态文字，不保存字体颜色）。
6. “停止执行”阻止后续命令与目标；已经下发的命令无法撤回。连接或网络操作退出后恢复按钮，汇总已执行与未执行数量。运行时关闭配置窗口或主程序会先请求停止，待日志保存后再关闭。

预备测试会按目标配置准备网卡并登录 Telnet；请保证设备 Telnet 已开启。登录成功提示符为 `>` 时，先发送当前 Telnet 页的“登录后命令”一次并等待 1 秒，再执行测试命令；确认框会列出该登录后行为，空值仍发送一次回车。它不触发电源、WiFi、升级或正式开关机测试流程；实际设备行为由当前页面中的命令决定。

新版预备测试、测试项执行和项目信息查询在登录成功提示符严格为 `>` 时，连接后直接等待设备主动输出的用户名提示符（包括已经收到的历史内容），不先发送回车，避免 CMS 将其当作空用户名。主日志依次提示等待用户名、用户名已发送、密码已发送（隐藏）和等待 `>`；密码后出现空行或 `Entering CMS CLI:` 不影响匹配。未收到提示符时按原超时结束，不盲发账号或额外回车。`#` 等其它提示符继续使用原登录起始方式；本次不改变共享连接超时、换行或登录后命令规则。

  1. **环境线路检查**—— 至少选择一个启用通道，填写 VLAN、网卡、PC IP、样机 IP；逐通道按需准备网卡并 Ping 样机，任一通道失败停止后续任务。
  2. **串口日志（全流程期间持续记录）**—— 勾选后在全流程开始时先显示多 VLAN 终端并执行“打开全部”，记录后续环境检查和开关机测试；串口打开失败记入日志，不阻止后续任务。
  3. **执行开关机测试**（默认不勾）—— 不启动旧工具 GUI 或 EXE，在独立无 GUI 子进程复用旧 Start All 的 Telnet/SSH、程控电源和通道业务。参数来自当前 `config.ini [ui_defaults]`、当前测试方案和 `network_card_ip.ini`；只启动新工具当前勾选通道。启动旧业务前，按当前选定方案“项目信息”中已保存的三项版本基准决定是否预检。三项去除首尾空白后全部为空时，确认框和主执行日志明确显示“三项版本基准均为空，跳过开始前版本校验”，不建立预检 Telnet 连接、不下发预检登录后命令或版本查询命令，继续原开关机测试流程；项目名称不参与判断。部分填写时提示缺少字段并阻止启动，需补齐三项或全部清空后保存。配置缺失、不可读或解析失败均报错，不能当作三项全空。全部填写时，确认框说明将执行预检及实际选定方案的登录后命令；逐台锁源 Telnet 登录成功且提示符为 `>` 时先下发配置命令（空值仅回车）并等待 1 秒，再查询已勾选通道的 `software_version`、`inner_sw_version` 和 `/proc/version` 编译时间，并与当前测试方案“项目信息”中手动保存的软件版本、内部软件版本、ONU 软件编译时间逐项严格比对；启用预检时，任一通道查询失败或任一字段不一致都会记录差异并终止，绝不下发断电帧或启动开关机测试。启用预检时全部通道三项均一致后才继续。初始化仅断电本次已勾选通道：按通道顺序去重后逐个发送单通道关闭帧，每帧后等待0.5秒，全部下发完成后才启动测试；不发送全通道断电帧，未勾选通道保持原电源状态。启动确认框列出本次通道并提示危险操作；主执行日志记录目标通道、实际十六进制帧和下发结果，下发完成不代表已回读确认电源状态。初始化中停止或写入异常时不继续剩余通道、不启动测试，也不自动恢复已断电通道。每轮测试时序及失败通道续跑保持原规则。转入新工具的旧日志采用精简模式：保留每轮开始、关键登录/连接/Ping/WiFi/重试结果、全部警告/错误、实际电源帧和最终结论，过滤配置路径、原始命令回显等底层 INFO；2 秒内同级同文重复日志只显示一次，连续出现的同级同文旧日志即使超过 2 秒也只保留第一条，出现其它可见日志或执行阶段后下一条相同结果可再次显示；`IP登录成功` 在本次开关机测试中按 IP 各显示一次，例如 `113/112/113/112` 最终只保留113和112各一条，重新启动测试后重新计数；旧英文网卡 Ping 成功行会根据当前测试方案实际目标转换为 `Ping 成功：源网卡 192.168.1.112 → 目标样机 192.168.1.1`；其中 `通道 【N】 开始第M次测试` 正文使用绿色字体。旧工具结果文件中形如 `2026-08-08 15:37:41.904434: 通道9下挂的设备在第1次测试时正常` 的每轮正常结论也会实时显示为新工具的 `[旧工具Logs][INFO]`，原结果文件照常完整保存。该项会等待所有通道执行结束，任一通道失败会停止全流程。

实际执行顺序为：已勾选串口日志提前启动 → 已勾选环境线路检查 → 已勾选开关机测试。串口日志预启动和环境检查完成后均不额外等待；原编排器其余任务间120秒等待及停止机制保留，当前三项组合不会产生额外的子任务间等待。

点击「开始执行」后，已选任务缺项时先询问是否继续，再显示实际顺序的总确认；选择开关机测试时明确提示初始化仅断电已勾选通道及本次版本预检策略。取消任一确认均不启动线程、不隐藏窗口。确认并成功启动后台线程后窗口自动隐藏，运行期间主入口只提示查看主界面；结束后可再次打开。完成、部分失败和异常提示均以主界面为父窗口，通过主程序 UI 队列返回 Tk 主线程；检测到线程已结束时清理残留运行态。

- **开关机轮次进度**：主界面“环境检查与开关机测试”卡片的进度条在全流程启动时重置；开关机测试开始后，最大值读取本次 `config.ini [ui_defaults] number_of_tests`，右侧显示“开关机测试进度：当前轮次/总轮次”。普通测试按每轮正常结论推进；仅上下电模式不写正常结论时，以进入第 N 轮确认前 N-1 轮已经完成，并在最终成功时补齐满格。多通道并行时按所有已选通道均已完成的最小轮次推进，避免快通道使总体进度提前到 100%；总进度条下方的“通道概览”另显示“当前第 N 轮已完成 X/Y、运行中/重试/失败数量”，每个通道以独立轮次小卡展示，只有落后、重试或失败项进入“关注”行。停止或失败时保留最后已完成轮次和通道详情。
- **必填项状态展示**：每行右侧实时显示当前 store / main UI 状态（绿色就绪 / 红色「缺: 字段1, 字段2」），打开窗口时自动计算，勾选 / 切换 Checkbutton 时也会刷新；底部「刷新状态」可在去配置后立即手动重算，不执行任何设备操作。
- **串口日志预启动**：全流程子任务编排在后台线程运行，但“显示串口终端 + 打开当前全部串口”会作为一个动作投回 Tk 主线程；全部打开成功后才开始其它子任务，避免只显示窗口却仍处于“COM 未打开”状态。任一串口打开失败时，主执行日志记录失败 VLAN，串口日志任务按既有非致命规则继续后续子任务。
- **串口日志目录同步**：全流程第2项与“串口日志记录”窗口共用当前日志目录。在串口窗口点击“浏览…”选择新目录后，已打开且未运行的全流程窗口立即更新，执行确认框也显示同一目录；尚未打开串口窗口时读取上次保存的有效目录，无有效记录则显示默认 `D:\Serial_Log`。取消选择或选择失败保持原值。新目录用于之后新打开的监控；已打开的监控继续写原日志文件，如需切换请先停止对应监控再重新打开。
- **停止、关闭与界面动作失效（2026-11-13）**：全流程尚未被主界面领取的动作默认排队最多30秒，超时、停止或退出后失效，不会稍后自动启动。已开始的操作按原安全停止边界收尾，期间不能重复启动；关闭已完成的配置窗口不影响原失败通道续跑。程序退出时保留界面处理后台收尾，待任务及串口日志结束后再关闭。

- **失败处理**：任一「致命」子任务抛异常 → 整个全流程停止，弹「全流程执行失败」错误框；串口日志失败只记结果不阻塞。
- **状态徽标与「停止测试」按钮**：主界面“环境检查与开关机测试”卡片以 11 号粗体彩色徽标显示当前状态，“正在执行”为深绿色底白字，其它状态使用灰、警告黄、成功绿或危险红；停止按钮在全流程运行期间启用，点击后状态先变为“正在停止”，编排器在当前子任务安全退出后终止后续子任务。执行旧 Start All 时停止事件会直接传入旧业务；全流程弹窗不再重复显示停止按钮。
- **状态范围**：只计算和刷新这三项的必填项；从配置窗口返回自动刷新，也可手动点击「刷新状态」。四项已移除任务的固件、参数表和 ONU 目标等缺项不参与启动校验。
- **窗口与兼容**：背景统一为浅蓝灰，默认920×560、最小880×520，继续保存和恢复宽高。底层编排器保留原任务代码及历史能力；窗口、确认、结果和主日志使用当前三项编号。`power_operation`、`parameter_table_path` 等已有配置字段保留，独立功能的默认值、持久化、设备命令和确认保持。

## 检查更新与手动换版

点击主界面工具栏右侧“检查更新”，使用电脑普通网络连接访问公开仓库 `oscarouxue-coder/Power_OnOff_Assistant` 的 GitHub Releases。仅在点击后联网，不在启动时自动检查，也不使用设备 VLAN 的锁源连接。测试电脑需要能访问 GitHub 和其附件下载域名；失败不会改动测试配置或停止正在执行的测试。

- 检查期间显示“正在检查…”并禁止重复点击；版本号按三段数字比较，例如 `v1.1.10` 高于 `V1.1.9`。只检查 GitHub 标记为 Latest 的正式发布，草稿和预发布不会作为更新提供。远端不高于本机时提示“当前已是最新版本”；本机版本未标注、断网、超时、限流、版本/附件不可访问或发布不完整时显示具体失败原因，可重新检查。
- 发现新版本后显示当前版本、最新版本、发布日期、更新说明和便携 ZIP 大小，点击“下载”选择保存位置；默认文件名包含新版本号。“暂不下载”或取消保存不下载文件；已有目标文件须另行确认覆盖。
- 程序显示下载和 SHA256 校验进度，支持取消。使用本次专属 `.part` 临时文件，只有下载大小、SHA256 和 ZIP 格式检查全部通过后才生成最终 ZIP；取消或失败清理本次临时文件，原目标文件保留。窗口关闭会取消所属任务，旧任务不会刷新后来打开的新窗口；网络读取中的取消可能需要等待读取结束或超时。退出程序时先等待更新任务取消与清理完毕。
- 下载成功后可点击“打开所在文件夹”。程序不会自动解压、替换 EXE、启动新版或迁移配置；检查、实际 GET 请求、下载、校验、取消/跳过及失败均写入主执行日志。

手动换版：先结束测试并退出旧程序，备份旧便携目录及其 `Auto_power_on_off_tool/config`；将新 ZIP **完整解压到另一个新目录**。保留新包默认配置副本，再按版本发布说明迁移需要保留的本机 INI 和自定义测试方案，核对网卡/COM、账号、项目和文件路径后启动新版。不要把新包的默认配置覆盖到旧目录；保留旧版与备份，直到新版确认正常。已有旧 EXE 没有此按钮，首次需要手动安装包含此功能的版本。当前发布版为 [V1.2.3（2026-10-17）](https://github.com/oscarouxue-coder/Power_OnOff_Assistant/releases/tag/v1.2.3)，包含开关机开始前版本校验可选化：三项全空跳过、部分填写拦截、全填严格校验，失败通道续跑采用相同规则；并修复Python 3.9源码启动兼容问题，保留网卡名称检查与确认改名。GitHub Releases 每次发布后只保留最新版及其附件，请自行保留需要的旧版本地备份。

## AI占用保护与接收历史监测（2026-11-15）

- 本机通用命令和文件写入在设备或共享资源忙碌时拦截，包含AI只选择部分通道、其它通道仍在挂测的情况；批准后转忙也不会下发。无害的通用命令也可能被保守拦截，不通过降低权限检查绕过。历史材料分析、证据检索、本机文件只读、被动串口和报告生成保留；需要主动访问DUT的步骤仍受占用保护。
- AI在发送前检查当前Shell和连接。Boot、重新登录、断线、超时或发送结果未知时停止复用，不自动重发；临时恢复也不能向不确定的会话发送命令，恢复未完成时保留记录。三档权限、凭据显示和业务测试判据不变。
- 源码程序后台每60秒记录一次资源快照，保存在本次主执行日志目录的`resource_monitor/transport_history_*.jsonl`。通道以实际COM/VLAN/会话标识关联；包含RSS、历史/待写半行大小、文件大小和可观察状态。正常开始和停止在主界面静默，原文仍写入主执行日志文件；启动失败、采样或记录失败、日志写入告警及异常恢复提示继续显示，不增加固定按钮。未开启的串口不会因此自动打开；监测不发送设备命令。
- `received_bytes`运行时由当前只追加的历史长度推导，非独立驱动计数；`history_limit_bytes=null`表示当前未设上限。文件大小包含时间戳/方向/文本换行，不能与接收字节直接相等比较；`last_flush_confirmed=null`与`unverified`表示不能确认，不是写入成功。专项测试另使用独立驱动计数、序列号和摘要校验。
- 当前文本日志不是字节保真原始归档。跨块UTF-8、无换行待写尾部及写盘异常仍有风险；只读监测不能追回未保存数据或获知已被忽略的全部错误。本轮不限制、截断或清理原日志，不改动接收、写入和原始内存历史。后续完整归档和告警方案须另行确认。

## 打包与免安装发布

在 `Cheating_machine_execution_tool` 目录执行标准构建脚本（自动准备独立环境与固定依赖，跨电脑步骤见根 `README.md`）：

```powershell
.\build_line_check_assistant.ps1
```

每次标准构建产生一个独立的 `dist/qt-<构建批次>/` 目录，其中包含 `DUTPilot_portable/`、`DUTPilot_portable.zip` 和 ZIP 的 SHA256 校验文件。把完整 ZIP 复制到目标电脑，解压后双击 `DUTPilot_portable/DUTPilot.exe`，保留同目录中的 Qt 插件及 DLL。

GitHub 更新发布约定（从2026-11-05确认后的下一次构建/发布开始执行）：先更新 `line_check_assistant/packaging_assets/QT_VERSION_INFO.txt` 的版本与说明，再构建并检查交付物；Release 标签统一为 `v主版本.次版本.修订号`，数字必须与包内版本一致。创建草稿 Release，填写更新说明，**只上传**以下两个**同一次构建**的附件，核对大小/SHA256后发布并标记为 Latest：

- `DUTPilot_portable.zip`
- `DUTPilot_portable.zip.sha256.txt`

发布为Latest后，匿名完整下载并核对两个附件的大小/SHA256、验证源码更新客户端，再删除旧Release及附件；保留Git标签和源码历史。公开发布说明只指引下载完整ZIP及ZIP校验文件，不再单独提供EXE下载。版本说明、第三方声明及EXE校验文件继续包含在ZIP内。V1.2.6及其六份附件、历史发布记录保持原样。

不要把 GitHub 自动生成的源码 ZIP 当作便携包，也不要使用包内仅用于 EXE 的哈希代替 ZIP 哈希；附件缺失时客户端明确提示发布不完整。现有更新客户端已支持只包含这两个附件的发布，哈希不符仍阻止保存为最终ZIP。创建/上传 Release 单独执行，构建脚本不会自动发布或上传。

便携目录包含 EXE、`PORTABLE_README.txt`、`VERSION_INFO.txt`（版本号与本版变更说明）、第三方声明、SHA256 文件和程序所需的 `Auto_power_on_off_tool\config`。构建时只把当前配置当作字段/业务模板，自动清空当前电脑的 OLT/DUT/升级账号密码、OLT/源IP、ONU ID、钉钉和远程控制信息、固件/参数表路径、项目版本，以及网卡、串口和无线网卡绑定；C600业务映射等业务默认模板继续保留。另一台电脑首次运行前必须重新填写网络、测试项、升级/写参和ONU注册配置。

若目标电脑曾解压过旧包，应将新包完整解压到新目录并按上文备份/迁移配置，避免混用旧EXE或覆盖本机配置。

生成的 `.spec` 文件统一保存到 `line_check_assistant\packaging_specs`。

每次重新打包出最新版 EXE 后，不在当前 PC 直接运行便携目录中的 EXE；只检查构建结果、ZIP清单、配置脱敏和SHA256，并向用户报告输出路径。

打包后程序会从 EXE 所在目录、上级目录中查找 `Auto_power_on_off_tool/config` 文件夹；程控电源协议已内置，不再依赖 `Auto_Power_On_Off_Tool.exe`。

## 独立兼容挂测窗口

使用保留的 Tk 源码入口时，先在项目工作台核对项目目录、已启用通道及每台 DUT 的唯一实物 ID，保存并关闭该项目。独立模式接受这一项目的目录或 `project.linecheck.json` 路径。确认挂测前，核对弹窗中的完整目录、保存版本和通道。没有选择项目的独立窗口会在点击开始时提示如何绑定。

## 1. 安装与启动

### 1.1 准备环境

| 项目 | 要求 |
|---|---|
| Python | 3.8 或更高（[下载](https://www.python.org/downloads/)，安装时勾选 "Add Python to PATH"） |
| 串口驱动 | USB 转串口线的驱动（CH340 / CP2102 / FT232 等，插上后一般自动装好） |
| 浏览器 | 串口升级选 "页面升级" 方式需要本机装 Microsoft Edge |
| tftp 服务器 | 选 "tftp 指令" 方式需要本机装 tftpd32 / tftpd64（自带 TFTPD322_NEW/ 工具） |

### 1.2 安装依赖

解压工具包后，在目录里打开 cmd：

```cmd
pip install -r requirements.txt
```

本目录已提供 `requirements.txt`，内容：

```
pyserial>=3.5
selenium>=4.0
webdriver-manager>=4.0
openpyxl>=3.0
```

### 1.3 启动

```cmd
python serial_upgrade.py
```

启动后弹出主窗口，顶上有两个 Tab：**串口升级**、**写参工具**。

### 1.4 在 VS Code 中运行

项目根目录已提供 VS Code 配置：

- 默认解释器：`${workspaceFolder}/.venv_serial_upgrade/Scripts/python.exe`
- 运行当前 Python 文件时，终端会自动切换到脚本所在目录。
- 调试配置 `serial_upgrade` 会固定以 `test_boot_upgrade` 作为工作目录启动，确保能找到 `TFTPD322_NEW/tftpd32.exe`。

推荐操作：

1. 用 VS Code 打开 `F:\Aouxue\Power_OnOff_Assistant`。
2. 打开 `Cheating_machine_execution_tool/test_boot_upgrade/serial_upgrade.py`。
3. 点击右上角运行按钮，或在“运行和调试”里选择 `serial_upgrade` 后按 F5。

## 3. 串口升级 Tab

### 3.1 字段说明

| 字段 | 默认值 | 说明 |
|---|---|---|
| COM 端口 | 启动时自动扫描列出 | 下拉选串口；点 [刷新] 重新扫描 |
| 刷新 | — | 重新扫描可用串口 |
| 波特率 | 115200 | 串口通信速率，按设备实际值选 |
| 账 号 | `root` | 升级 Tab 的登录账号（初始登录用） |
| 密 码 | `t*hEQ#BHu7z%3n` | 升级 Tab 的登录密码（输入隐藏为 `*`） |
| 升级方式 | 页面升级 | 三选一：页面升级 / tftp指令 / tftp put |
| Boot模式IP | 192.168.1.1 | 设备进入 boot 模式后的 IP。**始终可见**，三种升级方式都会用到 |
| 进入boot | 输入回车 | 二选一：输入回车 / 输入sdmc |
| 升级文件 | （空） | 点 [浏览] 选本地的固件/包文件 |
| 开始升级 | — | 启动整条升级流程（登录 → 触发重启 → 进 boot → 升级） |
| 停止 | — | 中断当前流程（变灰直到流程结束） |
| 状态 | 就绪 | 实时显示当前状态 |
| 进度条 | 0 | 流程进度 |
| 执行日志 | — | 实时日志（时间戳前缀） |

### 3.2 升级流程

完整流程按以下顺序执行，每一步的判断和失败处理都有对应日志：

```
[1] 打开串口 COMx @ 115200
    ↓
[2] 登录（账号/密码用升级 Tab 的字段）
    ├─ 先发回车看是否已登录（precheck）→ 命中 OpenWrt:~# 直接跳过
    └─ 否则：等 login: → 发账号 → 等 Password → 发密码 → 再发回车 → 末尾判定 OpenWrt:~
    ↓
[3] 发送 firstboot -yr
    ↓ 触发设备重启
[4] 等待设备重启（按"进入boot"方式循环）
    ├─ 输入回车：循环发 \r\n，等 UserName: 提示符
    └─ 输入sdmc：循环发 sdmc\r，等 UserName: 提示符
    ↓
[5] 检测到 UserName: → 进入 boot 登录
    ├─ 发账号 telecomadmin + \r
    ├─ 等 Password: → 发密码 nE7jA%5m + \r
    ├─ 再发回车，等 shell 提示符（=> / ECNT> / U-Boot>）
    └─ 最多重试 3 次
    ↓ **没进 boot → 整个流程 abort，升级动作不执行**
[6] 升级动作（按"升级方式"选）：
    ├─ 页面升级：起 Edge 浏览器 → 访问 http://<Boot模式IP> → 选文件 → 点升级按钮
    ├─ tftp指令：起 tftpd32 → 改 BaseDirectory → 找本机同子网 IP → 串口发 tftp <ip>:<file>
    └─ tftp put ：在本机 cmd 跑 tftp -i <Boot模式IP> put "<file>"
    ↓
[7] 完成，弹状态提示
```

### 3.3 三种升级方式对比

| 方式 | 适用场景 | 工作方式 | 优点 | 缺点 |
|---|---|---|---|---|
| **页面升级** | 设备有 Web 升级页（最常见） | 启动 Edge 浏览器访问设备，Selenium 自动化选文件+点升级 | 通用，跟人工操作一致 | 依赖 Edge，UI 变了要改 Selenium 逻辑 |
| **tftp指令** | 设备 boot 模式支持 tftp client 拉文件 | 改 tftpd32.ini 让其指向升级文件目录，设备 tftp client 主动来拉 | 一次配置后续复用，不需要每改一处都重启工具 | 需要本机 tftp server 跑着；多网卡要保证 IP 选对 |
| **tftp put** | 设备 boot 模式支持 tftp server 接收文件 | 本机 cmd 主动推文件到设备 | 简单直接，命令行瞬发瞬完 | 设备要开 tftp server；Windows 防火墙要放行 |

### 3.4 进入 boot 方式对比

| 方式 | 循环发的字节 | 适用设备 |
|---|---|---|
| **输入回车** | `\r\n` | boot 阶段按 Enter 即可跳出 autoboot、看到登录提示的设备 |
| **输入sdmc** | `sdmc\r` | 需要在 autoboot 阶段敲 `sdmc` 才能进入 shell 的设备（部分 Zyxel/BCM 系） |

两种方式后续登录流程完全一致（telecomadmin / nE7jA%5m + 重试 + 校验 shell 提示符）。

## 4. 写参工具 Tab

把设备参数（如 SN、MAC、SSID 等）从本地 Excel 表格批量写入设备 flash。

### 4.1 字段说明

| 字段 | 说明 |
|---|---|
| 参数表格 | 点 [浏览] 选 `.xlsx` / `.xlsm` / `.csv` 文件 |
| 增加参数 | 在写参栏最下方加一行空行（指令 + 值都空） |
| 写入参数 | 启动写参流程（登录 → ppctl clear → FACTORY_MODE=1 → firstboot -yr → 等 100s → 二次登录 → 写参 → 读回校验 → 退出工厂模式） |

写参栏（默认 15 行）布局：

```
┌──────────────────────────────────────────────────────────────────────┐
│  #01 │ SN              │ ppctl set SERIAL_NUMBER=            │ 7552P11111111111 │ 
│  #02 │ XPON SN         │ ppctl set XPON_SN=                  │ XPON001            │
│  #03 │ MAC             │ ppctl set LAN_BASE_MAC_ADDRESS=     │ 00:11:22:33:44:55 │
│  #04 │ 2.4主SSID       │ ppctl set WIFI_SSID_24G1=            │ MyWiFi             │
│  ...                                                                      │
│  #15 │ IP地址          │ ppctl set LAN_IP_ADDRESS=            │ 192.168.1.1        │
└──────────────────────────────────────────────────────────────────────┘
```

第 1 列：序号（只读）
第 2 列：标签（写参逻辑用来映射表头列名）
第 3 列：写参指令模板（不可编辑，作为指令前缀）
第 4 列：参数值（**可编辑**——选完 MAC 后会被自动填充，可手动覆盖）

#### "增加参数"按钮

在写参栏最下方插入一行新的空白行（默认标签/指令/值都空）。**写参流程不会处理空行**。

### 4.2 参数表格格式

参数表格（Excel / CSV）需要这样的格式：

| SN | XPON SN | MAC | 2.4G SSID | WiFi Password | 5G SSID | WiFi Password | Country code | Country code | Product Class | Superuser Name | Superuser Password | User Name | Password | IP |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 7552P11111111111 | XPON001 | 00:11:22:33:44:55 | MyWiFi | 12345678 | MyWiFi5G | 12345678 | CN | CN | X100 | admin | admin123 | root | root123 | 192.168.1.1 |
| 7552P22222222222 | XPON002 | 00:11:22:33:44:66 | MyWiFi | 12345678 | MyWiFi5G | 12345678 | CN | CN | X100 | admin | admin123 | root | root123 | 192.168.1.1 |

**列名映射**（写参栏标签 → 表头列名）：

| 写参栏标签 | 表头必须包含的列名（精确匹配，区分大小写） |
|---|---|
| SN | `SN` |
| XPON SN | `GPON SN` |
| MAC | `MAC`（写参时自动转 `XX:XX:XX:XX:XX:XX` 大写格式） |
| 2.4主SSID | `2.4G SSID` |
| 2.4主SSID密码 | `WiFi Password` |
| 5G主SSID | `5G SSID` |
| 5G主SSID密码 | `WiFi Password` |
| 2.4G国家码 | `Country code` |
| 5G国家码 | `Country code` |
| 产品名 | `Product Class` |
| super用户账号 | `Superuser Name` |
| super用户密码 | `Superuser Password` |
| 普通用户账号 | `User Name` |
| 普通用户密码 | `Password` |
| IP地址 | `IP` |

> **关键约定**：表头列名**必须**和上面"表头必须包含的列名"列**精确匹配**（含空格、大小写一致）。第一行是表头，第二行起是数据。

### 4.3 写参流程

```
[1] 打开串口（用升级 Tab 的账号/密码登录）
    ↓
[2] 登录成功
    ↓
[3] 依次发：
    ├─ ppctl clear                                ← 清除所有参数
    ├─ ppctl set FACTORY_MODE=1                  ← 工厂模式
    └─ firstboot -yr                             ← 触发重启进工厂模式
    ↓
[4] 等待 100s 设备重启
    ↓
[5] 串口输入回车（唤醒）
    ↓
[6] 二次登录（root / t*hEQ#BHu7z%3n，固定账号）
    ↓
[7] 写参循环（每条参数）：
    ├─ 发 ppctl set XXX="value"
    ├─ 读 ppctl get XXX
    └─ 比对，不一致重试（最多 3 次/条）
       ├─ 命中 → 下一条
       └─ 失败 → 累计失败项，最后弹"写参失败"对话框
    ↓
[8] 写参完成
    ↓
[9] 退出工厂模式：
    ├─ ppctl set FACTORY_MODE=0
    └─ firstboot -yr
    ↓
[10] 流程结束
```

#### MAC 特殊处理

`MAC` 行的值会被自动归一化成大写、冒号分隔的 6 段格式：

| 输入 | 归一化后 |
|---|---|
| `00:11:22:33:44:55` | `00:11:22:33:44:55` |
| `001122334455` | `00:11:22:33:44:55` |
| `00-11-22-33-44-55` | `00:11:22:33:44:55` |
| `aB:cD:12:34:56:78` | `AB:CD:12:34:56:78` |

#### 写参栏自动填充

选了参数表格 + 选了下拉的某个 MAC 后，工具会：

1. 取第一行作为表头（列名）
2. 找到选中的 MAC 那一行
3. 按"写参栏标签 → 表头列名"映射，把对应值填到写参栏的"参数值"输入框
4. 写参时按"指令 + 拼接值"组成完整指令

> 如果表头列名跟"列名映射"对不上，相应写参栏的参数值留空，写参时跳过。

## 5. 常见问题

### Q1: 启动报"ImportError: No module named ..."

依赖没装齐。运行：

```cmd
pip install -r requirements.txt
```

### Q2: 串口打不开 / 找不到 COM 端口

- 检查 USB 转串口线是否插好
- 装对应驱动（CH340 / CP2102 / FT232 等）
- 点 [刷新] 重新扫描

### Q3: 升级 Tab 登录失败 / 一直重试账号密码

- 升级 Tab 的账号/密码没填对（注意密码里的特殊字符 `* # %` 不会被转义）
- 设备的串口登录提示不是 `OpenWrt login:` 而是别的（比如 `Please login:`），precheck 会先发回车看，然后等 login: 提示 10s 超时

### Q4: 升级 Tab 一直收不到 UserName: / Password:

`进入boot` 方式没选对：
- 老设备用 Enter 跳出 autoboot → 选 **输入回车**
- 部分 Zyxel/BCM 设备要敲 `sdmc` → 选 **输入sdmc**

### Q5: 写参时某一条一直重试失败

常见原因：
- 设备不认这个 ppctl set 指令（命令拼错 / 设备固件版本不同）
- 参数值里有特殊字符（双引号转义问题）
- 设备实际值跟写进去的不一样（比如长度截断、字符集问题）

日志会显示：
```
[!!] [3/3] 密码回显中即检测到 UserName: → 登录被拒
```
或：
```
[!!] [2/3] 不一致: SN: 期望=ABC123 设备=ABC12
```

**最后会弹"写参失败"对话框**列出所有失败项，可以据此排查。

### Q6: tftp 升级一直 timeout

- **tftpd32 没点 "Start Server"**——GUI 启动后需要手动按那个按钮
- **tftpd32 的 Base Directory 不是工具改的目录**——开了 GUI 后可以在"Settings → Global Settings"看
- **本机防火墙拦截了 UDP 69 端口**——临时关掉 Windows 防火墙再试
- **多网卡时 IP 选错了**——看日志 `本机所有网卡 IPv4: [...]`，手动指定同子网的网卡

### Q7: 升级 Tab 走到 tftp put 但 cmd 报"不是内部命令"

Windows 默认没装 tftp 客户端：
- "控制面板 → 程序 → 启用或关闭 Windows 功能 → 勾选 TFTP Client"
- 或者换用 **tftp指令** 方式（不需要本机 tftp 客户端）

### Q8: 页面升级用 Edge 但 Selenium 找不到元素

设备的升级页面 HTML 变了。检查日志里 `等待文件上传 input 元素出现` 是否超时。如果是，工具里硬编码的 `//*[@id="m"]/form/input[1]` 这个 XPath 需要根据新页面更新。

### Q9: 升级 Tab 报"未进入 boot 模式，跳过升级动作"

之前是 boot 检测失败但升级动作照常执行（假报成功）。现在加了守卫，**没进 boot 就不会跑 tftp / 浏览器**——日志里会看到 `进入boot失败` 之类的错误，按 Q3/Q4 排查。

### Q10: 设备 boot 提示符不是 `=>` / `ECNT>` / `U-Boot>`

工具默认识别这三种。如果你的设备提示符是别的（比如 `TFTP>`、`#`、`root@hostname:~#`），告诉我，把 `_is_boot_prompt` 方法（`serial_upgrade.py` 里）加一行 substring 即可：

```python
def _is_boot_prompt(self, text):
    if not text:
        return False
    return (
        "=>" in text
        or "ECNT>" in text
        or "U-Boot>" in text
        or "TFTP>" in text        # ← 加这种
    )
```

## 6. 典型工作流速查

### 升级一个新设备

1. 设备接 USB 转串口，确认 COM 号
2. 工具选 `COMx` / `115200` / 填账号密码（默认值通常是 `root` / `t*hEQ#Bwu...`）
3. 升级方式选 **页面升级**（最通用）
4. 升级文件点 [浏览] 选固件
5. 进入boot 选 **输入回车**（先试这个；不行再换 输入sdmc）
6. 点 [开始升级]
7. 看日志确认整个流程：登录 → firstboot → reboot → UserName → 密码 → 升级页 → 完成

### 写一组参数

1. 准备参数表格（.xlsx 第一行是表头，含 14 个规定列名）
2. 切到 **写参工具** Tab
3. [浏览] 选参数表格
4. MAC 下拉框选要写入的 MAC → 写参栏自动填值
5. 检查写参栏每行的值（不对的可以手动改）
6. 点 [写入参数]
7. 流程走完后看日志，看是否所有项都成功写入

### 升级 + 写参连续做

升级和写参是两个独立流程，要分两次跑（一次升级 Tab、一次写参 Tab），不能连着做。

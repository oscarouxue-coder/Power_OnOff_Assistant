# Phase 5、7 串口被动取证与内存观测

原 Tk 诊断经 AiSerialBridge.read 调用 AiSerialClient，Qt 串口窗口诊断快照调用同一个读取函数。有模型工具资格的原诊断执行器会对读取结果截取前 65,536 个字符。此前读取先在原会话取得游标，再在另一段加锁期间按该游标复制历史。两次操作之间到达的数据也会被复制。

## 复现与修正

用原串口读线程、真实会话管理器和模拟驱动先接收 65,536 字节，再在复制开始前送入第二块 65,536 字节，末尾带 TAIL。原诊断接口返回 131,072 字节，超过承诺的近期窗口。在这个纯 ASCII 输入中，工具截取前半段会丢失 TAIL。[原始失败](before.txt)

[共享读取函数](../../../src/services/ai_serial_client.py)现在通过会话现有的相对尾部切片，在同一把驱动历史锁下定位并复制最多 65,536 字节。沿用已有会话、串口配置校验和解码规则。开关机或升级等待使用的旧游标继续读取原始完整历史。[模拟串口回归](../../../tests/test_qt_serial_terminal.py)

## 长挂前置观测

在独立模拟串口 COM7839 的原读线程内依次接收 1、2、4、8 MiB 规则数据，未启用文件日志。每次读到的数据量和底层保留的原始历史长度相同。到 8 MiB 时仍可从游标 0 读取第一行。物理串口调用与设备写入均为零。该实验测量单个字节缓冲区，未测整个进程驻留内存，也未执行 24/72 小时稳定性试验。[复验脚本](check_serial_history.py) · [原始采样](history-probe.json)

原 wait_for_any、wait_for_all 及 peek_since 使用相对会话开始的字节偏移，升级和写参服务会持有旧游标并在收到后续数据后核对标记。单纯丢弃早期数据会改变已有判据。原始历史存储策略另行处理，本阶段仅修正被动取证窗口。

本阶段未启用 Qt 的主动设备会话，网关业务拒绝策略继续生效。真实设备和长挂保持待验。

## 阶段复验

串口终端、共享传输和 AI 调试共 52 项通过。新用例核对被动接口返回最后 65,536 字节、模型工具保留末尾 TAIL、旧游标仍可读取原来两块数据、驱动写入为零。[专项输出](focused.txt)

Windows 私有桌面的 100%、125%、150% 缩放各通过 95 项，共 285 次，窗口隔离违规为零。Qt 原生窗口通过原通道右键读取快照，保留 [100%](native/scale-1/serial-diagnostic-snapshot.png)、[125%](native/scale-1.25/serial-diagnostic-snapshot.png)、[150%](native/scale-1.5/serial-diagnostic-snapshot.png) 三档证据。[原生结果](native/results.json)

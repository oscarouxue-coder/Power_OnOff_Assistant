# Phase 2、5 旧设备会话继续分析留存材料

原 Tk 会话服务按保存的批次判断实时取证资格。会话属于旧批次时，只能分析已经留存的材料。此前 Qt 只开放了由报告创建的设备会话。没有关联报告的旧本机会话在选择后只能查看历史，不能继续追问。

## 实际数据与原行为

已核对迁移备份的 SHA256，以只读副本汇总其中 4 个诊断数据库、28 条会话。4 条是未关联报告的本机单设备会话。其中 1 条具有明确的历史批次编号，留存 3 条证据。先前候选将这 4 条均显示为只能查看。报告不导出原始问题、证据正文或设备身份，也不对真实记录执行模型调用。[只读审计脚本](audit_backup.py) · [备份原始统计](backup-before.json)

在合成项目中，由原服务生成一个设备会话并写入原格式的旧记录，保留旧批次串口证据。切换到同一通道的新批次后，Qt 可以选择历史条目，但发送入口仍被禁用。[修正前的断言](before.txt)

## 接入范围

选择本机已结束批次的单设备会话后，沿用原项目库、冻结的模型配置和清晰标注的“仅分析留存材料”输入框。只有操作员主动发送才提交问题。旧批次的证据、手工材料与消息保存在原会话中。旧记录省略 scope 和 source 时仍按原数据库约定识别。保留原连续诊断偏好。

这个入口检查实际批次、设备目标与会话来源。当前批次和缺少批次编号的无报告设备会话仍等待实时设备会话接入，远程平台、批量子会话及工作区网关的项目控制范围维持原约束。

[会话模式与原会话服务](../../../src/services/qt_ai_chat.py) · [工作区模拟服务回归](../../../tests/test_qt_workspace_adapter.py) · [Windows 实际会话窗口](../../../tests/qt_workbench_probe.py) · [完整基线](../../../scripts/verify_baseline.py) · [三档指定原生用例](../../../scripts/verify_qt_migration.py)

隔离副本的模拟模型只收到合成的旧批次标记，工具清单仅有询问用户和检索留存证据。新批次同一通道的标记未进入请求。当前批次、缺批次、平台来源均未提交。[隔离回归](staged.txt)

## 真实旧数据库复验

另在临时数据库副本上打开符合条件的真实记录。修正前和隔离副本都能选中原会话并逐条读取与数据库相同的 3 条证据，修正后允许在该会话输入留存分析问题。核对前后会话、消息和证据内容一致。全程模型请求、网络连接与凭据解密均为零。[复验脚本](check_backup_selection.py) · [原候选](backup-selection-before.json) · [隔离副本](backup-selection-staged.json)

## 实时设备会话的剩余调用链

从原窗口实际发送问题时，[Tk 会话面板](../../../src/ui/ai_chat_panel.py)刷新当前项目目标，把问题、先前选择和取消条件交给 [AiSessionRouter.send](../../../src/services/ai_session_router.py)。[原控制器](../../../src/ui/ai_assistant_controller.py)使用项目级诊断传输及共享资源保护，串口桥提供现有会话读取、控制权取得、恢复和目标核对。Qt 目前在已选会话上调用原发送服务。本次只为符合条件的旧批次记录开放留存分析。当前设备上的实时采集还需迁移目标路由、项目资源准入和串口控制权交接。

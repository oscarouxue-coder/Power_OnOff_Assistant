# 迁移前实际项目的保存与重开

后续 Qt 归档窗口已接入下述 24 份主执行及资源监测日志。两个项目从原备份复验，980 行按原文与顺序一致。[项目主日志复验](../project_main_logs/REPORT.md)

Phase 2、8、9 的源码兼容性复验使用 Phase 0 本机数据备份。2026-11-21，从经过 SHA256 核对的归档恢复了其中全部两份版本化项目，在临时目录通过 Qt 工作区执行打开、查询历史、保存、关闭和重开。全程使用独立工作区、项目锁命名空间和临时用户数据目录。生成的报告只含数量，测试后临时副本已清理。

| 核对项 | 旧项目 A | 旧项目 B |
| --- | ---: | ---: |
| 原配置中的通道 | 1 | 3 |
| Qt 显示的通道槽位 | 16 | 16 |
| 草稿配置文件 | 6 | 6 |
| 原有版本中的配置文件 | 18 | 48 |
| 原有运行快照中的配置文件 | 0 | 24 |
| 原有项目主日志文件 | 6 | 18 |
| 原工作台历史运行 | 0 | 4 |

两个项目同时打开后各自保有原身份和名称。配置中的通道启用状态、VLAN、串口与旧程序读取结果一致。保存生成独立的新版本，内容逐文件与旧草稿一致。重开时再次核对身份、名称、展示通道和历史记录。两条历史成功记录、两条结果未知记录均按旧记录显示。原草稿、既有配置版本、运行快照配置和 24 份主日志的文件内容逐字节核对通过。

另通过“导入旧配置目录”导入备份中的单项目配置。原目录共 15 个文件，6 个 INI 全部通过原始备份哈希比对，代码、字节码和旧备份文件按原规则排除。旧程序请求解析器分别读取原目录与导入草稿，核对全部 25 个业务字段及 3 个所选通道，包括开关机轮数、延时、WiFi 及 Telnet 开关。保存并重开后重复解析一致，任务根目录绑定在导入后的项目。首次扩展复验时 Windows 临时目录短路径造成探针路径断言失败，改用解析后的临时根路径并保留目录边界检查后通过。

两份数据中的能力任务数据库均未提供任务样本，因此本次实测的四条历史属于旧工作台运行记录。主日志此次核对了原文件保留，尚未验证这些历史主日志可直接在 Qt 内翻阅。测试前后本机备份哈希一致，外部通信及物理串口打开次数均为零。目标电脑独立部署仍待现场验收。

# Phase 5、6 本机会话的自然语言目标识别

旧版在后台使用原会话路由判定目标。上一候选遇到“请把排查对象换到七号测试位”时留在普通问答。本阶段将本机普通问答、电脑诊断和当前批次通道会话接入同一个识别器。明确单通道仍走原快捷路径，报告与历史批次仍在原会话中读取材料。[上一候选的对照](../local_serial_chat/selection-natural.json)

识别只产生目标建议。Qt 工作区线程在提交前重新核对当前会话、项目目标、模型及运行批次。目标识别中的原文暂时回显在输入会话，收到有效结果后再按实际目标提交用户原文。迟到、取消或配置变化的结果无法启动设备任务。项目关闭时等待识别线程结束后才关闭会话数据库。模型识别期间仍可刷新工作区和停止本轮。

沿用原有会话窗口和控件。识别中，状态行显示“正在识别会话目标”，停止按钮可用。明确切换与自然语言切换均复用同一通道会话。电脑诊断和读取已打开串口沿用已有服务。本阶段没有变更开关机执行器、帧格式、等待时间、现场判定或旧 Tk 入口。网关继续按本期范围处理项目控制。

## 首次测试发现的问题

首次原生 100% 缩放中，电脑诊断用例的模拟模型只接管流式问答接口。新增目标识别需要调用非流式接口，窗口未等到预期的模拟回答。该首次失败使用合成配置和测试密钥，无法从记录判定模型请求是否到达外部。修正为两个接口均使用模拟回复，并在工作区专项和原生项目用例的模型传输入口拦截未模拟的请求；即使业务代码捕获异常，只要调用过真实传输入口，用例仍会失败。

持续开机全业务老化按负责人既有决定待接入。真实串口、DUT 循环、长挂、干净目标机启动仍待现场。更广的设备实时诊断、批量会话等功能保持逐项核对。[迁移总表](../MIGRATION_PROGRESS.md)

## 分阶段模拟验证

- 自然语言请求在 Qt、旧路由中各触发一次模拟意图识别，均选中通道 7。单独选择无需提交诊断问题。明确通道表达在两个入口均跳过意图模型。[自然语言对照](natural.json) · [明确通道对照](current.json)
- 会话与工作区专项运行 80 项，涵盖迟到回执、取消、切换会话、目标配置变化、依赖维护互斥及关闭数据库前的等待。用户原文交给原服务，模型不能改写待执行问题。本次识别的未提交错误只在当前窗口反馈。[独立候选专项](focused-final.txt) · [共享工作区复验](shared-routing.txt)
- 原开关机子进程在两条模拟通道上运行时，延迟目标识别后仍能刷新工作区。停止本机识别仅取消模拟模型请求，原任务继续持有资源。网关远程停止返回拒绝，最终两轮断电和通电的 8 帧全部写完。子进程与主进程均无真实串口或外部请求。[识别与开关机并行复验](power-intent.json) · [原逐帧回放](power.json)
- 本机模拟串口留存材料可读，项目列表与切换项目完成，远程读串口和停止均被明确拒绝。两份迁移前项目副本也通过打开、保存和重开核对。[网关回执](gateway.json) · [旧项目复验](archived.json)

在能够返回模拟电脑回答的首次 150% 复验中，测试把“正在识别目标”误作“已进入电脑诊断”。两种状态都允许停止。重试时先核实已进入电脑诊断，再要求发送按钮可用，并检查原会话数据库已收到补充文本。另一次窗口复验发现未入库的错误没有出现在原有状态栏。现已把失败原因送入会话状态栏，并在输入框为空时恢复原文；期间手工输入的新草稿保留。对电脑诊断和自然语言选择两项原生用例做了三档专项，6 次均通过。[100%](native-pair-1.txt) · [125%](native-pair-1.25.txt) · [150%](native-pair-1.5.txt)

## 下一项已复现的差异

同一份源码在两个模拟通道上跑完原开关机流程。通道 3 产生 16 条当前批次证据，包括通道结果、阶段、日志和诊断设置。按项目和原诊断批次核对，旧会话的原证据刷新得到 16 条，Qt 当前通道选择后得到 0 条。工作台任务号与原诊断批次号不同，此对照使用项目实际收到的原诊断开始事件确认归属。没有调用模型或打开物理串口。[实测对照](power-evidence-audit.json)

另做了普通电脑会话的偏好对照。开发中的首版把自然语言切换到本机电脑判成连续诊断，旧版在普通问答中发起同一请求时保持普通模式。现已修正；专门选择连续电脑诊断的原入口继续创建独立的连续会话。[修正前](pc-before.json) · [修正后](pc-after.json)

原开关机回放中的两次诊断开始通知属于同一项目和同一诊断批次，两次都能取得本任务不可变的配置目录。后续可用此配置核对通道身份。[运行配置归属](power-binding.json)

# 串口收尾线程创建失败与工作区资源回执

串口终端和受控串口操作共用的串口管理器支持异步关闭。原实现先移除最后一个所有者，再创建收尾线程。用模拟驱动让 Windows 线程创建调用抛错后，管理器已无活动会话，但驱动仍开着，关闭回执也无人完成。Qt 终端虽恢复显示订阅，此时管理器已无法按原端口找到它。[复现脚本](check_worker.py) · [修正前的状态](before.json)

隔离源码副本中，管理器在原锁内先确认收尾线程已启动，再把会话交给它。线程未启动时保留同一监控会话、控制所有者与工作区占用。再次关闭可正常结束收尾。批量关闭中，已受理的端口继续结束，尚未受理的端口仍可重试。若线程已经实际启动后调用方才收到异常，沿用已启动的收尾线程。驱动已关闭、工作区资源登记却失败时，回执带错误结束，该管理器继续阻止端口重开。[隔离复现结果](isolated-after.json) · [多端口和工作区故障专项](isolated-worker.txt)

本阶段只用模拟驱动。模拟控制端口未发送字节。驱动拒绝关闭、实际设备启动及长时间串口记录仍应按原范围现场验收。串口接收历史的保存策略、程控电源帧和挂测判据沿用上一版本。

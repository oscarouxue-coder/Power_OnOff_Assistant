# 同一网关槽位重启与回执恢复

## 复现与修正

旧候选首次连接时能列项目。用相同槽位、配对凭据和数据库第二次启动，实例身份保持，启动标识更新。工作区在轮询新消息前导出数据库中所有旧回执，网关核对原请求的启动标识后关闭连接。在模拟环境中，选择刚认证的实例已返回「实例不在线、名称重复或超出授权范围」。[修正前的失败记录](before.txt)

工作区沿用原签名协议、收件去重和项目授权检查，在保存每条路由时用同一 SQLite 事务记录其启动标识。重新连接时仅导出当前启动的工作区回执。旧表继续保留原四列，旧记录默认保留在本地；收到签名身份与原摘要完全匹配的当前启动请求时，可恢复该条原回执的关联。原 Tk 入口仍可使用既有路由表。回退到修正前封存的程序时，该程序自身的跨启动回执问题仍可能复现。程序没有向旧记录推测分配启动标识。

# 第一条网关请求与启动中断

迁移计划 Phase 5、6 要求保留原远程项目范围、回执与生命周期。沿旧 Tk 的工作区控制器注册路径核对到 `WorkspaceService.register_controller`。原代码先启动客户端，后挂接项目。如果网关一连上就查询项目列表，可以得到空列表，并把它当作这个请求的正式回执。如果收件线程已经启动，但网络线程创建失败，工作区也取不到这个客户端。

## 复现与修正

在临时项目 A 中模拟一位已授权成员，在客户端启动期间立即提交“项目列表”。修正前，首条答复漏掉了 A。另一次实验让收件线程等待，保持它实际存活，然后令网络线程启动失败。此时工作区没有持有运行时，槽位释放回调也未执行。[修正前的断言](before.txt)

工作区现先持有实例运行时，按原本机授权挂接项目，再创建和启动客户端。启动失败时先停止接收。若已启动的线程仍在收尾，工作区保留实例和数据库并等待它退出；若已空闲，立即释放资源。关闭时只等待实际启动过的线程。其余已准入项目仍走原执行与停止路径。

专项复验使用真实线程和原 SQLite 路由器，网络边界使用模拟端点。首条回执包含已授权的 A。网络线程启动失败时，已启动的收件线程仍归工作区所有，停止请求有效，线程退出后才能释放槽位。相关权限、回执去重和已准入任务断线场景使用本机回环或 Fake 服务。[34 项专项结果](focused.txt)

# Qt 项目网关控制面验证

原 Tk 在已配置网关模式时，从项目初始化路径创建项目控制器、注册授权与网关客户端。旧 Qt 候选能保存槽位，重开后的工作区缺少注册路径。本阶段先验证实例连接、项目目录与选择，使用临时项目、临时实例身份、测试用凭据和 127.0.0.1 上的模拟网关。

## 控制命令与回执

从 Qt 保存的槽位重启工作区，打开 A、B 两个临时项目，使用原 WebSocket 客户端完成回环身份验证。模拟成员首先只看到获准的 A，选择 A 后收到原项目选择回执。业务会话控制器尚未挂接时，实验版本返回明确的拒绝回执，没有创建业务任务。改授权 B 后，目录不含 A。已拒绝的请求重复到达时保持原回执。重新授权 A 后两个项目均可见，关闭 B 后只列 A。退出工作区时客户端空闲并释放实例占用。

已在隔离副本的 Windows 原生窗口中，经“下次启动配置”确认槽位、通道与能力，关闭并重开工作区。传输边界用模拟连接替换。状态窗口读取实际运行时并显示已连接；未向真实平台发送消息。[原生窗口专项](isolated-native.txt)

## 业务边界

配置生效后的实例连接会从网关取走发往该实例的消息。控制命令与业务消息共用同一接收队列。当前 Qt 本地会话仍只对已接入的会话类型开放取证，实时 DUT 会话与业务审批桥还需迁移。负责人已选择本期开放项目控制命令。业务消息由网关返回明确拒绝，并保留原请求回执，后续接入项目业务会话和原审批链。

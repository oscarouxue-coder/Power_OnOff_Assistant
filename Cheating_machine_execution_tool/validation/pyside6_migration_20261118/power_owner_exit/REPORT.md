# 开关机原子进程失去 Qt 主进程后的表现

Phase 6/9 要求重启后核实任务状态及资源保护。此前用同进程模拟执行器验证了断续保护。这次用 Windows spawn 启动原业务子进程，保留原计时、队列和执行器，只在设备边界接入虚拟电源与模拟服务。在 CH3 第一次通电后，承载 Qt 工作区的测试进程直接以 47 退出。

| 观察 | 实测结果 |
| --- | --- |
| 主进程异常退出 | 观察程序确认进程退出时，距子进程观察起点约 3.17 秒 |
| 重开同一项目 | 显示结果未知，旧任务仍持有持久资源保护，再次准备启动被拒绝 |
| 原子进程 | 在 13.23 秒写入 CH3 断电帧，在 16.77 秒写入 CH3 通电帧，两帧都发生在主进程退出后 |
| 结束确认 | 原子进程关闭了模拟串口，观察程序通过该 Windows 进程句柄等待实际退出。无实体电源、物理串口或外部通信 |

两帧来自失去主进程的旧任务。重开的工作区没有再次下发命令。“结果未知”不能证明测试架已停止，这是现场复核时需要区分的状态。本次验证未改变原业务行为。

绕开 Qt 任务准入，直接调用原 `run_legacy_power_test`，在相同工况和相同位置使其调用进程退出。原子进程也在主进程退出后写入相同两帧，分别在子进程计时 13.25 秒和 16.78 秒出现。此对照表明该行为沿自原执行器。Qt 工作区的重开及禁启另由上表所列 Qt 入口单独复验。[原执行入口轨迹](original-entry.json)

[逐帧及进程证据](observation.json) · [复验脚本](check_owner_exit.py) · [上阶段的双项目恢复验证](../parallel_power/REPORT.md)

再次运行 Qt 路径，并在 Windows 进程句柄仍指示原执行器存活时打开“核实任务”。修正前的候选版本允许进入审阅。探针随即取消，核对原保护仍在；没有提交核实或再次启动任务。操作员在这一阶段看到的是可填写的核实窗口，不能据此判断原执行器已经退出。[存活时的审阅状态](review-availability.json)

首次探针把 Windows 虚拟环境启动器的 PID 当作 Python 业务所有者，因此进程关系断言提前终止。改用 multiprocessing 的实际父进程身份和 Windows 进程创建时间复核后成功完成测试；首次使用的专属临时目录在确认模拟串口关闭、子进程退出后移入回收站。

## 修正后的工作区

负责人选择保留已启动的任务，原子进程退出前禁止解除保护。Windows 业务子进程进入任务目录后、接触串口前，以项目 ID 登记内核句柄。同项目每个子进程分别持有句柄，最后一个退出后登记才消失。子进程在登记时核对启动它的进程；在登记前已失去启动方时直接结束。已经开始的任务继续沿原循环执行。重开的工作区只查询进程，旧版本未登记的子进程通过 Windows 进程参数和所属项目的原执行目录核对。

工作台状态轮询最多缓存最近 3 秒的查询结果。任务历史在打开核实、提交核实以及底层写入结果前重新查询进程。读进程失败时保留保护。进程退出后仍由本机操作员依据现场记录提交结果。测试中的人工结论仅用于临时项目。原任务的延时、上下电命令、通道判定及停止路径沿用原执行器。

### Windows 原进程与模拟电源复验

在 CH3 第一次通电后使工作区退出，持有 Windows 进程句柄，分别在句柄示存活和示退出时重开同一项目。下列时间从子进程观察起点计，两次写入依次为原断电帧和通电帧。

| 项目 | 确认主进程退出 | 子进程断电 | 子进程通电 | 存活时尝试核实 | 进程退出后 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| 新版执行器 | 3.17 秒 | 13.23 秒 | 16.77 秒 | 拒绝 | 保留未知，提交模拟核实后解除 | [逐帧记录](managed-worker.json) |
| 模拟旧版未登记句柄 | 3.16 秒 | 13.23 秒 | 16.77 秒 | 拒绝 | 保留未知，提交模拟核实后解除 | [逐帧记录](older-worker.json) |

每次重开均拒绝再次启动。原进程存活期间尝试直接调用结果存储也被拒绝，任务记录及资源保护均保留。用模拟证据确认异常中断后，原服务把该临时任务记作失败，未触发重试。独立专项还启动了三个 Windows 子进程，两个归属项目 A，一个归属 B，验证同项目引用及跨项目相互隔离。进程无法读取、登记前已丢失启动方、项目身份不一致、旧 GUI 核实及审阅期间状态变化均有回归断言。[5 项专项输出](focused.txt)

兼容性组在模拟子进程中关闭新增的登记调用，保留原运行目录和 Windows spawn 参数，验证旧版进程的识别路径。修正前原入口的实际轨迹另见上文。独立开发副本及首次冲突的临时测试目录已经在确认进程退出后移入回收站。

已在本批主源码重跑两个并行的 16 通道项目。两个不同的 Windows 原业务子进程各完成两轮，两个模拟电源各收到 64 帧。每个通道的次序均为断、通、断、通，两个任务均由原执行器报告完成。[双项目 128 帧原始记录](two-banks.json) · [复验入口](../parallel_power/check_parallel_workers.py)

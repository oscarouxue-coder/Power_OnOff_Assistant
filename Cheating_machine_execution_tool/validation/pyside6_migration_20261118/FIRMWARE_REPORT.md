# Qt 样机升级首个执行检查点

> 本报告所列的部分截图和测试输出已在对应验证通过后清理，测试结论与复跑方法见正文。

2026-11-19。项目详情的「样机升级」入口已接入原页面升级和三个全包传输分支。页面升级保留原最多 8 台并行。配置了程控电源的全包升级支持 Tftp 指令、Tftp Put、Web 网关、Boot 方式、1–8 并行和恢复出厂选项。默认设备测试入口仍为 Tk。现场未验收。

## 审计和实现

[实施前审计](NEXT_FIRMWARE_AUDIT.md)对照了 Tk 模式分支、旧固件/目标参数、原自动串口监听及停止边界。Qt 预检使用原 `FirmwareUpgradeValidation` 读取固件长度与 SHA256、核查源网卡和目标；页面升级的并发限制以原 `run_page_upgrade_batch` 默认值为准。复用原 `firmware.upgrade`、Job、资源锁和 `dispatch_upgrade`。原四套引擎、设备命令、重试、判定与时序保持原样。

- 新的 `firmware.editor.*` 仅允许本机 GUI 调用。预检按本次项目、确认令牌、实际目标及固件哈希建立一次确认，窗口默认取消；确认阶段复核项目版本和网卡。文件变化、会话过期、拒绝确认、重复目标或并行资源冲突须重新核对。固件使用原 Job 的内容绑定及独立副本。
- 页面升级在未配置程控电源时仍可用。全包升级的人工重启分支仍走原入口，Qt 保留受控接口的程控电源校验。执行前检查超级用户名、密码和固件。升级密码仅在本机 GUI 编辑回填，默认遮蔽，预检摘要和任务参数不包含密码。
- 「保存项目设置」按原 `SampleUpgradeSettingsStore` 写入同一项目文件并提交版本，保留写参账号、写参并行数、电源方向、参数表路径等同文件字段。保存不访问设备。版本变化拒绝覆盖，保存失败恢复原文件，恢复失败进入项目未知保护。
- 停止沿原引擎的安全点，窗口关闭和切换视图不会结束后台 Job。重开可看到原任务和逐台结果；关项目或退出沿工作台现有资源收尾。

## 现场开始

记录目标机、操作员、Windows 版本及缩放、软件版本及 ZIP 哈希（源码运行时记录源码基线及解释器）、项目 ID、运行 ID、所选 DUT、硬件映射、原测试配置、本机时区和开始时间。核实测试架及资源可用，在软件原入口执行本机确认并启动项目。采样脚本仅观察指定 GUI 进程。外部测试进程需要单独记录 PID 和结果。

在目标机解压带此脚本的验证材料。以下示例在脚本所在目录运行，日志保存在已存在且可写的目录中。通过任务管理器“详细信息”确认当前工作台 PID；源码运行时选择已打开工作台的 Python 进程。

使用便携候选时，按现场记录表运行采样。脚本校验 ZIP 与同次构建的校验文件，并比较所选进程对应的 EXE 与 ZIP 内 EXE。首条记录写入两份哈希和操作员填写的项目、运行 ID。提供 `-ExpectedStartUtc` 时同步核对进程启动时间。校验失败在创建采样文件前结束。[目标机操作与回填表](FIELD_RECORD.md)

下例用于源码版，源码版本和批次信息登记在同批现场记录。

```powershell
$workbenchId = [int](Read-Host '输入目标工作台 PID')
Get-Process -Id $workbenchId | Select-Object Id,ProcessName,StartTime
$trace = Join-Path (Get-Location).Path ('qt-process-' + (Get-Date -Format yyyyMMdd-HHmmss) + '.jsonl')
powershell -NoProfile -ExecutionPolicy Bypass -File .\watch_process.ps1 -TargetProcessId $workbenchId -OutputPath $trace -DurationSeconds 259200 -IntervalSeconds 60
```

72 小时窗口为 259200 秒，24 小时单独实施时使用 86400 秒。同一批次连续观察时可在第 24 小时登记中间结果并继续至 72 小时。保存该批次起始时间、软件日志和过程记录。脚本使用系统 Windows PowerShell，独占新建输出文件并逐条写入。记录头含 PID、进程名、创建时间 UTC 及采样配置。

需要提前结束观察时，在另一 PowerShell 窗口用实际采样文件的完整路径创建停止标记。

```powershell
$trace = Read-Host '本次 JSONL 采样文件的完整路径'
New-Item -ItemType File -Path ($trace + '.stop')
```

## 证据与判读

| 现场时间点 | 需要记录 |
|---|---|
| 启动前、首次稳定采样 | 原配置及任务身份，串口日志目录，空闲时及负载开始后的工作集、专用内存、CPU、线程，资源所有者。截取工作台，注明本地时间 |
| 运行中、24h、72h | 项目与各通道的最近真实上报、已完成/目标轮次、重试与失败原记录、最近日志落盘时间。核对可读日志内容和业务结果。记录同一组界面操作（如切页、查看日志）的实际响应时间，以及队列积压/日志写入错误。按工作负载解释资源变化 |
| 发生失联、异常退出、主机休眠或日志中断 | 保留最后有效样本、DUT/资源状态最后有效证据、重启及重新接管的时间和运行 ID。现场复核后，用新文件采集新的进程段；中间缺口列为未知 |
| 项目停止后和工作台退出前 | 在原入口请求停止，分别记录请求时间、任务终态、读线程退出、串口尾行落盘和租约释放。保留日志目录、原始结果文件及表现异常的通道，复核停止后的资源水平 |

JSONL 的每一行均有 UTC 时间。样本记录进程累计 CPU 秒数、按单核口径计算的区间 CPU 百分比（多核可超过 100）、工作集/专用内存字节和线程数。首样无区间 CPU 百分比。相邻样本实际间隔超过配置的 1.5 倍时标记 `gap=true`，该区间 CPU 比例留空。该阈值只标识采样稀疏，设备和业务健康另由任务、心跳和现场记录判断。

尾行 `observation_window_ended` 表示采样窗口到期，`operator_stop` 表示现场要求停止采样。目标进程退出或读取出错会返回非零，分别记录 `target_exited` 或 `sample_error`；若进程查找、权限、目录或建文件在采样前失败，错误输出到终端。文件缺少结束行时登记观察中断。保留完整文件，并核对采样缺口。

现场结论逐项记录测试条件、实际观察、证据文件路径、异常与复核人。分别判定 GUI 稳定性、任务行为、日志完整性、设备运行和资源释放。进程存活时间与设备连续运行、有效测试时长需要各自的证据。

# Phase 6 串口部分启动与关闭回执

从 Qt 终端沿 QtSerialTerminal、SerialSessionManager、PySerialSession 跟踪启动和退出。Qt 第一次检查日志路径可写后，旧驱动仍需在打开设备后打开实际日志、启动读线程。这两个操作中的任何一个失败，都可能留下已取得的串口和 Windows 系统锁。另一个独立问题是底层驱动 close 抛出异常时，上层却会收到成功。

## 旧行为实测

用原会话与线程、模拟驱动、专用模拟端口和记录释放参数的协调器，在临时目录对三个故障分别取证。

| 注入点 | 模拟驱动 | 系统端口保护 | 原工作区结果 |
| --- | --- | --- | --- |
| 实际日志无法打开 | 仍开着 | 仍保留 | 按正常释放登记 |
| 创建读线程失败 | 仍开着，日志句柄也未关闭 | 仍保留 | 按正常释放登记 |
| 驱动拒绝关闭 | 仍开着 | 仍保留 | 返回成功，按正常释放登记 |

## 本期实现

日志打开失败或在读线程启动前后发生异常时，原会话现先回收已打开的驱动与日志。仅在读线程真正启动过时等待它退出。确认收尾成功后原错误仍返回给调用者，可按原流程重试。

驱动不能确认关闭时，串口进入原有的关闭失败保护。工作区按结果未知登记，保留端口的系统占用，原 Qt 终端展示实际错误，并阻止再次打开。其他通道的监控和日志可以继续。普通关闭、已有升级或写参的所有者、串口读取和等待标记沿用原路径。

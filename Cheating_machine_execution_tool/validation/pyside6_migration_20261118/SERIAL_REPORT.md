> 本报告所列的部分截图和测试输出已在对应验证通过后清理，测试结论与复跑方法见正文。

2026-11-18，分支`feature/pyside6-migration`。本轮继续Phase 5，接入基本串口终端。整套GUI迁移尚未完成，Tk仍为默认正式测试入口，V1.2.10及现有EXE不变；未提交、打包、运行EXE或连接真实串口/DUT。

## 审计与实现边界

原`src/ui/serial_terminal.py`负责Tk窗口、标签、手动发送确认及显示；原`SerialSessionManager`负责按COM共享会话、监控/控制所有权和异步关闭票据；`PySerialSession`负责唯一读取线程、字节历史、原协议发送及日志落盘。旧终端不是可从Qt调用的无GUI业务接口，因此新增独立Qt适配服务管理本机窗口的监控所有权，直接调用原管理器/传输，未调用旧GUI回调，也未复制串口协议或创建隐藏Tk。

不变量来自原串口验收：显式COM优先，缺字段按VLAN映射；默认SerialSettings不变；文本加回车、空回车和危险词确认；升级控制锁；仅释放本标签所有权；原`<vlan>_<COM>_<YYYYMMDD>.log`命名、逐行时间戳与关闭尾行落盘。原Tk窗口、SerialDelivery和传输文件与Phase0备份逐字节核对。

本轮实现：

- 从真实项目详情“串口日志”打开独立Qt窗口，支持键盘/鼠标入口。显示窗口只建立已选VLAN/COM标签，不自动打开设备；“打开全部”才取得监控所有权。
- 打开、手动发送、目录写入和关闭都在原工作区后台队列执行；主线程仅更新控件。复用现有100ms界面定时器，以有在途保护的200ms显示请求读取，不新增窗口定时器/原串口读取线程。
- 文本Enter发送、空输入Enter和“回车”按钮；危险词沿原`reboot/reset/firstboot/tftp/upgrade`二次确认，取消保留输入；成功后清空，失败不重发。发送前复核绑定、会话身份和两分钟一次性确认，并短暂取得原控制所有权，不能抢占升级/其它控制者。
- 逐标签默认取消的关闭确认、停止全部、关闭窗口及项目/应用退出。监控只释放自己，其他所有者保留；等实际关闭票据/读取线程/日志尾行完成。关闭失败保留可见状态及原管理器保护，不把点击关闭当成完成。
- 目录恢复/选择沿项目`ui/serial.json`和原默认项目日志目录，保留旧geometry键，选择目录按原规则加入project_id。已有会话继续原文件，界面显示实际会话文件；新打开监控使用新目录。日志区右键清屏只清显示，目录框右键打开文件夹。
- 复用SerialDelivery身份隔离及BoundedMailbox；单显示事件最多16Ki字符、每标签待显示64Ki字符、2000事件队列、最多5000行且512Ki字符的可视文档；合并/丢弃显示事件明确反馈，原串口落盘不经过这些缓冲。只取当前标签文本，非当前标签有界保留。
- 上翻暂停跟随、回到底部恢复；使用活动文本游标锚点保持裁剪旧行后的阅读内容。长行自动换行，小窗口只需纵向访问，底部输入仍可见。
- `serial.terminal.*`只接受gui来源，AI/远程明确拒绝；既有AI的`serial.send`待接入状态不被Qt手动发送冒充完成。串口输出/手动输入不发给外部服务。

共享连接沿原管理器保留实际参数（包括原持有者使用不同波特率的情况）；新监控不强改参数，手动控制使用同一会话的实际settings。没有日志文件的共享会话明确显示“未启用文件落盘”，不把请求路径冒充实际落盘。发送能力标为dangerous，可能打开COM的发送预检标为modify，显示轮询不取得写权限。

- 本轮完整基线通过：3040项测试、226项指定回归实际执行，296份编译/286份源码登记、能力/GUI覆盖及全部协议项通过，`ALL CHECKS PASSED`、exit 0。串口为已验收功能，本轮Qt迁移按结构边界补跑完整门禁；不沿用前轮2981项冒充本轮。

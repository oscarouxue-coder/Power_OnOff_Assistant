# 全业务老化系统检测预览 · Windows 原生验证

2026-11-24。在 Qt 工作台选择全业务老化项目，点击详情右上角的「系统检测预览…」。宽窗从左侧选择检测项，窄窗使用顶部下拉框。在「检测概览」选择阶段，或点击「阶段对比」并排查看开始基线、运行中、结束。全部观察值显示「无数据」，页面标明「界面预览 / 采集未接入」。

| 检测组 | 检测项 | 字段和解释 |
| --- | --- | --- |
| 进程 | 进程清单、状态与占用、文件描述符 | 进程名称、PID、数量和疑似消失或重启线索；状态、线程、VmSize、VmRSS；实际打开的 FD 数及类型和单列的 FDSize 容量 |
| 内存 | 系统可用内存、Slab 内存 | MemAvailable 和趋势；Slab、SReclaimable、SUnreclaim 和分项趋势。单点下降不足以判断泄漏 |
| 网络 | 套接字 | TCP、UDP、Unix，监听或绑定状态、可判定的方向及分类数量变化 |
| CPU | CPU 使用率 | 使用率和连续样本趋势 |

## 已执行的专项

每档均通过仓库的 `run_gui_child(framework='qt', native_render=True)` 在 Windows 非输入私有桌面执行 `scripts/run_tests.py qt_aging_inspection_probe qt_typed_status_probe -v`。使用生产 MainWindow 和 WorkspaceController，注入三个合成项目和记录调用的工作区替身，停用独立周期轮询。子进程使用 Windows Qt 平台，并断言实际像素比等于目标缩放。

| Qt 缩放 | 专项结果 | 隔离记录 |
| --- | --- | --- |
| 100% | [3 项通过](scale-1/tests.txt) | [8 个受管窗口，零违规](scale-1/isolation.json) |
| 125% | [3 项通过](scale-1.25/tests.txt) | [8 个受管窗口，零违规](scale-1.25/isolation.json) |
| 150% | [3 项通过](scale-1.5/tests.txt) | [8 个受管窗口，零违规](scale-1.5/isolation.json) |

- 每档在 840 和 480 逻辑像素宽的预览窗口逐项浏览七项检测，核查三阶段空态、字段、对比表头和横向滚动范围。在 800 × 550 的工作台内核对入口完整可见并实际打开。
- 同项目刷新保留当前对比视图。切换到同名但不同身份的老化项目后，旧预览关闭，重新打开回到开始基线。切到开关机项目后入口隐藏，触发隐藏按钮也打不开窗口。返回工作台总览会关闭旧预览。
- 在导航、切换与关闭期间，工作区替身记录的调用数为零。文件写入入口、QSettings 写值、线程、子进程和套接字守卫均未记录调用。新窗口内无采集按钮和计时器。另两个既有专项核对逐 DUT 状态及两种项目的业务健康显示。
- 本次五个 Python 文件编译通过，源码编译清单检查通过，已跟踪文件的增量差异格式检查通过。未运行完整基线、全套 Qt 迁移回归或真实采集。

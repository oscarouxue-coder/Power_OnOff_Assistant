# Qt 终态子控制器引用修复及复验（2026-11-25）

## 结论

已在明确批准范围内修复先前已确认的 12 条常驻子控制器反向引用。**正式关闭后，完整空工作区 30/30 轮及含实际合成报告的工作区 30/30 轮，全部 23 类跟踪对象在正常事件处理后弱引用归零，无逐轮主动 GC；完整空工作区最终诊断 GC 不再减少总句柄。** 含报告组正常收尾稳定在 708–721，最后额外诊断 GC 尚有 5 个未知句柄差值，不将其全部归因于原问题，也不宣称无限期无泄漏。

## 修改前确认、安全挂点

目标文件和关闭路径依赖三次独立采样（北京时间 21:35:39、21:36:13、21:37:33），哈希和时间未变化；[开工哈希](workspace-before.json) 保存所有已修改追踪路径和目标 SHA-256。工作区无新活动写入证据，基于已批准范围开始。三处上一轮服务层修复原字节保留。

先在未修改生产代码的真 Qt 原生隔离 fixture 预检两轮，实际顺序均为：

1. 原先排队的 UI 回调已处理。
2. window.destroyed 发出时 window C++ wrapper 已失效，但 controller C++ wrapper 仍有效。
3. 延后到下一轮事件处理时，window、controller、timer 的 C++ wrapper 全部无效。

[预检原文](native-preflight.txt) / [两轮精确顺序](preflight-trace.json)。据此未在 QWidget.destroyed 信号栈中直接解除引用，也未提前到业务 closed 事件。正式应用事件循环退出时原窗口仅正常 close，可能尚存活；需在事件循环返回、原 worker 等待和重启标志读取之后，主动交付该窗口自身 DeferredDelete，而非运行任意全局事件或强制 GC。

## 最小生产差异

- [workspace_controller.py](../../src/ui/qt/workspace_controller.py)：固定 12 个子控制器的所有权清单；只在正式退出许可、adapter worker 确实退出、更新任务无待处理项、service 已合法关闭及 writer 原 report/associate 已确认释放，以及 window/controller/timer 都已销毁后，解除失效的子控制器 workspace 回指。窗口销毁信号只安排弱引用的延期观察，且方法经过幂等保护。拒绝、活跃、归档未确认或仍有 Qt 对象的路径不清理。
- [application.py](../../src/ui/qt/application.py)：原 app.exec 返回、adapter.wait_closed 成功及重启信息读取后，调用合法关闭窗口的显式 DeferredDelete，仅投递该窗口的销毁事件；实际对象失效后释放反向引用，再按原顺序释放实例及可能重启。未更改实例锁、业务任务、网络、权限或设备规则。
- [qt_workbench_probe.py](../../tests/qt_workbench_probe.py)：保留既有断言；新增真正销毁前不释放、销毁后释放、重复终态、最终双归档未确认保留的回归；原活跃/更新/繁忙拒绝/重启顺序原用例加入定向断言。

无生产 gc.collect、无新依赖（isValid 来自既有 PySide6 自带 shiboken6），未修改三服务修复、挂测引擎、资源恢复、AI 模型传输、设备及权限代码。原报告正常/缺失/错误、切换/迟到及停止语义保持。

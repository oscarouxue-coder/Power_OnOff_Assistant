# P0A 真正相反佐证的现有格式边界审计（2026-11-25）

## 结论

**当前 P0A 支持的两类已保存材料投影，无法构造同一事实、同一测量时点的真正相反观测。** 不把不同业务维度、轮次或日志等级当成矛盾。此前 [P0A 报告](../qt_saved_material_summary_20261125/REPORT.md)、[P0B 复核](../qt_saved_material_batch_20261125/REPORT.md) 与 [P0 收口](../qt_p0_closeout_audit_20261125/REPORT.md) 亦一致记录：存在/缺失/失败的真实合成对照已验，真正相互矛盾佐证不具证据。本轮不能升级这一缺口，也不构造虚假格式或在正式 Qt 报告里制造冲突结论。

## 明确现有边界

- [qt_power_logs.py](../../src/services/qt_power_logs.py) 第 167 行：开关机结果仅精确接受 `通道 7 ping 通` 这种正向标记；原文没有可核实时间，投影明确时间未知且不是实时状态。原记录写入处 [powe_on_off_telnet.py](../../Auto_power_on_off_tool/test_case/powe_on_off_telnet.py) 第 607 行也只写无时点的正向标记，不应拿文件名作为该事实测量时点。
- [qt_power_logs.py](../../src/services/qt_power_logs.py) 第 162 行：WiFi 仅投影原时间、通道、轮次和记录等级，业务结果未知。原 [power_test_wifi_log_service.py](../../src/services/power_test_wifi_log_service.py) 第 81 行写入的日志头带时间/级别/上下文；任意正文不属于 P0A 受限观察契约。
- P0A [资料选择](../../src/services/qt_power_logs.py) 第 183 行每通道每种类型至多一个原文件。两类观测没有共同可核实事实身份、测量点或相反结果。即使人为给两个 WiFi 头相同时间和轮次，INFO 与 ERROR 也只是等级；不能表明相同事实一真一假。
- [已有合成服务测试](../../tests/test_qt_log_history.py) 和 [实际 Qt 原生测试](../../tests/qt_workbench_probe.py) 验证真实界面保留来源定位、未知/非实时以及缺失和读取失败；不给它们新增“相矛盾事实已验证”标签。P1 已保存报告仍只保留这些原受限投影，不另行推断。

## 独立合成格式验证

[format_probe.py](format_probe.py)，仅本地纯投影函数、五个合成输入、禁真实 HTTP/串口/socket/外部启动，退出 0，保护入口调用全 0。[格式实测 JSON](format-observation.json) / [测试输出](probe-output.txt)：

| 合成输入类别 | 实际投影 |
|---|---|
| 现有正向 Ping 标记 | 原记录 Ping 通，时间未知，非实时 |
| 假设反向 Ping 文本 | 不接受（None） |
| 假设带时间的正向 Ping 文本 | 不接受（None） |
| 相同时间、轮次的 INFO WiFi 头 | INFO，业务结果未知 |
| 相同时间、轮次的 ERROR WiFi 头 | ERROR，业务结果未知 |

两种假设文本只是确认边界，**并非真实已支持的反向记录格式**。WiFi 合成正文未进入投影。此为五个输入断言的纯本地格式审计，不是正式 Qt 真矛盾报告测试，更不是 P0A 冲突验收通过。未重复跑已通过的 Qt 报告功能/原材料保全专项。没有新发现的错误展示，未修改生产或既有测试。

## 如要真正补足这项验收

先取得原生产记录确实持有的同一事实身份、同一测量点/时间、同一目标及可比较的相反结果的安全契约。必须能够在原支持格式内核对它，而不是从等级、文件名、轮次或自由日志正文猜测，也不据此选择某个结论、判定根因或宣称实时状态。如果两类现有格式不提供这些信息，增加记录字段或受限解析新语义不是单纯 Qt 显示调整；须单独审定业务/数据契约，本轮停在此明确缺口。

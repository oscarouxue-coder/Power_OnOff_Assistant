# 多实例远程 AI 接入实施计划

2026-11-15：合并负责人七项补充要求，后续已授权开始分阶段代码实施。首批身份/槽位、配对/认证通信、投递去重/确认、Agent/Job关联及主机资源保护已进入源码；命令行网关与显式源码实例入口可运行，Fake升级端到端及专项结果见DEVELOPMENT_LOG。原GUI配对表单、群内审批/跨实例业务取消及真实平台/VPN/DUT验收尚未完成，不将首批表述为最终方案全部交付。

## 1. 目标、部署与职责

- 钉钉、飞书各复用一个现有应用机器人；一台常开 Windows 电脑运行独立网关，多个 LineCheckAssistant 实例主动连接。部分测试电脑跨网，使用现有 VPN 或单位认可的虚拟局域网。
- 网关只负责平台身份接收校验、实例接入认证、授权可见实例列表、目标选择、消息可靠转发及回复关联。不加载模型，不运行 Agent，不执行设备命令，不实现业务 Capability、业务 Job Manager 或风险批准策略。
- 实例继续通过现有 AiConversationService / AiSessionRouter、AiCapabilityAdapter、Capability Registry、Capability Service、CapabilityJobs 和资源保护运行业务；完全访问用户可调用该实例**已经开放且在本地授权范围内**的业务，包括后续完成接入的固件升级、老化挂测、供电、写参、DUT 和 ONU 管理。
- 运行时目录存在文件、GUI 有按钮、业务清单标记或通用 Shell 可以操作，均不构成远程能力已开放的依据。待接入能力返回明确的未开放结果，网关不补做业务执行。
- 实例与网关均不自动启动真实测试。此次实施验证限 Mock/Fake、本机隔离通信和离屏 Tk；真实平台、VPN、Windows 可见界面及真实 DUT 由负责人另行验收。不提交、不打包、不运行新 EXE。

```text
钉钉 / 飞书可信平台事件
          ↓
常开电脑网关：认证、选择实例、可靠消息及回复关联
          ↓ 认证后的主动连接（VPN / 虚拟局域网）
实例 A 的 Agent       实例 B 的 Agent       实例 C 的 Agent
          ↓ 各自现有 Capability / Job / 资源准入
各实例获准操作的电脑、设备、通道和业务任务
```

## 2. 实例身份、存储与权限

### 2.1 永久身份与启动身份

- `instance_id`：随机 UUID，属于本机 Windows 用户、程序目录及一个持久化实例槽位；名称、电脑名和项目名仅是显示信息，不能用作认证或唯一键。
- 身份、凭据和槽位数据保存在程序目录外的本机用户数据区，按规范化程序目录分区；不进入源码、便携 ZIP 或项目配置。复制程序到另一目录/电脑会创建新身份并重新配对，不能继承原实例权限。原路径原槽位更新程序保留身份。
- 同一程序目录多开时原子申请空闲槽位，每个槽位有独立永久身份、会话库和现有业务任务库；槽位同一时刻只允许一个进程持有。空闲槽位可再次使用，历史和任务记录随槽位保留；界面显示槽位及实例编号。不得让后启动进程打开同一业务库并将前进程活动任务标成中断。
- `run_id`：每次主程序启动生成新的 UUID；网络重连和网关重启不更换此 ID。协议中的 run_id 是进程启动身份；现有会话的 run_id 是诊断/挂测批次，两者分字段保存，不复用、覆盖或互相推导。
- 连接、请求和审批同时绑定 instance_id + run_id。发现同一永久身份有另一活动启动身份时拒绝接管，要求核对、离线确认或撤销重配；不因后连入而踢掉原连接。
- 实例重启使旧的活动选择、未执行请求及旧审批失效，不能自动转向同名实例或新 run。历史任务可在重新选定同一永久实例且通过当前只读权限验证后查询；返回原 run_id，不将历史任务恢复为可执行操作。

### 2.2 可信身份与本地授权

- 身份边界包含平台、应用机器人、企业、聊天类型、群/单聊 ID、成员、永久实例；授权另外绑定目标通道/设备、允许的能力/操作范围和本地授权版本。网关与实例各自验证，权限取两端允许范围的交集。
- 平台身份只能来自现有钉钉/飞书接收适配器验证后的事件，不能从聊天正文提取。网关管理接口仅本机操作员可用，不向聊天或实例开放“伪造平台事件”接口。
- 实例通过已配对网关的认证连接接收结构化身份，独立检查凭据、消息认证/有效期、instance_id、run_id、本地允许的平台/企业/聊天/成员及操作范围；不能接收或信任正文/协议中的 approved、full_access 或 grant_id 声明。
- 配对只建立连接信任，不授予业务完全访问。首次接入默认停用远程执行；本地操作员确认聊天/成员及范围后启用。完全访问继续由现有权限服务创建有效 grant，绑定当前会话、目标、模型、批次、实例和启动身份；网关不发放 grant。实际降权和失效沿用现有服务，不新建平行权限系统。
- 启用全部群成员或全部已开放能力必须在本地明确确认；新接入的实例不继承既有飞书“默认完全访问”偏好作为有效授权。AI 可整理申请材料，不能调用授权、配对确认、提权或批准自己的操作。
- 查询历史 Job、停止业务、批准操作同样验证当前身份与范围；只读权限不因任务已结束而扩大。审批仍验证原发起人、原操作指纹、原会话和有效期，切换实例不改变审批归属。
- 稳定业务 principal 纳入永久实例，但不随 run_id 变化，便于同一真实成员重启后读取有权查看的旧结果；执行授权和审批另外绑定原启动身份。直接接入旧身份键保持兼容，网关来源通过显式来源字段扩展，禁止默默改变既有会话归属。

## 3. 消息、业务任务与恢复

### 3.1 最小接口与确认语义

采用独立数据模型及有版本的消息协议；在实现前用契约测试锁定以下接口，不新增设备业务 API：

| 类别 | 必需关联字段/行为 |
|---|---|
| 实例登记/心跳 | protocol_version、instance_id、run_id、显示名、项目、能力目录版本；认证凭据独立于业务参数 |
| 用户请求 | 稳定 message_id、request_id、经校验的来源身份、instance_id、run_id、创建/失效时间、原用户正文；不包含权限授予字段 |
| 接收确认 | request_id、目标双身份、received/rejected；仅表示实例已持久化接收或明确拒绝，不等于业务启动/成功 |
| 会话关联 | request_id、实例内部会话/真实用户轮次标识；相同请求始终关联原轮次，不再次送入模型 |
| 业务关联 | request_id、operation_id、现有 job_id、目标设备/通道、原始 run_id；由实例真实执行结果生成 |
| 回复/增量事件 | 稳定 reply_id、原请求/会话/任务关联、event_id/游标；持久化接收确认与平台发送结果分别记录 |
| 查询/取消/审批 | 明确原 instance_id/run_id、job_id 或审批 token；实例再次做可信身份、范围及指纹检查 |

- 平台 message_id 与平台/应用/企业/聊天组合形成稳定去重键，不单用正文、昵称或当前所选实例。选择过程只为请求绑定一次目标，重复平台事件不能在切换后落入另一实例。
- 网关持久化入站消息和目标绑定，再确认平台接收；长耗时模型/业务不在平台回调内等待。实例必须先原子持久化 inbox 去重记录，再确认并启动会话处理。
- 相同消息重复抵达或确认丢失，只查询/返回原接收状态及关联，不生成新用户轮次或 operation_id。正文/目标在相同 ID 下变化时拒绝，不解释为新的操作。
- 新请求有效期60秒，实例收到超过期限的请求不执行。超时区分未接收、已接收待处理、已启动任务和结果未知；不得把超时显示为操作失败并自动重试。
- 网关重启时未确认请求标记“待核实”，通过原实例同一 run 的 inbox/请求状态查询恢复关联；不直接重发执行。实例进程重启时未完成接收处理标记中断/未知，不重新送入 Agent。

### 3.2 复用现有 Job 和幂等机制

- 网关 SQLite 只保存身份注册、配对/撤销、成员选择、消息收发状态、回复游标和 request→会话/job 关联；**不复制业务参数快照、执行状态机、业务恢复或 Job 取消控制**。业务真相及历史结果仍在各实例现有 CapabilityJobs 中。
- 将可信入站 request_id 映射为实例本地唯一用户轮次，接入 AiCapabilityAdapter 的现有 operation_id 生成链，再复用 CapabilityJobs 的 request_key + 参数指纹。模型不得提供幂等键；不同工具步骤仍保留各自操作关联，不把整段对话折叠成一个业务操作。
- 固件升级、程控电源、写参、ONU 删除等修改能力，只有通过本地共享执行服务的持久化幂等、未知结果拦截和资源准入测试，才可标记为远程开放。同一操作键改参数必须拒绝；unknown 不以新键自动重跑，必须走原业务明确核实流程。
- 已准入长任务继续在本地 Job Manager 运行；网关/机器人断线、模型超时、切换实例、停止聊天不会调用 jobs.begin_close/cancel 或撤销其已准入业务控制。只有明确的业务取消或本机应用退出按原安全边界处理。
- 实例进程退出/崩溃不承诺任务继续：沿用 CapabilityJobs 将未完成任务标记 unknown，禁止自动恢复设备操作。网关恢复只是恢复消息关联和结果查询。
- 当前资源服务主要提供进程内准入。同机多开上线前，在现有资源保护层补齐真实 COM、网卡、供电组、设备/OLT 等共享资源的跨进程互斥；按实际能力使用的资源键准入。所有相关 GUI/Agent 共用边界，不能只在网关加锁或以独立数据库代替资源互斥。未知结果形成的资源保护同样不能因更换实例槽位绕过。

### 3.3 连接与结果恢复

- 实例主动连接，使用现有固定依赖 websockets==15.0.1；业务接口不接受未经认证的连接。VPN/虚拟局域网提供传输保护，应用层仍认证每个实例并防重放；WSS 验证证书，不使用跳过验证配置。
- 心跳15秒，60秒未收到标记离线；离线24小时从默认列表隐藏，历史身份和关联不删除。离线实例不接受新业务请求，不自动转向其它实例。
- 断线按1、2、4、8、16、30秒上限退避并加入抖动；恢复后先验证身份并交换确认游标，再同步持久化回复和查询状态，不重建执行请求。
- 业务 Job 状态/增量事件从原 Job Manager 读取，按回复ID和事件游标恢复；成员恢复连接或发送查询后可查回原结果。平台发送成功与本地持久化成功分别标注。平台回复确认丢失可能导致文本重复，不能宣称端到端恰好一次；即使重复回复，也不得重复业务操作。
- 网关持久化实例注册、凭据撤销、授权可见范围、成员选择和消息关联。启动时所有连接先视为离线，重新认证后的同一 run 可恢复选择；新 run 需成员重新确认。
- 机器人应用密钥仅在网关使用 Windows DPAPI 保存；每个实例接入凭据单独生成、加密保存、独立撤销，轮换不影响其它实例。一次性配对码5分钟过期且只可消费一次；网关生成候选后本地确认其身份/聊天范围才正式启用。
- 网关为本机操作员提供启动、配对、撤销、状态与审计入口；默认只绑定明确配置的 VPN/局域网地址，不绑定所有接口。无认证、失败认证或已撤销实例不得获得在线列表、消息或控制能力。
- 网关连接异常、平台断线、实例离线、队列满、磁盘/持久化失败、转发超时和恢复均写网关日志；实例关键阶段及实际业务命令写现有主执行日志。网关完全宕机时依靠实例本地动态状态/日志告警，不能承诺宕机网关还能向群发送告警；恢复后补发一次状态摘要。

## 4. 使用方式与兼容

- AI“远程管理”新增独立的统一入口页，保留原钉钉/飞书直接接入；两种模式互斥，切换前等待原消息/审批处理结束，不自动转换正在运行的会话。机器人凭据仅网关直接接入平台，实例统一模式不再占用该平台 Stream。
- 实例页配置入口地址、名称/槽位、配对及本地允许范围；常用保存/启停保留必要按钮，其余操作按需菜单，不增加常驻说明。布尔控件用原生 Checkbutton、背景用 apply_module_theme；危险授权确认必须显示范围。
- 群文字支持“在线实例”“切换实例 <编号/唯一名称>”“当前实例”；消息中明确写实例名称/编号也可选目标。成员首次选定后沿用，按平台/企业/聊天/成员分别记录，互不影响。重名、不明确或离线时追问并保留原问题，不猜测第一个目标。
- 普通追问沿用该成员当前实例；引用别的实例日志或比较设备不自行切换。第一版一次排障请求只面向一个实例，实例内部多通道任务继续走现有编排。
- 操作回复标题包含可读实例名及编号、设备标识/通道、job_id；未创建业务 Job 的会话/转发反馈显示 request_id 并标注“尚未启动业务任务”，没有设备目标时显示“本机/普通问答”，不编造设备或任务成功结论。
- “停止”仍停止当前聊天；明确“停止任务 <任务ID>”才调用现有取消业务能力。查询任务和批准编号根据原任务关联定位，**不根据成员当前所选实例改路由**。目标实例还需复核原归属，过期、跨成员、跨 run 的审批拒绝。
- 不迁移或覆盖原机器人/本机配置；新来源会话与旧来源隔离，旧历史可读。网关只存最小必要聊天关联，回复使用已有远程凭据过滤和飞书富文本格式，不引入新的未过滤外发出口。

### 5.2 分阶段实施与门禁

1. **契约与依赖补齐**：锁定身份/请求/授权接口，补特征测试；在 Full Capability Agent 原层扩展稳定业务 principal、实例启动授权、可信轮次幂等关联及跨进程资源保护。保留原直接来源及旧存储兼容；网关模式默认关闭。
2. **网关基础与消息链路**：独立 models/core/services 模块实现配对、认证连接、永久/启动登记、成员目标选择、持久化 inbox/outbox、确认、超时、心跳、撤销和查询恢复；全程 Fake 入口/实例，不接设备。此阶段无需等待所有业务都接完。
3. **实例 Agent 桥与首批业务**：在现有控制器增加生命周期装配，独立 service 桥接到现有 Agent/权限/Job；先以固件升级 Fake 引擎验证真实工具链路、完全访问和逐项批准。不能把“网关成功转发”标为“完整业务能力完成”。
4. **按能力接续**：依 Full Capability Agent 当前覆盖矩阵逐项接续已完成且通过验证的供电/老化/DUT/写参/ONU等；复用原 Job 和业务执行器，补跨实例断线/恢复契约测试。网关协议不随单个业务增加而复制业务参数模型。
5. **界面、文档与验收**：补统一入口配置页、主日志和使用说明；审查覆盖矩阵与GUI动作并执行覆盖更新门禁。专项及完整基线通过后由负责人完成真实群聊、多电脑/VPN、Windows可见和授权范围内DUT验收；另行要求时才标准打包。

分工按模块边界划分，不要求并行代理：Full Capability Agent 负责业务工具、Job 持久化/幂等和资源保护；本方案负责网关、实例接入与消息关联；身份/权限接口共同衔接，保持只有一套执行和授权真相。

## 6. Mock/Fake 测试与验收标准

| 场景 | 必须断言 |
|---|---|
| 多人并发选实例 | 两成员分别选择/切换后互不影响；同成员跨群、企业、平台不串会话或权限 |
| 身份及复制/多开 | 不同电脑/目录/槽位的永久身份不同；同槽位重启永久身份不变、run改变；复制凭据/活动重复身份拒绝；原物理资源冲突被拒绝 |
| 目标误选/歧义 | 重名、离线、启动变化、失效选择均不下发；显式切换只影响后续普通请求；旧任务结果/审批仍回原关联 |
| 身份越权/提权 | 伪造成员/企业/聊天/目标、已撤销凭据、过期/篡改/重放请求、模型提供approved/grant、超范围设备/能力均无执行；AI不能调用权限控制面 |
| 重复消息/确认丢失 | 同message/request的并发、延迟和重投只进入一次Agent轮次；只启动一个原job；相同ID改参数拒绝；不能靠换所选实例绕过去重 |
| 网关重启 | 在线先失效再认证；同run恢复关联；未确认请求先查状态不重新执行；选择、凭据撤销、回复/事件游标恢复 |
| 实例重启 | 新run拒绝旧请求/审批；未完成Job保守unknown，不重启设备任务；合法成员重新选定后只读查询旧任务；跨实例Job ID不能读取 |
| 长任务中断聊天 | Fake老化/升级开始后断开网关、停止对话、切换实例，原Job仍运行；只有明确业务取消使用原安全停止控制；重连后可查询原结果 |
| 未知结果 | Fake引擎已下发后超时/异常/进程中断保守unknown；不自动换request/operation键重试供电、刷写、写参或ONU删除 |
| 审批及范围变化 | 只有真实原发起人/本地操作员批准；切换不改对象，跨run/过期/指纹变化拒绝；运行前再次检查降权、目标变更和物理资源占用 |
| 回复与可靠性 | 每个业务结果带实例、设备/通道、原job_id；无job不冒充业务已启动；回复确认丢失至多影响文本重复，不改变业务；恢复查询有权限且不重执行 |
| 故障与兼容 | 磁盘/数据库失败、队列满、网关不可达、平台单独断线有清晰状态；旧直接接入、模型偏好、设备命令、停止和权限行为不回归 |

- 先用临时数据库、Fake平台/Fake连接/Fake业务引擎和可控时钟验证上述断点；再以真实本机隔离通信验证认证/确认，不读取个人凭据或操作真实DUT。
- 新源码纳入 PY_COMPILE_FILES；新增GUI业务审查覆盖台账并运行 `python scripts/verify_capability_coverage.py --update` 及相关测试。不能只更新快照而把未接入能力标成完成。
- 结构/授权接入前先跑现有相关特征测试，完成后按本方案运行 `python scripts/verify_baseline.py` 完整基线，保留实际输出。已通过历史记录不能替代本轮检查。
- 文档实施时更新 DEVELOPMENT_LOG、PROJECT_STATUS、操作员README及ACCEPTANCE_BASELINE对应状态/待确认项；实际平台和DUT验收只能由负责人提供结论。当前文档修订不提升任何验收状态。

## 7. 回退与当前交付边界

- 可分阶段关闭统一接入并恢复原直接模式；活动业务先按现有安全边界结束或由负责人明确取消，再卸载相关装配，不能用网关停止中断设备操作。
- 保留全部永久身份/撤销记录、消息审计和原Job库；回退不删除数据库、不重新分配旧任务、不恢复旧审批或执行未完成请求。
- 首批交付源码命令行网关、显式`--gateway-slot`实例装配及Mock/Fake回归。后续补齐GUI配对/授权体验、原任务审批/业务取消路由、跨用户/不同网络和真实平台验收；每阶段记录实际代码与验证，不将源码通过升级为现场验收。

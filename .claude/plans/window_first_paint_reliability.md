# 复杂配置窗口首次绘制可靠性计划

## 目标

- “测试项配置”和“DUT配置”首次打开时直接完整显示，不出现透明客户区。
- 不依赖移动鼠标、切换窗口或其它操作触发重绘。
- 首次创建和复用现有窗口使用同一显示路径。

## 实现

1. 现场先后确认透明预布局/原生重绘方案、Git提交`93b33aae`的历史隐藏构建方案在当前版本均无效。
2. 源码探针测得测试项配置和DUT配置构建分别约0.155秒和0.077秒，不存在必须隐藏构建的长耗时。
3. 移除两个异常窗口独有的`withdraw → after(0) → deiconify → update()`生命周期，首次创建改为与样机升级、写参和ONU注册相同的标准`Toplevel`自然映射，由Tk主事件循环完成首次绘制。
4. 复用已有窗口时只执行标准`deiconify → lift → focus_force`；DUT状态高度校正继续通过`after_idle`执行，不嵌套调用`update()`。
5. 项目负责人照片进一步确认故障是“标题栏已绘制、Tk客户区首帧未提交”，而不是Layered透明窗口；本机原生诊断也确认窗口无`WS_EX_LAYERED`、DWM未cloaked且客户区尺寸正常。
6. 在标准映射后的120ms和360ms分别执行一次可恢复的1像素宽度脉冲，触发Windows`WM_SIZE/WM_PAINT`对子控件树整体重新布局和提交；每次立即恢复原尺寸和位置，不改变DUT窗口尺寸记忆。

## 验证

- 回归测试锁定两个窗口首次创建不得使用隐藏、强制映射或嵌套`update()`，复用显示保留标准置顶聚焦。
- 回归测试锁定两次刷新时机、1像素脉冲和完整几何恢复，并覆盖销毁/失效窗口安全边界。
- 主界面和DUT窗口源码接线回归。
- `python scripts\verify_baseline.py`。
- Windows桌面分别多次打开“测试项配置”和“DUT配置”，确认无需移动鼠标即可完整显示。

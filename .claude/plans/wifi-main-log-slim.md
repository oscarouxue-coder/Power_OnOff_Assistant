# 精简正式开关机测试的 WiFi 主界面日志

## 目标和范围

- 仅精简正式开关机测试及失败通道续跑的 `[旧工具Logs][级别] [WiFi测试]` 主界面显示。
- 主日志文件继续逐条保存目前传入 `_log` 的原文，包含时间戳；原有子进程日志生成、过滤和去重保持不变。
- DUT配置窗口的UBUS查询/配置日志、其它功能日志保持原样。不调整DNS、Ping计时/判据、重试、线程、停止、设备命令、配置或发布版本。

## 实现

- 新增独立显示模块 `Cheating_machine_execution_tool/src/ui/main_log_filter.py`，提供纯函数 `format_main_log_message(message: str) -> str | None`；返回None只表示不插入主界面，不影响文件保存。
- 严格匹配旧工具WiFi前缀。非目标日志原样返回。WARNING/ERROR及包含异常、失败、未通过、取消、跳过的目标日志保留；未知WiFi文本保守保留，不按INFO级别一刀切。
- 保留首次WiFi信息摘要（包括已经授权的SSID/密码）、读取开始、入队占用、取得使用权及实际等待时长、实际无线接口、每次连接尝试、实际临时连接下发、连接核验结果、无线Ping开始的源IP/目标IP、Ping汇总，以及停止/异常和释放使用权。
- 隐藏已知过程细节：每条只读查询命令/回显隐藏提示、逐频段目标读取摘要、双频合一状态、每10秒排队提示、无线扫描提示、连接前目标SSID摘要、等待10秒重试提示（前一条未通过原因及下一次尝试保留）、等待IPv4提示、DNS查询/地址列表、逐包Ping下发/回复/超时、成功后的重复“本项无线测试通过”、临时连接断开/清理成功。清理失败等异常始终保留。
- 可见WiFi前缀统一为 `[WiFi]`，保留通道、轮次、频段；从重复行移除 `网卡=<名称>`，实际无线接口行继续提供接口名称/GUID/ifIndex。原文完整写入文件，不修改已有授权的凭据内容。
- `line_check_assistant/app.py::_log` 只调用显示函数并按其返回值执行现有Text插入/颜色流程；原文写文件无论是否显示均执行且仅执行一次。颜色按原始消息判断，外部显式tag保持有效。
- 新模块纳入 `scripts/verify_baseline.py` 编译清单。不新增设置或持久化键，不引入依赖。

- 使用临时日志文件和模拟Text控件调用真实 `_log`：隐藏内容仍完整落盘，可见内容无重复，颜色及显式tag保留；不接设备。

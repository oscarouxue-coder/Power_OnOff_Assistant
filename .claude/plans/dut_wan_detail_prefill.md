# DUT WAN 查询详情回填计划

## 目标

“查询现有 WAN”不再只返回连接名；选择下拉项后，将设备当前 WAN 的业务类型、VLAN、模式、接入方式、协议、地址方式、MTU、NAT、端口绑定及可读取的静态地址/PPPoE 参数同步到修改表单。

## 实施边界

1. 协议层一次只读查询 WAN 所需 BBFDM 多路径，并解析为独立快照模型，不导入旧 `SdmcUbusLib` 的共享 Session。
2. 批量查询继续只允许名称完全一致的共同 WAN；完整参数也必须在所有目标上一致才允许自动回填。
3. UI 只负责把快照映射为表单值；切换下拉项立即更新，不执行写操作。
4. 继续保留目标变化、查询失败、配置完成后的缓存失效规则，以及设备端 Session 注销。
5. 新增 core、service、UI 映射回归并纳入 `verify_baseline.py`。

## 验收重点

- `3_INTERNET_R_VID_172` 至少显示业务类型 `INTERNET`、业务 VLAN `172`、路由、IPoE、IPv4 DHCP、MTU 1500 等实际查询值。
- PPPoE、桥接、IPv6/双栈和静态地址按设备返回回填并遵守现有表单显隐规则。
- 多台同名 WAN 参数不一致时不拿任意一台覆盖批量表单，界面明确提示人工核对。

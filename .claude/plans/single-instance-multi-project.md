# 单实例多项目管理（2026-11-17）

负责人已确认并要求实施：单窗口项目列表、全部现有业务按项目隔离、独立项目文件夹、统一模型/平台接入、显式保存和恢复草稿、首轮4项目并行模拟验收。预览后进一步确认侧栏必须可收起；收起后通过项目菜单切换。

## 架构与不变量

- 一个ProjectWorkspace/Tk根窗口，项目视图为独立Frame，保留兼容的LineCheckAssistant独立入口。切换只显隐视图，不替换全局配置变量、不停止任务。
- `project.linecheck.json`持有稳定UUID、格式版本和已保存配置版本；项目内draft、revisions、runs、history、ui、inputs、logs分别承载编辑草稿、提交版本、任务快照、历史、界面状态、输入和日志。
- 项目上下文显式传入业务/能力装配。现有store在已准入任务线程内读取固定配置快照，旧开关机子进程只改变自身工作目录，业务源码仍来自程序包。
- GUI与AI复用现有service、Capability/Job、确认和安全停止逻辑；跨项目共享资源准入与现有跨进程锁，不能利用同进程重入穿透项目隔离。不同项目的相同通道编号不代表相同物理资源。
- 模型账户在当前用户workspace目录统一加密保存；项目历史和模型选择独立。平台只保留一条连接，明确选择项目，审批仍回原项目，接入和远程项目范围均为本机控制面。
- 保留原设备命令、Boot/TFTP/刷写时序、源IP绑定、并行钳制、PASS/FAIL和已有安全停止规则。预备测试仍是明确确认后使用当前页面的独立快照，不把它改成正式挂测。

## 实施与验证

1. 项目身份/路径、版本化保存、恢复草稿、复制与旧配置导入；先用临时目录验证失败回退、身份冲突、目录移动。
2. 可收起侧栏装配、窗口及回调生命周期隔离；以离屏真实Tk验证4视图只使用一个根窗口，关闭后台项目不改变当前选择。
3. GUI/AI任务资源协调和固定运行配置；Mock/Fake验证4项目并行、单项目停止、保存期间快照不变以及资源冲突/未知保护。
4. 统一模型/平台和实例内项目路由；Fake验证显式项目、去重、跨项目审批归属、撤销范围、历史导入不重放。同步能力目录及机器清单。
5. 专项回归、完整`python scripts/verify_baseline.py`、源码清单/协议不变量/能力覆盖及差异检查；Windows完整可见交互、平台/模型及DUT结论由负责人复验。

## 兼容与回退

- 旧配置目录、旧AI原库和设备验收历史保留；导入写入新项目目录。历史审批、恢复操作和活动任务不自动执行。
- `python run_line_check_assistant.py --legacy-single-project`或`LINECHECK_LEGACY_SINGLE_PROJECT=1`保留原程序目录配置入口，仅用于兼容回退。
- 新主入口支持项目路径参数；同用户会话的重复启动通过本机认证管道唤起既有窗口，不启动第二套项目管理器。
- 保留便携EXE/ZIP及既有标准构建门禁。本轮不构建、不发布、不运行EXE、不连接真实设备或平台。安装程序另立需求。

## 验收边界

这是当前明确需求触发的项目运行边界调整，不做无关文件整理。单进程提供配置和任务归属隔离，不承诺进程崩溃时其它项目继续运行。自动化检查不替代Windows/平台/设备现场验收；实际命令、数量、失败和收尾结果记录在DEVELOPMENT_LOG.md。

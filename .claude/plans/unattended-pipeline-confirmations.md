# 全流程无人值守子任务确认

## 已确认范围

- 用户已授权实现无人值守模式。
- 仅覆盖全流程中的子任务 3「样机升级」和子任务 4「写样机参数」。
- ONU 注册、自动重试、设备命令、停止时序和单独工具栏入口不改变。

## 不可变行为

- 默认仍为人工确认；单独执行升级或写参时继续显示原确认框。
- 无人值守必须由本次全流程窗口显式选择，并在总确认框中展示升级和写参风险摘要。
- 配置缺失、预检失败、无程控电源而需要人工重启、子任务失败或停止时，不静默继续。
- 任何写操作不自动重试；失败仍停止后续致命子任务并保留日志。

## 实施步骤

1. 在全流程窗口增加默认关闭、非持久化的 Windows 原生「无人值守」勾选项，并将选择传入本次运行上下文。
2. 扩展总确认摘要，明确显示该模式仅跳过升级和写参的子任务确认，并列出实际升级/写参风险配置。
3. 让主程序的全流程升级/写参入口接收一次性跳过确认标记；正常入口仍使用原确认框。
4. 为两种模式、总确认摘要、失败/停止边界补回归；同步验收基线、操作员说明和开发记录。
5. 运行专项测试与 `python scripts\verify_baseline.py`；完成后进行 Windows 源码版复验，不进行真实设备写入。

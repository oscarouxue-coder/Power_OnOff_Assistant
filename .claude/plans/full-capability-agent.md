# Full Capability Agent 实施与回退台账

2026-11-15，负责人已确认完整审计方案及效率、任务独立、远程身份隔离补充要求。

## 目标和不可变边界

- 最终覆盖全部适合自动化的 GUI 业务；升级是首批，不是项目完成标志。未接入、未验证和人工控制面始终保留在覆盖矩阵。
- GUI/AI 共用业务执行服务，不模拟按钮，不调用含窗口生命周期的 GUI 回调。
- 高频业务直接提供 schema 并缓存；execute 内部做校验/权限/实时预检，不要求 list/describe/validate 多轮往返。
- 已准入任务独立于模型请求、对话停止及窗口隐藏；只有明确业务取消/应用退出才按安全边界停止。未知结果不自动重放。
- 保持三档权限及本地/平台/企业/聊天/用户/目标来源隔离，AI 不自我授权；A1/A2 不放宽，A7 只读监测不改接收/缓冲/落盘。
- 四种升级引擎、源 IP、并行上限、命令/重试条件、恢复出厂默认和安全停止保持；默认不增加刷后登录。适配未知由负责人明确确认并绑定目标/文件哈希。
- 先补等效受控本机/文件接口再迁移通用工具。扩展须本地负责人审阅代码哈希/版本/参数/资源/权限，不能由模型批准。
- 不执行真实 DUT、断电、刷写、打包、提交或发布。

## 独立阶段

1. 当前基线复核、机器覆盖清单/矩阵及新增 GUI 动作门禁。
2. Registry、schema 缓存/快捷工具、独立持久化 job、资源租约、审计与指标。
3. 升级共享业务适配、实时预检、权限/来源、后台任务、Mock/Fake 和完整回归。
4. 按覆盖矩阵逐模块接入挂测/供电、配置/写参、DUT、ONU、日志/数据、通知和更新；每模块独立测试，不批量重写旧代码。
5. 等效通用工具/文件工作区及版本化扩展迁移；整体验收。

每阶段记录实际完成、检查和剩余项，不能将目录登记当作可执行覆盖。回退按相反依赖顺序：业务接入 -> AI 工具装配/GUI适配 -> 核心目录与任务设施；保留任务记录、原始日志和个人配置，活动危险任务结束前不热卸载。

## 多实例远程接入依赖交接（2026-11-15，设计待实施）

配套方案见[多实例远程AI接入](multi-instance-remote-ai.md)。统一网关只认证身份、选择实例和转发消息，不另建Agent、业务工具、Job Manager或授权策略。Full Capability Agent继续负责已注册业务、持久化幂等、未知结果保护及资源准入；网关只保存消息/回复投递状态和原任务关联。

- 接入前置：永久instance_id与每次进程启动run_id分离；现有会话run_id仍是诊断批次。业务principal纳入永久实例，执行grant/审批另外绑定启动身份；保留旧直接来源兼容。可信request_id进入原用户轮次/operation_id链，不允许模型或网关声明approved/full_access作为授权。
- 同机多开前置：每个持久槽位独立会话/业务库且原子独占；在现有资源层补真实物理资源的跨进程保护及未知结果保护，不能仅删除原目录互斥、共开Job库或只在网关加锁。
- 现有CapabilityJobs及AiPermissionService是唯一业务任务/权限真相；需要的身份、范围检查及关联增量在原层完成。查询旧Job须验证当前范围；未知结果不换新键自动重试。网关断线/聊天停止不取消已准入任务，实例进程退出仍按原策略保守unknown。
- 首批用固件升级Fake引擎联调；供电、老化、DUT、写参与ONU按本台账逐项完成并验证后再开放。进行中的capability_device_services源码不等同于覆盖矩阵已接通或现场验收，网关不得通过通用Shell补齐pending业务。

多实例首批后续已按负责人指令进入源码实施：复用现有Agent/Capability/Job，以可信来源扩展、独立槽位数据、原request/operation/job关联及资源层系统互斥衔接，不另建业务执行器。实际文件、Mock/Fake及本轮完整验证见DEVELOPMENT_LOG；GUI配对、群内审批/跨实例取消及真实平台/VPN/DUT仍待后续，不改变下方首批历史验证记录。

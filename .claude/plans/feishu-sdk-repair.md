# 缺少飞书SDK时按需安装并重启

负责人已确认：仅在缺少飞书SDK的原错误弹窗中增加“安装并重启”；“确定”、Esc和关闭不安装。活动任务存在时拒绝修复，由操作员结束后重试，不自动停止任务或等待执行。

- 使用专门异常识别缺包，其他错误保留原提示；源码虚拟环境才提供安装，EXE引导更新完整ZIP。
- UI独立模块；service协调后台安装、维护占用及验证；core负责锁定依赖、子进程和等待原进程退出后的重启。当前解释器安装，不修改全局Python，不升级工具链。
- 下载飞书及必要依赖的wheel，全部核对现有锁定清单，再离线安装；验证版本、真实SDK导入与pip check。安装失败保留原程序，不重启。
- 安装期间模态窗口和维护准入阻止新业务；同环境实例占用拒绝修复，修复期间的新源码实例在导入主程序前检查同一互斥量。关闭期间不强杀；同解释器、工作目录及业务参数仅重启一次，不携带IDE参数，不重放群绑定或启用操作。
- 依赖安装/重启是人工控制面，AI不可代确认；登记覆盖清单、编译清单，更新操作员README、状态、验收边界与开发日志。
- 验证缺包异常、取消/关闭、活动任务、EXE/全局解释器、锁定wheel、失败不重启、参数/路径、多实例和一次重启；真实SDK离线专项在仓库外隔离环境执行。日常仅相关检查，不构建、不运行EXE、不提交/发布。

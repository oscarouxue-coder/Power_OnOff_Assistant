# C300 按 PON 查询与参数化注册

## 目标

让 C300 使用与 C600 一致的四步操作体验：在第 1 步填写机框/槽位/PON 并筛选未注册 ONU；在第 2 步配置 ONU ID、类型模板、T-CONT/DBA 与标准业务映射；然后预览、明确确认、注册和只读验证。

## 不可变边界

- C300 与 C600 的驱动、命令和解析器保持隔离，不复用 C600 的 `gpon_olt-`、`gpon_onu-`、`real-speed` 或四层 DBA 语义。
- C300 仍以已确认的全局 `show gpon onu uncfg` 查询为准，在客户端按目标 PON 过滤；绝不下发已确认不支持的 `show gpon onu uncfg gpon-olt_<PON>`。
- 默认业务等价于现有六项固定模板；默认关闭危险删除、不自动 write、每次仅处理一台 ONU、首条 CLI 错误停止、显式源 IP 绑定不变。
- C300 未进行本轮真实写入验收；实施期间不执行注册、删除或 `write`。

## 实施步骤

1. 扩展 C300 请求与 driver：显式 ONU ID、T-CONT/DBA、六项具名业务（业务名/Service ID/VLAN）可配置；为每组业务派生同号 GEM/VPort，补齐严格校验、预检和动态回读断言。
2. 扩展 ONU 配置存储：保存 C300 非危险参数及默认业务映射；危险删除和 write 授权继续不持久化。
3. 调整主界面：C300 第 1 步显示机框/槽位/PON；查询后仅显示目标 PON，状态/确认文案明确实际执行全局查询再筛选。第 2 步显示 C300 参数化表单和三列业务表，切换型号时保持资料隔离。
4. 加入 driver、service、store 与 UI 回归：默认命令等价性、PON 筛选、覆盖 ONU ID、参数校验、预览失效、动态验证期望。
5. 更新操作员说明、验收基线（状态仍为已实现未验收）、项目状态、开发记录；运行专项与完整基线。

## 现场验证边界

完成代码后，仅由项目负责人安排测试 ONU 和维护窗口，先以只读命令核对目标 C300 接受可变 ID、T-CONT profile、Service ID/VLAN 的形式，再决定是否进行一次注册/回读/write 验收。

# 将 Tftp Put / Web 的 Boot 登录统一为 Tftp指令时序

负责人明确要求两条路径的传统账号Boot登录与Tftp指令一致，已确认直接复用原登录入口。本计划替代同日`tftp-put-boot-prompt.md`的半秒探测方案。

- 在Tftp Put/Web首轮电源动作返回后，传入已就绪事件，同步调用现有`wait_for_boot_login`；不增加线程，不改Tftp指令实现。旧Put专用方法暂保留为非活动兼容入口。
- 每次探测回车后最多等1秒查找完整用户名提示；命中后暂停探测并观察1秒，若提前出现密码提示则丢弃本轮并重新探测。
- 发送用户名→等1秒→回车→最多等30秒查找密码；发送密码→等1秒→回车→最多等20秒查找Shell。游标采样时点、乱码补救和默认600秒外层尝试窗口均原样采用Tftp指令。
- 保持SDMC、首轮电源1秒/1秒、各传输方式、网卡/源IP、并行、恢复出厂和收尾；主日志记录开始和实际登录结果。
- 调整原业务测试及Web/停止专项，用相同响应对照三条实际入口的写入/等待时序，覆盖提前密码、失败重试、乱码、超时、停止、电源失败和释放；旧兼容方法测试保留，不能把旧半秒测试当作当前业务证明。
- 同步操作员说明、项目状态、验收§2.5/§2.6.1/§3及开发记录，原历史记录保留并注明被本轮替代；Windows源码版和真实样机仍待负责人确认。
- 本轮仅局部切换调用，不搬迁或重写已验收实现；运行相关编译、专项、能力覆盖及差异检查，不触发完整基线、不打包、不运行EXE、不提交。
